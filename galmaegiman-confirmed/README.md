### 확률 계산

전체 가중치 40+30+20+10=100. 등급 확률은 각 가중치÷100입니다. 등급을 먼저 추첨하고 같은 등급 안에서 균등하게 선택합니다. 개별 캐릭터 확률은 흔함 40%÷6, 안흔함 30%÷9, 특별 20%÷20=1%, 희귀 10%÷40=0.25%입니다. 한 번마다 독립 추첨하며, 열 번 중 희귀가 반드시 한 번 나온다는 보장은 아닙니다. 특수함은 일반 뽑기에 없습니다. 새우깡 상위 뽑기는 추후 작업입니다.

‘뽑기’를 다시 전송하면 별도의 뽑기입니다. 카카오 요청에 확인되지 않은 메시지 고유 ID를 가정해 자동 중복 제거했다고 주장하지 않습니다. 조합/교환의 같은 확정 토큰 재전송은 기존처럼 한 번만 소비합니다. 이전 판에서 열어 둔 미완료 순서 지급은 업데이트 후 새 뽑기를 안내합니다. 이미 지급된 캐릭터는 회수하지 않습니다.

## 2. HTTPS — 두 번째 Termux 세션

Termux에서 옆 메뉴의 **NEW SESSION**으로 새 세션을 엽니다. 기존에 설치한 Ubuntu의 `cloudflared`를 그대로 사용합니다.

```bash
proot-distro login ubuntu --termux-home
cd ~/galmaegiman-confirmed
npm run tunnel
```

출력된 `https://…trycloudflare.com/kakao/skill`을 복사합니다. 새 HTTPS 도메인은 이미지 주소에도 자동 반영됩니다. 서버를 다시 시작할 필요는 없습니다. 이 창도 켜 둡니다.

기존 터널을 계속 사용할 때는 새로 켜지 말고 아래 명령으로 **현재 실제 주소**를 지정합니다.

```bash
npm run url -- https://여기에-현재주소.trycloudflare.com
```

이 명령에는 `/kakao/skill`을 붙이지 않습니다. 위 예제의 한글 주소를 실제 발급 주소로 바꾸세요. Quick Tunnel은 재시작하면 도메인이 바뀔 수 있으며 테스트 목적 서비스입니다. 주소가 바뀌면 카카오 URL과 Test URL도 직접 갱신해야 합니다. 앱이 카카오 관리자센터 설정을 원격 변경하지는 않습니다.

## 3. 카카오 관리자센터 연결

세 번째 Ubuntu 세션에서 프로젝트 폴더로 이동해:

```bash
cd ~/galmaegiman-confirmed
node scripts/show-connection.mjs
```

표시된 값을 카카오 **스킬 상세**에 입력합니다.

| 항목 | 입력값 |
|---|---|
| URL / Test URL | 표시된 동일한 `https://…/kakao/skill` |
| 헤더 Key / 테스트 헤더 Key | `X-Skill-Secret` |
| 헤더 Value / 테스트 헤더 Value | 표시된 비밀키 |

비밀키가 들어간 화면이나 `.env`, 백업 파일은 공유하지 마세요. 기존 코드에는 없던 보호 설정이므로 **두 헤더 모두** 추가해야 합니다. 키를 끄거나 인증 코드를 삭제하지 마세요.

1. 스킬을 저장합니다.
2. 게임 블록에 스킬과 버전을 선택하고 **스킬데이터 사용**으로 저장합니다.
3. 기본 시나리오의 **폴백 블록**에도 동일한 스킬·버전과 **스킬데이터 사용**을 연결합니다. `조합 브라자 갈매미맨`, `조합 확정`, `교환 확정`, `취소`, `도감 2`처럼 값이 달라지는 발화를 서버에 넘기기 위해 필요합니다. 이름별 패턴을 전부 등록할 필요는 없습니다. 다른 시나리오가 이름 명령이나 진행/취소 발화를 가로채지 않는지 확인하세요.
4. 다른 블록이 `받기`, `뽑기`, `내갈매미` 등을 가로채면 그 블록도 같은 스킬로 연결하거나 테스트 시나리오에서 해당 패턴을 정리합니다. 기존 무관한 시나리오는 지우지 마세요.
5. 봇테스트에서 `확률` → `뽑기` → `내갈매미` 순서로 확인합니다. 뽑기는 즉시 지급하며 확정 버튼이 없습니다. 조합·선택 교환은 미리보기 후 확정합니다.
6. 테스트가 되면 **배포**하고 실제 채널 채팅에서 다시 확인합니다. 봇테스트 사용자와 실제 채널 사용자는 별도 데이터로 취급합니다.

선택적으로 `.env`의 `KAKAO_BOT_ID`에 관리자센터 봇 ID를 넣고 서버를 재시작하면 해당 봇 요청만 받습니다. `bot.id`는 실제 요청 필드입니다. 임의의 `roomId`, `chatId`, 외부 요청 고유 ID를 만들어 사용하지 않습니다.

조합/교환의 확인 정보는 버튼에 포함됩니다. 긴 코드를 복사하거나 입력할 필요가 없습니다. 진행/취소 항목을 직접 누르세요. 글자로 `조합 확정`만 입력하면 재료를 소비하지 않고 미리보기를 다시 열도록 안내합니다. 같은 확인 버튼을 다시 보내도 한 번만 처리하며, 다른 사용자의 버튼은 사용할 수 없습니다.

이름이 같은 여러 개체의 보호/해제/표식 전환은 해당 조건에 맞는 가장 오래된 1마리에 적용합니다. 기존 DB의 개체는 합치거나 삭제하지 않고 화면에서만 수량으로 묶습니다. 이전 ID 입력과 개체번호 입력도 호환용으로 처리하지만 새 화면에는 표시하지 않습니다.

첫 접속 3장, **가입 후 맞이하는** 한국 시간 09·12·18시마다 기본 +10장입니다. 관리자는 `npm run refill -- 숫자`로 다음 충전량을 변경할 수 있습니다. 첫 접속 이전 기간은 소급 지급하지 않습니다. 자정에 획득권을 지우지 않고 미사용분을 누적합니다. 꺼져 있던 동안 도래한 지급 시점은 다음 요청에서 정산합니다. 뽑기는 보유 여부·도감 등록 여부와 무관하게 중복 획득 가능합니다. 도감을 완성해도 같은 등급 확률을 유지합니다. 조합 재료로 소비해도 도감 기록은 남습니다.

같은 종류 개체를 여러 개 가질 수 있습니다. 성별은 설정/표시 및 희귀 표식 자격에만 쓰고 조합 짝 제한은 없습니다. 흔함·안흔함·특별은 표식 전환 대상이 아닙니다. 기능은 비그래픽 게임 상태 변경으로만 표현합니다.

## 5. 백업 / 되돌리기 / 재부팅

```bash
cd ~/galmaegiman-confirmed
npm run backup
```

라이브 DB도 SQLite `VACUUM INTO`로 일관된 스냅샷을 만들고 무결성을 검사합니다. 별도 sqlite3 실행파일이나 시스템 패키지를 설치하지 않습니다. DB와 WAL을 따로 복사하는 방식이 아닙니다. 충전 설정 파일이 있으면 변경 이력도 함께 백업합니다. 백업에는 인증 설정이 있으므로 비공개 보관하세요.

새 판 사용을 취소하려면 새 서버를 `Ctrl+C`로 멈추고 **이전 폴더**에서 기존 서버를 켜면 됩니다. 카카오 스킬 URL·헤더도 이전 설정으로 돌려야 합니다. 원본 DB는 자동 변경하지 않았으므로 남아 있습니다. 백업 복원이나 판 사이 데이터 변환은 자동 수행하지 않습니다.

갤탭 재부팅 후 Ubuntu 세션 두 개에서 `npm start`, `npm run tunnel`을 각각 다시 실행하고 새 도메인을 카카오에 반영하세요. 안드로이드가 Termux를 종료하면 챗봇도 멈춥니다. Docker, systemd, 유료 VPS는 이 테스트판에 필요하지 않습니다.

## 6. 문제 확인

- `EADDRINUSE`: 이전 게임 서버가 3000 포트를 쓰고 있습니다. 해당 서버 세션을 직접 종료하세요. 무차별 프로세스 종료 명령은 쓰지 않습니다.
- `401`: URL 헤더와 테스트 헤더의 비밀키가 둘 다 일치하는지 확인합니다.
- 이미지 안 나옴: 브라우저로 `https://현재주소/images/C001M.png`를 열어 봅니다. `npm run url -- ...`로 주소를 갱신합니다.
- 조합·교환의 확정 버튼 반응 없음: **폴백 블록 연결·저장·배포**를 확인합니다. 목록이 보내는 `조합 캐릭터이름`과 `조합 확정`/`교환 확정`/`취소`가 같은 스킬에 도달해야 합니다. 확인 항목의 추가 데이터는 공식 `action.clientExtra`로 받습니다.
- `502`: 게임 서버 세션이 살아 있는지 확인합니다. `/health`가 열리면 네트워크·서버 연결을, `/ready`가 열리면 DB 연결을 확인할 수 있습니다.
- 테스트만 되고 실제 채널이 안 됨: Test URL뿐 아니라 운영 URL·헤더·배포 버전도 확인합니다. `properties.isFriend`는 Boolean으로 허용합니다.
- 오래된 미리보기: 다른 조합·지급·잠금으로 상태가 바뀌거나 10분이 지나면 다시 미리보기를 열어야 합니다. 이미 성공한 동일 확인 요청은 추가 지급하지 않습니다.
- 패키지 설치 실패: 오류 마지막 부분을 공유하되 `.env`와 비밀키는 가립니다. 인증서 검증 해제나 출처 불명 설치 스크립트를 사용하지 마세요.

## 7. 개발·검증

TypeScript / Fastify 5 / Prisma 6 / SQLite / Vitest. `package-lock.json`으로 설치 버전을 고정합니다. 카탈로그·조합 YAML을 검증하고, DB의 콘텐츠 해시가 다르면 시작을 중단합니다. 기존 데이터 변경은 명시적인 콘텐츠 마이그레이션 작업으로 분리합니다. `data/display-names.yaml`은 이름이 비어 있는 항목의 화면 표시만 보완합니다. 기존 DB 콘텐츠 해시와 보유 개체 ID에는 영향을 주지 않습니다.

```bash
npm run build
npm test
npm run test:db
npm run data:check
```

`npm test`는 단위 테스트, `npm run test:db`는 별도 임시 SQLite에만 통합 테스트를 실행합니다. 테스트 앱을 외부에 열거나 관리자 재화 지급 API를 배포하지 않습니다. 기록은 `docs/TEST-RESULTS.md`를 참고하세요.

설치 후 `node scripts/http-smoke.mjs`로 실제 로컬 HTTP 통신도 점검할 수 있습니다. 로컬 진단용 계정 1개가 새 판 DB에 생성되며, 실제 카카오 계정의 상태는 바꾸지 않습니다. 3381 포트에 테스트 서버를 잠시 띄웠다가 종료합니다.

한 프로세스·한 태블릿 테스트 운영을 전제로 큐와 트랜잭션을 사용합니다. 여러 서버/PM2 cluster로 확장하지 마세요. PostgreSQL이나 여러 인스턴스로 이관할 때는 DB 마이그레이션·분산 동시성 검증이 별도 필요합니다. 75개 이미지는 원본 PNG이므로 표시 시간은 파일 크기와 네트워크에 영향을 받습니다. 실제 갤탭 지연은 측정하지 않았습니다. 0.2.6은 획득 결과에서 첫 수집일 때만 이미지를 전송하고, 목록은 이미지 없이 표시합니다. 게임 응답을 위해 실시간 이미지 생성은 하지 않습니다.
