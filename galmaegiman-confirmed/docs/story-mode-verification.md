## 검증 범위

서버가 확정한 대화 진행·의뢰 수락·모험 결과·귀환 대화를 계정별로 보존하는지, 초반 및 주민 의뢰의 수직 흐름과 같은 엔진의 전체 콘텐츠 진행을 확인한다. 새우Gang과 석상 조각은 별도로 검사한다. 재접속, 다른 계정, 반복 탭, 중복 정산, 네트워크 단절에 해당하는 응답 손실 재시도, 트랜잭션 실패 후 재시도, 클라이언트 위조 입력, 미해금 콘텐츠 노출, 패배·도주 무보상, 인간 적 오지급을 포함한다.

## 검토에서 찾아 고친 것

- 신규 빌런 ID를 기본 로스터 검증기에 바로 넣으면 기존 `u01`~`u60` 계약 때문에 거절됐다. 기존 기준 유닛으로 검증한 후 해당 적 한 개체의 프로필만 교체하도록 고쳤다. 기본 로스터 검증은 그대로다.
- 재감상이 귀환 대사만 보여주던 것을 완료한 의뢰의 소개+귀환 대화로 고쳤다. 재감상은 새 조각·새우Gang을 주지 않는다.
- 동시에 다른 대원으로 출발할 때 고아 모험과 잠긴 대원이 남던 것을 계정 출발 예약으로 고쳤다.
- 모험/전투 생성의 여러 저장 경계 사이에서 요청이 중단될 때 내부 영수증을 먼저 복구하도록 고쳤다.
- 잘못된 모험 ID가 출발 예약을 영구히 남기던 것을 거절 시 예약 해제로 고쳤다.
- 저장된 콘텐츠 버전이 다른데 새 대사를 읽던 것을 명시적 오류로 차단했다.

## 한계와 미실행 검증

- 전체 스토리 시험은 모든 콘텐츠 조우를 레벨 1로 낮춘 임시 fixture와 60레벨 대원을 사용한다. 저장·해금·API·현재 공격형 전투 연결을 증명하며, 약 60까지의 경험치 곡선·무과금/저등급 대원 최종전 난이도·운영 밸런스를 증명하지 않는다. 본편 조우 XP 시험값은 0이며 기존 성장/랭크 정책을 대신 확정하지 않는다.
- 서사·공격 프로필 수치는 시험값이다. 고유 빌런 처치 후 최후나 주민 종족/최종 외형을 승인한 것으로 해석하지 않는다.
- 승인 석상 이미지의 전송은 원본 준비 성공 후 공식 다운로드 단계에서 `download failed`로 실패했고, 소비 환경 목적지로 1회 재시도도 같은 결과였다. 정확한 하위 네트워크 원인은 반환되지 않았다. 이미지 픽셀·최종 아트를 확인/적용했다고 보고하지 않는다.
- Android 이전 화면 콜백·뒤로가기·앱 강제 종료·반복 탭의 클라이언트 수명 검증은 별도 Android 담당 결과다. 상위 담당은 Robolectric 가로 캡처 6개를 직접 픽셀 검토했다고 전달했다. 이는 실제 물리 기기의 터치·네트워크·앱 수명 종단 시험을 뜻하지 않는다. 물리 기기 E2E는 미실행이다.
- 운영 서버/DB 마이그레이션·실제 플레이어 보상 변경·서비스 재시작·배포·GitHub 푸시/PR은 수행하지 않았다.

파일 결과는 **20개 통과·1개 실패**, 전체 종료 코드는 **1**이다. 실패 20개와 별도 `afterAll` cleanup 오류는 이전과 동일한 모집 정책 시험 계정 삭제 FK 오류다. 이전 기준 커밋 통제 실행의 20개 실패 이름·종류와 최종 실행의 20개가 정확히 일치했다. 관련 시험·모집 세션·일일 진행 파일 세 개는 여전히 기준과 SHA256이 같고, 최종 DB에도 기존 `DailyProgress`의 삭제 제한 행 21개가 남아 있다. cleanup·reset 코드를 바꾸거나 실패 파일을 빼지 않았다. 이 선정 범위에서 기존 cleanup 실패 외 새 통합 회귀는 발견하지 못했다.

기존 `roster60-play-modes.integration.test.ts`의 임시 root에도 명시 시험 정책 파일을 제공했다. 실제 localhost HTTP의 일반게임 정상 승패는 시작 레벨 8에 가장 가까운 기존 레벨 10 조우의 600/200 XP를 확인하고, 재접속·정산 재시도 뒤 추가 지급이 없음을 확인한다. 랭크 경로는 기존 XP 0과 기존 레이팅 검증을 유지했다. 생산 경로에 임의의 XP fallback 파일을 만들지 않았다.

최종 증거는 `/workspace/story-integration-evidence/server-normal-xp-combined-final/`의 `run.log`, `run-metadata.json`, `vitest-results.json`, `summary.json`, `failure-classification.json`이다. 원래 177개 결과·XP 0 추가 1개 결과·기준 25개 통제 결과·후속 중간 실행들은 각 원래 폴더에 보존했다. 서로 다른 시점의 수를 합산하거나 전부 통과로 표시하지 않는다.

양의 정상 완료 XP 지급 연결은 구현했지만, 약 레벨 60까지의 본편 성장 곡선·일반게임 위주 전체 완주 난이도·운영 수량 승인은 여전히 별도 검증/결정 사항이다. 실제 플레이어 데이터나 운영 DB는 변경하지 않았다.

### 카탈로그 안전 읽기 변경 뒤 추가 집중 회귀

서버가 이미 고정한 방의 진행을 현재 카탈로그 읽기와 분리하도록 `safeKnowledgeCatalog`를 적용한 마지막 변경 뒤, `test/normal-xp.integration.test.ts`에 집중 시험 **1개**를 추가했다. 같은 시험 안에서 카탈로그 getter가 `null`을 반환하는 경우와 예외를 던지는 경우를 각각 검사한다.

- 이미 시작한 정상 일반게임 방의 `current` 조회가 성공한다.
- `tick`이 그 방의 실제 턴을 진행시키며, 카탈로그를 읽을 수 없는 다른 대기자는 취소 가능한 조건 안내를 받는다.
- 대기 취소가 개체를 해제하고, 고정된 기존 방의 수동 행동·정상 KO·승패 60/20 XP·정산 재시도가 성공한다.

새 임시 DB에서 추가 시험만 지정 실행해 **1개 통과·0개 실패**, 같은 파일의 나머지 17개는 필터로 실행하지 않았다. `tsc --noEmit`도 종료 코드 0이다. 증거는 `/workspace/story-integration-evidence/normal-xp-catalog-safe-final/`의 `run.log`, `run-metadata.json`, `vitest-results.json`, `summary.json`, `typescript-check.json`이다.

기존 **206개 단일 통합 실행(186통과·20실패)**은 그대로 보존했다. 이번 결과는 그 뒤의 **별도 집중 1개 통과**이며 207개를 함께 실행했다고 보고하지 않는다. 이 추가 검증에서 서버 소스·XP 정책·다른 시험 범위를 변경하지 않았다.
