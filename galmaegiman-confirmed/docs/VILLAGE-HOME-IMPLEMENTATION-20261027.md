# 순환형 마을 메인 화면 구현 기록

이 문서는 이전 통합/자리 표시자 단계의 실행 기록이다. 후속 실제 13PNG 연결·렌더·로컬 APK 결과는 `VILLAGE-ART-INTEGRATION-20261027.md`를 최신 기준으로 따른다. 아래 이미지 미연결/게시 대기 표현은 당시 상태다.

기준 소스는 `manual/home-assembly-20261019@c37c24ecb9399abf0cb438b25412924ffbe921db`다. 이 작업 트리에 이미 통합된 스토리 및 원본 사용자 버그 수정은 보존했다. 운영 서버, GitHub, APK 설치, 운영 DB에는 반영하지 않았다.

## 실제 연결한 범위

`MainActivity.home()`이 `NativeVillageHomeController`와 `NativeVillageHomeView`를 생성한다. 마을은 8U이며 네 구역 사이에 빈 산책 공간을 둔다. 카메라는 연속 `double` 값으로 유지하고 화면 투영에서만 순환한다. 관성은 Android `OverScroller`를 사용하며 로컬 이동 차이만 카메라에 더한다. 먼 배경, 바다, 지형, 건물, 배, 주민을 분리했고 배경과 바다의 반복 길이도 전체 마을 한 바퀴와 일치시켰다.

| 건물 | 연결한 기존 기능 |
| --- | --- |
| 방범대 지원소 | 모집. `h.load("draw")`로 최신 계정 상태와 기존 모집 병렬 조회를 유지 |
| 방범대 아지트 | 방범대 편성 |
| 기록소 | 도감, 조합 |
| 우편함 | 기존 우편, 이벤트 소식, 공지사항 탭 |
| 바닷가 플레이 | 탐험, 실제 스토리 컨트롤러, 일반전, 랭크전 |
| 시장 | 기존 아이템 상점, 플레이 패스, 재화 보유·교환 화면 |

일반 플레이 선택 화면도 탐험·스토리·일반게임·랭크게임 네 항목으로 연결했다. 시장의 유료 재화 관리 항목은 기존 상점의 보유·교환 접점에 연결한다. 신규 현금 결제, Billing, 별도 프리미엄 지갑을 구현했다는 뜻은 아니다.

홈의 상시 재화 수치는 표시하지 않는다. 기존 모집·조합·상점 등 소비 화면은 수정하지 않아 보유량과 비용 표시를 유지한다. 상단 출석 버튼과 메뉴의 내 정보·환생 안내·설정 진입을 보존했다. 레거시 튜토리얼이 홈의 출석·모집·편성·플레이 실제 버튼을 찾을 수 있도록 안내 대상만 연결했다. 튜토리얼 단계나 서버 진행을 자동 변경하지 않는다.

## 주민과 저장

대장장이·상인은 시장, 사서는 기록소, 방범대원은 아지트에 항상 배치된다. 네 명이 화면 한 장에 동시에 보인다는 뜻은 아니다. 서버 `native/roster60/story/state`의 주민 상태가 `AVAILABLE`일 때만 느낌표를 그린다. `ACTIVE`는 부탁 진행 중, `READY`는 보고 가능, `COMPLETED`는 이야기 완료로 구분한다. 요청 실패 시 임의의 느낌표를 만들지 않으며 다시 확인할 수 있다.

주민을 누르면 스토리의 주민 화면으로 이동한다. 새 제안과 귀환은 서버가 확인한 대화를 열고, 수락은 기존의 별도 수락 버튼을 사용한다. 진행 중·완료·조건 미달 주민도 일상 대화를 볼 수 있다. 이미 읽던 장면이 있으면 보존한다.

화면 세대, 전체 세션 토큰, 서버 읽기 세대로 늦은 응답을 거부한다. 카메라는 서버 주소와 안정적인 계정 ID로 범위를 나눠 저장하며 재진입·회전 후 같은 연속 위치를 복구한다. 이미지 콜백도 현재 화면 및 로딩 세대를 확인한다. 이미지를 불러오는 동안 건물 이름과 메뉴 버튼은 사용할 수 있다.

입력 시험에서 빈 산책로의 `DOWN`으로 `FrameLayout` 자신이 터치 소유자가 되면 뒤이은 `onInterceptTouchEvent(MOVE)`가 호출되지 않는 실제 누락을 찾았다. 자식 버튼에서 시작한 드래그의 가로채기는 보존하고, 자체 `onTouchEvent(MOVE)`에서도 동일한 수평 이동·터치 슬롭 판정을 하도록 수정했다. 빠른 이동 중 탭은 이동만 정지하고 다음 별도 탭은 즉시 선택한다. 저속 탭은 현재 탭으로 선택할 수 있다.

같은 계정의 토큰 갱신은 새 홈 컨트롤러에서 카메라를 복구한다. 안정적인 계정 ID가 바뀌면 기존 작업 표시의 세대를 무효화하고 이전 계정 스냅숏·메뉴 임시 상태를 비운 뒤, 기존 `native/state` 전체 조회를 거쳐 홈을 새로 만든다. 따라서 홈의 내 정보 메뉴에도 이전 닉네임이나 보유량을 남기지 않는다. 홈 조회 중 인증이 만료되어 토큰이 비워진 경우에는 같은 화면 세대임을 확인하고 로그인으로 전환한다. 이전 프로필 팝업도 닫는다.

## 시각 자산의 미완료 경계

이 기록 시점에는 승인된 v2 원화의 실제 파일을 이 환경에서 열지 못했다. `native/village-loop-v2/manifest.json`의 13개 자산은 모두 `verified:false`다. 화면은 원화 준비 중 문구와 명시적인 건물·배·주민 자리 표시자를 사용한다. 이전에 거절된 파란 지붕과 동일 체형 주민 시트는 사용하지 않는다. 따라서 승인 원화 적용이나 완성된 마을 그림을 검증했다고 보고하지 않는다.

Gradle은 앞으로 확인되는 로컬 `art/gpt/village-npc-20261027/` 원본만 앱 자산에 포함하도록 준비했다. 이 경로의 존재나 게시 여부를 조회하지 않았으며, 파일이 없으면 그대로 자리 표시자로 동작한다. 런타임은 개인 GitHub URL이나 외부 이미지 다운로드에 의존하지 않는다. 서버 주민 `guard`는 개별 투명 자산 `patrol.png`에 명시적으로 대응한다. 흰 배경 주민 합본을 직접 그리지 않는다. 실제 파일 수신, 원본 픽셀 확인, 경로 확정, manifest 승인 및 실제 이미지 렌더 검증은 남아 있다. 승인 5단계 석상 이미지는 이 마을 자산과 별개이며 여전히 미전달이다.

## 검증 기록

새 홈 생산 Java 소스의 컴파일은 통과했다. 최초 집중 시험 35개 통과 후 다른 계정 전체 재조회와 인증 만료 경계를 추가한 Android 통합 시험은 22개 클래스, 147개 시험에서 실패·오류·건너뜀 모두 0으로 통과했다. 여기에는 기존 통합 111개와 홈·자산·순환 수학·일반전 XP 표시 36개가 포함된다. 홈 전용 14개, 자산 3개, 순환 카메라 6개, 배치 검증 7개는 모두 통과했다. 실행 로그 `/tmp/village-home-final-integrated.log`의 `BUILD SUCCESSFUL in 3m 19s`와 해당 실행 XML의 합계를 직접 확인했다.

147개 통합 실행의 컴파일된 컨트롤러를 역어셈블해 최종 `operations.close()`·컨트롤러 식별·이전 상태 초기화·전체 상태 재조회가 포함됨을 확인했다. 이 실행의 생산 소스 해시는 `integrated147/manifest.json`에 보존한다.

이전 계정의 진행 중 요청과 늦은 응답을 더 명시적으로 확인하는 시험을 보강한 뒤, 홈 15개·플레이 이동 12개·제품 전투 5개, 총 32개를 별도 실행했다. `/tmp/village-home-auth-final32.log`는 `BUILD SUCCESSFUL in 1m 40s`이며 3개 클래스의 XML 합계도 실패·오류·건너뜀 모두 0이다. 최종 컨트롤러 생산 소스 SHA256은 `f1f68fb9991373d8c8e9c9d110619d246e0ba05ea82f20ed4c1cd6755f9e21aa`로 통합 147개 실행의 수집 해시와 같다. 두 실행은 겹치는 시험을 포함하므로 각 결과로 구분해 기록한다. 생산 소스는 이 상태로 동결했다.

직접 연 픽셀 검토 범위는 `focused35/screenshots/village-home/`의 915×412, 1280×720, 915×412 글꼴 130% 세 규격 × 8U, 총 24 PNG다. 통합 `integrated147/screenshots/village-home/`의 같은 이름 24개와 SHA256을 대조해 모두 동일함을 확인했다. 동일 폴더의 `geometry.json`에는 24장에 걸친 건물·주민 영역 240개를 기록했으며 최소 너비는 128px, 최소 높이는 약 126px였다. 집중 시험은 고정 버튼의 48dp 이상 크기와 완전 가시성, 중앙에 온 세계 버튼의 텍스트 높이 및 말줄임을 수치로 확인했다. 픽셀 검토에서는 기존 한글 글꼴, 출석·메뉴·구역 이동 버튼, 건물 이름과 기능 설명, 주민의 새 부탁·진행 중·보고 가능·완료가 읽히는지 확인했다. 조건 미달에도 주민이 상주하고 구역 사이 빈 공간이 유지되는 것은 기능 배치 검증에 포함된다.

이 검토는 명시적 자리 표시자를 대상으로 했다. 원화의 미술 완성도, 승인 원본과의 픽셀 일치, 석상 복원 이미지 연출은 검증하지 않았다. 호스트의 Robolectric 렌더 결과는 실제 기기의 프레임 속도나 APK 설치·운영 정상 증거로 확대하지 않는다.
