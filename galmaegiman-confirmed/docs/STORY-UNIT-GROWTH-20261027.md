# 스토리 개체 성장의 한정된 시험 프로필 후속

이 후속은 통합 tree `9ead0d74c9c397761423587648203812e08b4d9d`를 보존하고 기존 본편21개·주민 의뢰4개의 스토리 연결 전투에만 시험 개체 XP를 연결한다. 새 주민12화, 운영 기본 지급량, 신규 특전·환생 옵션·랭크 규칙을 추가하지 않는다. 원본 스토리 콘텐츠의 XP0은 그대로 두고 명시적으로 선택한 별도 시험 프로필을 수락 시 고정한다. 정책이 없었던 수락/과거 전투에 새 보상을 소급하지 않는다.

## 별개 사건과 지급 시점

대장 XP는 기존 의뢰 완료 사건에 계정1회 지급한다. 개체 XP는 서버에서 확정한 해당 의뢰 전투 사건별로 정산한다. 의뢰 클리어/대화 재생·같은 claim·새 requestId 재조회가 개체 보상을 다시 만들지 않는다. 서로 다른 정상 전투와 같은 전투의 재조회도 구분한다. 새 정책이 붙은 의뢰는 요구 승리를 이미 채웠으면 먼저 귀환해야 하며, 마지막 전투를 반복해서 유한 보상 예산을 늘릴 수 없다.

시험 제안은 전투별 총 승리 XP를 실제 출전 개체끼리 균등 분배하고 정수 나머지는 ownedId 순으로 배분하는 것이다. 스토리의 기존 패배·도주·항복·무승부 XP0은 유지한다. 이 분배와 기본 수량은 운영 승인 수치로 주장하지 않는다. 일반 모험의 기존 출전100%·예비50% 규칙이나 일반전·랭크 정산에 이 시험 규칙을 확대하지 않는다.

모험 연결 전투는 기존처럼 귀환까지 XP를 보관하고, 직접 스토리 전투는 전투 정산에서 지급한다. 모험 안의 연속 전투 사이에 아직 귀환하지 않은 XP로 레벨을 미리 올리지 않는다. 실제60/99 상한까지만 지급하고 넘친 몫은 버린다. 자동 환생·초과 XP 이월은 없다. 같은 모험에 기존 일반 모험 XP가 섞인 경우 시험 스토리 몫을 별도 표시해 기존 몫의 계약을 조용히 바꾸지 않는다.

## 실제 진행 조건과 성장 검증 범위

현재 스토리의 입장 조건은 선행 의뢰 완료와 누적 Gang 문턱이며 계정/개체 최소 레벨 gate는 없다. `recommendedLevel`은 권장값이고 DTO도 `RECOMMENDATION_ONLY`다. STORY06/12/18의 Gang2/4/6과 주민 해금 순서를 그대로 검사한다. 랭크의 대장60+각 개체60 조건은 스토리에 적용하지 않는다. 향후 실제 gate가 추가되면 이 시뮬레이션도 같은 조건을 검사해야 하며, 보상 총합만으로 입장 제한을 우회하는 증거로 사용할 수 없다.

현재 시험 프로필의27전투 총 승리 XP는655359다. 기존 비환생 common 곡선의 Lv60 누적218453을 세 표본 개체에게 균등 분배할 수 있는 산술 총량이다. 다음 실제 조우 레벨+3을 목표로 보상 시점을 배치한 변경 가능한 시험 제안이며, 원본 적 수치나 곡선을 바꾸지 않는다. 실제 출전 여부·실신·상한 폐기로 개인 수령량은 달라진다. 이 합계만으로 완주나 모든 개체60을 주장하지 않는다.

대장 예산은 본편4200(Lv43), 기존 주민4개1800을 더한6000(Lv61), Lv60 문턱5900으로 유지한다. 제안 주민12화는 추가하지 않았다. 원본은 모험 전투22회·직접 전투5회이며 모험형 의뢰는17개다. 같은 의뢰의 연속 전투를 같은 run에서 끝내면 귀환17회, 실제 클라이언트의 매승리 귀환 흐름은 완료 시22회다. 어느 경로도 연결 귀환의 대장 XP를 중복 계산하지 않는다.

**무반복 캠페인 완주와 표준 주력의 실DB60 도달은 아직 검증 실패다.** 원래2인 u01/u02와3인 u01/u02/u03 표본은 실DB에서 STORY_11 철심에 막혔다. 당시 대장은2900 XP/Lv30, 2인은 각Lv37(XP67605/66027), 3인은 각Lv32(XP44544)였다. 세 번째 소유는 명시적 시험 초기조건이며 신규 계정의 확정 지급이라고 설명하지 않는다. starter+선택권 u02는 보장 선택 경로지만 그 편성의 완주를 보장하지 못했다.

추가 전술·합법적인 다른 common 선택과 귀환 경로는 제한된 무DB 실제 action 모형으로만 확인했다. 최대로 진행한 u01/u08 표본도 주민 방범대원2전째에서 막혔다. 매승리 귀환 표본은 두 개체Lv60·최대HP로 진입했지만 적HP889 중163을 남기고 패배했다. 이는 실DB 완주나 모든 합법 전략의 불가능성 증명이 아니다. 탐색은 종료하고 병목과 조정 대안을 동봉한 `evidence/campaign-blocker-analysis.md`에 남긴다. 힌트/전술·보상 배치·보급·적 수치 중 밸런스 변경을 적용하려면 별도 결정을 받아야 하며 이번에는 적용하지 않았다.

## 시험 정리와 기존 FK 실패

기존 모집 파일의 확률 경계 시험20개는 성공적인 claim이 만든 DailyProgress를 남긴 채 Player를 삭제해 실패했다. fixture가 등록한 격리 시험 계정만 대상으로 DailyProgress·AuditEvent를 먼저 정리한 뒤 Player를 지운다. 운영 FK나 Cascade 규칙을 낮추지 않고 사업 검증·시험 개수·확률 경계 검증을 삭제하거나 skip하지 않는다.

최종 선택 서버 회귀34파일406개는406통과·실패0·건너뜀0이다. 기존385개와 새 정산21개를 함께 실행했고 실행 시작의 생산 소스·선택 시험·시험 정책 해시가 최종 파일과 일치한다. 새21개는 직접/모험 각 경로의 실제 출전·미출전·정수 나머지, null/과거 계약 고정, 60/99 상한, 수동 환생 후 과거 정산 재조회, 학습 기술, 같은/다른 요청과 두 Prisma 클라이언트, 실패 시 원자 롤백·동일 요청 복구, 모험2전투 누적, 독립 재료전투의 정책 미상속, 실제 인증 HTTP와 클라이언트 XP 필드 거부를 포함한다.

별도 실제 캠페인 시험2개는 **0통과·2실패·건너뜀0**이며 최종 소스에서도 둘 다 STORY_11 패배로 재현됐다. 두 실패 시험의 win assertion을 그대로 유지했다. 이들은 회귀406개와 다른 파일이며, 회귀 통과를 캠페인 성공으로 확대하지 않는다. 고정 seed뿐 아니라 실제 battleId·행동·이벤트를 저장해 해당 실행을 재현할 근거를 남겼다. 동속 판정 해시에 battleId가 포함되므로 seed 하나만으로 모든 재실행의 동일 순서를 보장하지 않는다.

FK 수정의 독립 통제 시험은 tree9ead의 생산 소스를 그대로 추출한 임시 작업 폴더에서 시험 파일 하나의 cleanup만 교체했다. 동일25개 이름이 이전5통과·20실패에서25통과·실패0으로 바뀌었다. 별도 회귀의 seed가 있는 격리DB에서도 통과했다. 초기 정산 시험의3실패는 여러 개체의 fixture source를 같은 값으로 만든 유일성 제약 오류였고, 고유 source로 고친 뒤 모든 정산 사례가 통과했다. 최초 실패 요약·원문은 삭제하지 않았다.

최종 TypeScript 검사는0오류다. Android·Prisma 스키마·원본 스토리와 카탈로그·대장 정책의 tree9ead 이후 변경은0이다. 따라서 Android/Gradle/APK를 이 후속에서 다시 실행하지 않았다. 기존182개 Android 통과는 이전 정책 APK 검증 기록이며 이번 서버 캠페인 완주 증거가 아니다. 전체 저장소의 모든 시험·실기기·운영 환경 검증을 수행했다고 주장하지 않는다.

## 앱과 운영 경계

이 후속은 Android 소스를 바꾸지 않는다. 기존 정책 APK는 tree9ead의 클라이언트이며 이번 서버 시험 보상 후속을 새 APK로 포장하지 않는다. 개체 성장의 실제 증거는 DB 누적 XP와 다음 편성/전투의 서버 레벨·학습 기술이다. 기존 스토리 결과창은 Gang 문구가 XP 문구를 덮어쓰고 귀환 후 즉시 허브로 돌아가므로 새 개체 XP의 상세 표시에는 제한이 있다. 이번 서버 시험이 새 결과 UI까지 완성한 것으로 설명하지 않는다.

운영 DB·마이그레이션·배포·코드 push·실계정 지급·물리 기기 플레이는 하지 않았다. 대장 곡선/보상은 여전히 시험 수치이며, 원본 적의 레벨·강화율·HP·기술을 낮춘 정산 전용 fixture와 원본 난이도를 유지한 성장 경로 검증을 구분한다. 석상 실제 이미지 연결은 이 후속 범위 밖이며 여전히 미완료다.
