# 실제 제품 화면 연결 수정 (로컬, 미배포)

## 적용한 범위
- 조합: `NativeRoster60Craft`의 기존 좌/중/우 배치를 유지하며 재료 speciesId, 레시피 resultId, 선택된 6슬롯에 manifest 정면 그림 연결. 같은 ID의 뒤 그림/모집 등록증으로 혼용하지 않음. 공통 `Roster60Portrait`는 파일명 검증, inSampleSize=2, 최대8MiB 캐시를 사용.
- 도감: 어두운 패널의 이름·정보를 밝은 TEXT 토큰으로 지정. 모든 내용을 ScrollView에 쌓던 방식을 능력치/적합도/방어/기술 페이지로 분리. 이전/다음·등급/보유필터·누르는 동안 설명 유지. 원본 이미지는 변경하지 않음.
- 제품 전투: 새 인증 API·5스탯·6명령·6기술·앞뒤 배치 보존. 범용 재화 헤더 제거, 기존 `battle-v1/bg-harbor.png`를 직접 열어 확인 후 전장 배경으로 연결. 양측 캐릭터 옆 이름/Lv/HP/MP HUD. 내구/저항/속도 raw 문자열, profile ID와 시험안 내부 문자열은 전투 중 노출하지 않음. 시험 기본안 정보 자체는 도감 등에 유지.
- 전장 아래 2×3 명령판: 일반 페이지는 48dp×2행+설명 영역, 기술 페이지는 같은 6슬롯+돌아가기. shared product-mode만 레이아웃 변경, 기존 offline review모드 분리. 길게누르기/해제/취소 gesture 코드는 유지.
- 전투 중 수동 '다시 확인/결과 받기' 버튼 숨김. 종료 상태에만 기존 멱등 settle API 자동 요청, 결과 표시와 홈/모험 확인 동선. 불확실 요청은 기존 저장된 requestId 복구 유지. 정산 실패는 오류와 재시도 노출(실패를 성공으로 덮지 않음). 인간 PvP 수락/상대 행동 대기/항복/정산에도 동일 renderer 연결.
- 메뉴 잠금 중 일반 플레이의 adventure/active 조회가403일 때 일반/스토리/연습 options로 진행하도록 보완. 모험 요청 자체의 잠금은 우회하지 않음.

## 확인 근거와 남은 차이
`docs/BATTLE-REFERENCE-UI.md`는 구 33종 웹 전투의 오른쪽 조작판을 설명한다. 이번 하단 compact2×3는 최신 사용자 요청에 맞춘 로컬 변경이며, 과거 시안과 픽셀 단위 일치를 주장하지 않는다. 새 전투 캡처 libfile_402ca56144348191aec3c9c32fdcfc2e는 prepare_materialize 후 공식 helper가 `download failed`를 반환했다. HTTP 상태 미제공, 추가 재시도/우회 안 함. 소비 환경에서 해당 캡처 픽셀은 직접 확인 못했으며 부모의 실제 관찰과 소스를 대조했다.

## 다회 모집은 별도 보류
수량 UI는 숨기지 않았고 현재1후보 제한도 임의 변경하지 않았다. 사용자가 다회 모집을 승인했으나 batch의 리롤 범위가 미정이다. 추천: N개를 단일 거래로 생성/비용 N×2/6/10 차감, 후보마다 기존 같은등급1회 리롤1/3/5 및 최종1회 수령. 기존 즉시지급 API의 상한은50회, 현 후보 session/start에는 수량 필드 없음. 전체batch리롤 방식과 후보별 방식 중 확인 후 구현 필요. 가격/확률/잔액 미변경.

## 검증 및 제한
- 60종120개 정면/후면 파일 존재와 실제 이미지 열기 검사 통과. 이미지 파일 수정/추가 없음.
- 새 portrait 클래스: 설치된 공식 Android36 android.jar 대상으로 javac 타입 컴파일 통과.

- 서버 소스/DB/경제정책 변경 없음. 직전 서버 메뉴패치의65파일679시험 결과와 이 Android 수정 검증은 구분.
- 운영 배포/push 없음. 계정 초기화 없음.
