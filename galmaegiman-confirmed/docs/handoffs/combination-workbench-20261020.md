## 구현

- 기본 조합 진입은 재료로 찾기. 왼쪽 보유·사용 가능 수량과 검색/페이지, 가운데 선택 등록증과 개별 × 및 전체 비우기, 오른쪽 결과와 그 아래 48dp 조합 버튼.
- 재료 칸은 동적으로 늘어나며 가로로 넘긴다. 고정 4칸 제한을 추가하지 않았다. 서버가 실제 레시피의 최대 재료 수를 반환하고 동일 한도로 요청을 검증한다. 구 서버 연결 시 기존 6개 한도 사용.
- 기존 결과 검색·가능만 필터·수량 조합은 결과로 찾기 탭에 유지. 도감/획득 결과의 특정 조합식 바로가기는 결과 탭으로 연결.
- 공개 조합식과 선택 재료의 중복 수량까지 정확히 일치할 때만 가능한 결과로 표시. 미공개 카드는 성공 확정 표시가 아니다.
- `/my/api/craft`의 사용 가능한 pool 항목에 `hiddenHint: boolean`만 추가. 미발견 히든의 결과 ID·이름·이미지·전체 레시피는 새 힌트로 반환하지 않는다. `recipes`의 기존 공개/발견 필터를 유지한다.
- 선택 재료 중 단서가 있으면 미공개 등록증의 황동 테두리만 약 2초 코사인 주기로 명암 반복. 공개 결과도 있으면 옆으로 넘겨 별도 미공개 단서를 볼 수 있다. 재료 제거 시 재구성, 화면 이탈 시 분리, 창 포커스 상실/백그라운드 시 다음 프레임 예약 중지.
- 확인창 중복 열기 차단, 선택 스냅샷·화면 epoch·계정 토큰 재확인 후 기존 `performCraft`/`h.request` 호출. 기존 busy 차단·요청 응답 epoch 검사·서버 거래/개체 재검증·소모 처리 유지. 조회·선택에서는 소모하지 않는다.
- 서버 보호·탐험 상태 제외 및 기존 편성 보호 잠금 흐름 유지. 이번 변경은 개별 개체 선택 정책·거래 로직을 바꾸지 않는다.
- 기존 등록증 아트/네이티브 텍스트·버튼 재사용. 원본 이미지·결제·광고 SDK·우편함 수정 없음.

## Claude가 이어서 할 일

1. 이 브랜치만 별도 체크아웃. 원본 수동 작업 브랜치와 기존 Claude 작업을 덮어쓰지 말 것.
2. 사용자 승인 범위와 루트 CLAUDE.md의 빌드 전 디자인 검토 지침을 확인하고, 실제 게임 글꼴로 검토할 것. 이번 작업에서는 사용자 지시가 단위 테스트·정적 검사로 제한되어 캡처 검토를 하지 않았다.
3. Android Java 컴파일/리소스 참조 검사 후 네이티브 화면을 실제로 검토. 780×360, 915×412, 1280×720 가로 화면 및 키보드 표시에서 글씨·검색·페이지 버튼·48dp 터치 영역 겹침 확인. 검색 결과 0개/긴 이름/최대 재료/같은 종 여러 마리/결과+단서 동시 표시 확인.
4. 미발견 단서 재료 추가→2초 테두리 반복, 마지막 단서 제거→중단, 탭 이동·뒤로가기·홈/백그라운드→중단, 복귀→재개, 발견 완료 후 힌트 제거를 실기기로 확인.
5. 확인창 취소·빠른 이중 탭·요청 실패·통신 결과 불명·계정 전환·뒤로가기 확인. 성공 소모는 한 번만, 틀린 레시피는 소모 없음. 다른 개체 소유권·잠금·편성/탐험 보호를 실제 격리 DB에서 재검증.
6. 새 힌트는 서버 코드도 필요하다. 기존 서버에서는 새 UI는 동작하지만 힌트는 없으며 기존 6개 한도를 사용한다. 서버 배포는 이번 권한에 포함되지 않으므로 별도 승인 없이 하지 말 것.
7. 디자인/실기기 검증 후 사용자가 맡긴 APK 빌드 결과와 미해결 사항을 보고. 여기서는 APK·Actions·운영 배포를 실행하지 않았다.
