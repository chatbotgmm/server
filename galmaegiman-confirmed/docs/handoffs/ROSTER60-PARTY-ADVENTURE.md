# 60종 순차 전투와 모험 보상

## 확정 정책과 실제 연결

- 출전 1 + 예비 최대 5. 서버가 소유권, 중복, 잠금, 편성 경쟁을 검증하며 전체 편성을 전투 동안 잠근다.
- 교체와 아이템은 자신의 행동을 소비하고 공격/기술보다 먼저 처리한다. 교체 후 공격 대상은 현재 출전 개체다.
- 아이템 기존 효과/인벤토리 차감 유지. perBattle=0을 무제한 횟수로 해석하고 maxStack은 유지한다. 무료 아이템을 생성하지 않는다.
- 스토리/대전 모드 도망은 즉시 항복, XP 0. 현재 새 엔진의 상대는 서버 AI이며 실제 양측 인간 PvP는 아직 별도 연결 작업이다.
- 모험 도망 70%. 서버 seed/battleId/turn 해시로 한 번 판정하며 requestId 변경으로 같은 턴을 재추첨할 수 없다. 실패는 상대만 1회 행동, 성공은 현재 전투 종료이며 정상 복귀가 아니다.
- 모험 시작/조회/복귀 인증 API와 전투 create/action/settle이 같은 DB 거래 흐름을 사용한다. 새 Roster60Adventure/Receipt 테이블 migration은 파일 및 격리 DB 검증만 수행한다.
- 전투 중 정상 복귀는 서버에서 RETURN_ONLY_OUTSIDE_BATTLE로 차단한다. 승리 XP는 모험 미정산 보상으로 저장하고 정상 복귀 시 한 번 지급한다. 전멸은 해당 모험 미정산 보상만 소멸한다.
- Android 제품 전투 진입에서 모험 선택 → 편성 → 다음 전투/복귀 경로를 사용한다. 확정 요청을 기기 저장소에 유지하여 불확실 응답 재시도에서 requestId를 재사용한다.

## 제한과 미정

- 출전 기절 시 생존 예비를 직접 선택하는 무료 강제 교체 승인 반영. 서버 상태를 다시 읽어 선택 대기를 복원하며 교체 영수증 재전송은 턴/상대 행동을 추가하지 않는다. 새 출전 속도로 같은 턴의 저장된 순서를 갱신하되 동일 서버 seed를 사용한다.
- 새 엔진은 상태이상/지속피해 기술을 아직 지원하지 않는다. 따라서 해제 아이템은 해제할 상태가 없다고 거절하고 소비하지 않는다. 도망 실패의 상태이상 지속시간 처리를 완료했다고 주장하지 않는다.
- 현재 새 전투가 생성하는 모험 보상은 XP뿐이다. 재화/아이템 모험 드롭 정책은 추가하지 않았다. XP 대상은 기존 초기 출전 개체 규칙을 유지하며 예비/참전 개체 분배는 별도 결정이 필요하다.
- 양측 교체/아이템 동시 제출은 새 인간 PvP 미연결로 실행 검증 대상이 아니다. 향후 둘을 같은 우선 행동군으로 두고 동군 내 최종 속도/저장된 동률 seed 적용이 일관된 제안이다.
- 모험 중 HP는 이어지고 전투 시작 MP는 확정 정책대로 충전된다. 성장/스탯 변경은 복귀 정산 때 적용한다. 상한 초과 XP 정책 미정 때문에 누적 보상이 상한을 넘는 전투는 생성하지 않는다.
- 기존 운영 서버에는 배포하지 않았다. 실제 Android 기기 실행/렌더 검증은 하지 않았다. 새 PNG 전달 차단은 그대로다.

## 검증

서버 전체 58파일/606테스트 통과(`/tmp/party-adventure-final-regression.log`). 더 빠른 상대를 명시한 교체/아이템 우선순위 대상 5테스트 추가 재검증 통과. Android 관련 14테스트 및 debug assemble 성공(`/tmp/party-adventure-android-final.log`), Node/웹 빌드 성공. 취소 후 항복 버튼이 잠기던 경로는 명시적 확인/취소 리스너 및 다이얼로그 identity 검사로 수정했다. 이 결과는 Robolectric 자동 검사이며 실기기 렌더 검증이 아니다.

기존 cde2152 스키마에서 새 스키마로의 격리 SQLite 리허설: 신규 11테이블, 계정/재화 보존, FK 검사, 백업 복원 통과(`/tmp/adventure-migration-rehearsal.log`). 운영 DB 접근 없음.
