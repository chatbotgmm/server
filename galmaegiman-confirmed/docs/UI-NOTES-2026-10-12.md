# PDF 화면 메모 반영

기준: `main-oz3tvo`의 `d51b671`(v0.16.2). 첨부된 `Notes_261012_195932 (1).pdf`의 판독 가능한 메모를 반영했다. 앞선 전투 화면 PR #1은 이미 병합된 상태다.

## 변경

| 화면 | 반영한 동작 |
| --- | --- |
| 내 갈매미 | 이름·등급·속성 검색. 카드 클릭은 상세 보기, 길게 누르기·우클릭·Shift+F10은 카드 메뉴. 스크롤 동작은 길게 누르기를 취소한다. |
| 카드 메뉴 | 상세 보기, 해당 갈매미와 관련된 조합식, 탐험 편성 추가, 보호/해제. 조합식은 재료 부족 여부와 관계없이 보여 주고 실제 조합은 기존 확인 절차를 따른다. |
| 보호 | 로그인한 사용자의 대기 중인 같은 종류 개체에만 적용한다. 탐험 중인 개체와 다른 사용자의 개체는 변경하지 않으며, 기존 재료 보호 규칙·감사 기록을 사용한다. |
| 전투 편성 | 오른쪽 목록을 가로로 넘긴다. 선택을 바꿔도 스크롤 위치를 유지하고 아래 저장 상태는 간단한 글로 표시한다. |
| 아이템 | 가로 카드 목록. 치료약의 쓰기 버튼에서 스토리 팀의 회복 대상을 고른다. 기존 회복 API로 아이템 수를 줄이고 개체별 스토리 체력을 저장한다. 일반·랭크 대전의 체력 규칙은 그대로다. |
| 로비·모드 | 로비 갈매미의 임의 말풍선을 띄우지 않는다. 스토리 목록·기술·승진은 읽기 쉬운 큰 버튼으로 표시하고 PvP의 연습 버튼은 제거한다. |
| 증강체 | 공격은 빨강, 유틸은 노랑, 수비는 파랑으로 구분하며 분류 글자도 함께 표시한다. 전투 상태창의 증강체 버튼을 누르면 전체 효과 설명을 작은 창으로 보여 준다. Escape·닫기·외부 클릭으로 닫는다. |
| 이미지 | 그림 크기를 유지하며 로딩하고, 실패하면 기존 갈매미 그림을 대신 표시한다. 대체 그림도 실패하면 자리표시자로 마무리한다. 웹과 앱 패키징에 같은 처리 스크립트를 포함한다. |

카드 메뉴 마지막 손글씨 항목은 보호/해제로 해석했다. 첫 장의 뽑기 화면과 로비 버튼 옆 일부 손글씨는 판독이 불명확해 사용자에게 텍스트 확인을 요청했다. 새 그림 생성이나 임의 버튼 이름 변경은 하지 않았다.

## 검증

- `npm run db:generate`, `npm run build`, `npm run data:check`, JS 문법 검사, `git diff --check` 통과.
- `npm run test:db`: 격리 SQLite DB에서 8개 파일·124개 테스트 통과. 추가한 보호 API 검증은 인증·요청 형식·다른 계정 격리·탐험 중 개체 제외·보호/해제와 실제 반환 수를 확인한다.
- `node app/build-www.mjs` 통과. 공유 이미지 처리 스크립트가 앱의 `my.html`, `index.html`, `www/`에 포함된 것을 확인했다. APK 빌드·배포는 수행하지 않았다.
- 시스템 Chromium과 Playwright에서 실제 Fastify API·임시 SQLite·게임 데이터·그림을 사용했다. 계정·아이템 API를 fixture 응답으로 대체하지 않았다.
- 780×360, 915×412, 1280×720에서 갈매미 목록·전투 편성·아이템·증강체 선택 화면 확인. 아이템 목록의 페이지 넘침이 없고 작은 화면의 치료약 쓰기 버튼이 보인다.
- 검색과 검색 결과 없음, 카드 상세, 길게 누르기·키보드 메뉴, 움직임에 따른 길게 누르기 취소, 보호 저장, 탐험 편성 저장, 전투 편성 변경 후 가로 스크롤 유지·저장, iframe에서 치료약 사용과 체력 변화 확인.
- 증강체 설명의 포인터·키보드 열기, Escape·닫기, 이미지 다운로드 실패 후 대체 그림 표시 확인. 점검 중 브라우저 실행 오류 없음.

운영 DB는 수정하지 않았다. EC2 배포에는 실행 환경의 AWS 인증과 대상 인스턴스·리전 정보가 별도로 필요하다.
