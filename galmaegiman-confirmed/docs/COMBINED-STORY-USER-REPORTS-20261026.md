# 스토리·버그·일반게임 XP·마을 홈 통합 보고서

이 문서는 이전 통합/자리 표시자 단계의 실행 기록이다. 후속 실제 13PNG 연결·렌더·로컬 APK 결과는 `VILLAGE-ART-INTEGRATION-20261027.md`를 최신 기준으로 따른다. 아래 이미지 미연결/게시 대기 표현은 당시 상태다.

## 정확한 기준과 산출물

기준은 `chatbotgmm/server`의 `manual/home-assembly-20261019@c37c24ecb9399abf0cb438b25412924ffbe921db`다. c37c24e에 포함된 튜토리얼 서버 재동기화·출석·큰 글꼴 레이아웃·시험 전용 시작 우회를 보존했다. 오래된 main이나 `deploy/server-7a799e9`의 외부 dist를 이번 소스 빌드 결과로 사용하지 않았다.

최종 패치는 이 기준에 스토리와 부모의 승인 버그 패치, 이후 명시 승인된 일반게임 XP와 실제 Android 마을 홈을 함께 담는다. 최초 스토리 단독 ZIP은 이전 상태의 보존본이다. 깨끗한 c37c24e에는 `combined-c37c24e.patch` 하나를 적용한다. 정확히 원본 버그 패치만 적용한 트리에는 선택적으로 `followup-on-original-bug.patch`를 쓸 수 있다. 둘을 함께 적용하지 않는다. 이미 스토리나 다른 수정이 있는 트리에 전체 패치를 다시 적용하지 않는다. 변경 소스 사본은 검토용이며 공용 파일 덮어쓰기 지시가 아니다.

운영 DB, 실제 플레이어 데이터, GitHub 코드·이미지 게시, 배포, 서비스 재시작, APK 생성·설치는 수행하지 않았다.

## 버그 소스 수신과 보존

버그 ZIP의 공식 Library 다운로드와 허용된 한 번의 재시도는 `download failed`로 실패했다. 상세 원인이 없어 권한 거절로 단정하지 않는다. 이후 부모가 동일 승인 소스의 8개 텍스트 조각과 COMPLETE를 전달했다. 전송 XML 엔티티를 정확히 한 번 해제하고 줄바꿈을 보존해 합친 결과는 **198,738 bytes**, SHA256 **`1319f85576b50fced7acabb52667687968c10b91266a053f945f4a3290266847`**로 원본과 일치했다. 일치 전에는 적용하지 않았다.

c37c24e 별도 Git index와 스토리 작업 트리의 적용 검사에 통과한 뒤 병합했다. MainActivity·NativeApi·roster60-routes 같은 접점은 두 기능을 함께 보존했다. 편성 재측정의 위치 되돌아감, 결과 메타데이터 갱신의 관성 중단, 실제 속도에 따른 빠른 탭 정지/느린 탭 선택, 모집 병렬 조회, 발견 기반 조합 작업대, 일반게임 30초 AI·서버 대기 시간 표시를 보존한다.

초기 버그+스토리 병합의 33/36 파일 바이트 일치 기록은 당시 증거다. 최종에는 후속 승인된 XP와 홈 때문에 PvP·메뉴·시험도 바뀌었으므로 이 숫자를 최종 불변 파일 수로 주장하지 않는다. 최종 manifest는 원본 버그 tree와 최종 tree를 파일별로 비교해 후속 변경을 구분한다.

## 실제 연결된 스토리

명시 시험 프로필에서 계정 저장·VN 대화 커서·이어하기·읽은 기록·명시 수락·편성·실제 모험/전투·귀환 대화가 연결된다. 7장·21개 메인 의뢰, 주민 4명의 유한한 의뢰, 50개 장면, 27개 순차 조우가 같은 데이터 엔진을 사용한다. 의뢰 창을 여는 동작과 수락은 별개다. 동시 출발·중간 네트워크 실패·외부 영수증 유실은 계정별 출발 예약, CAS, 내부 전투 영수증으로 복구한다.

어둠의 새우Gang은 서버의 흑화 갈매미 승리 정산에서 계정·전투별 한 번만 지급한다. 패배·도주·항복·인간 빌런·일반게임에는 주지 않는다. 석상 조각과 다른 재화이며 환생 후 강화 비용으로 자동 소비하지 않는다. 석상 단계 1→5의 저장·전환은 연결됐지만 승인 이미지의 복원 연출은 미완료다.

첫 반복 빌런 기본형의 초중반 직접 전투를 만들지 않았고 마지막 변신 공격 프로필만 별도 시험 데이터로 연결했다. 5스탯·8기술속성 경계를 유지하며 ATK나 이동·상태·회복·충전·priority 효과를 추가하지 않는다. 본편 조우 XP는 시험값 0이다. 전체 의뢰 연결 시험은 낮은 조우 레벨 fixture이며 실제 약 60레벨까지의 성장 시간과 난도를 검증한 것이 아니다.

## 일반게임 XP — 사용자 확정과 시험 제안

사용자가 확정한 범위는 **정상 승리와 정상 패배의 개체 XP 지급, 항복·도주 0, AI/HUMAN 같은 결과별 기준**이다. AI와 사람 상대의 기준이 같다는 뜻이며 승리와 패배의 수량까지 같다는 뜻이 아니다. 랭크의 XP·평점·보상, 기존 자유 모험·본편 XP, 새우Gang 정책은 바꾸지 않는다.

`normal-xp-policy.json`은 `testValues=true`, `productionBalanceApproved=false`인 명시 시험 제안이다. 시작 레벨에 가장 가까운 기존 비튜토리얼 duel 조우의 `winXp/lossXp`를 재사용한다. 기존 패배 XP가 0인 행은 설정의 절반·최소 1로 보완한다. 실제 전투에 들어간 개체별 지급과 미출전 예비 0도 초기 분배 제안이다. 운영 수량·비율·분배 승인으로 표현하지 않는다. 운영 승인 파일은 제공하지 않았으며 새 normal 입장에 설정이 없으면 잠금 전에 503으로 닫힌다.

큐 입장 때 실제 계정 소유 개체·시작 XP·성장 곡선·결과별 지급량·정책 버전을 고정하고 방 snapshot으로 옮긴다. 서버가 판정한 정상 `BATTLE` 종료만 지급한다. 클라이언트가 결과를 신고하지 않는다. `(playerId, roomId, ownedId)` 원장, XP 증가, 대원 잠금 해제, 방 종료와 요청 영수증을 같은 트랜잭션에 저장한다. 결과 재조회·재접속·중복 명령·settle로 누적 지급하지 않으며 AI 가짜 Player·개체 보상은 만들지 않는다. 공개 DTO에는 해당 사람의 지급만 담는다.

무승부·연결 종료·타임아웃·서버 중단 보상은 미정이다. 특히 첫째·둘째 미입력 시 서버 자동 행동으로 KO가 나도 정상 XP로 위장하지 않고 `TIMEOUT_RESOLUTION_POLICY_PENDING`으로 0을 기록한다. 과거 normal 방은 소급 지급하지 않고 `LEGACY_POLICY_UNCONFIGURED`로 정산·해제를 허용한다. 구버전 큐나 카탈로그 변경 큐는 안내와 취소를 제공하며 다른 유효 대기자와 진행 방을 막지 않는다.

기존 `growthAt`가 상한 초과 정책을 요구하면 요청 XP 전체를 적용하지 않고 `CAP_POLICY_PENDING` 감사 기록을 남긴다. 잘라 지급·XP 은행·자동 환생·향후 자동 지급을 추가하지 않았다. 59레벨에서 상한을 넘는 지급도 보류될 수 있으므로 일반게임 성장 경로의 양수 XP 연결과 약 60레벨 완주 완성은 구분한다.

## 실제 Android 순환형 메인

`MainActivity.home()`은 전용 `NativeVillageHomeController/View`를 사용한다. 8U 마을의 네 구역은 지원소·아지트 → 기록소·우편함 → 바닷가 플레이 → 시장 순서다. 빈 산책로와 확장 공간을 두고, 연속 double 카메라의 화면 투영에서만 modulo를 적용한다. 원경·바다·지형·건물·배·주민 레이어가 전체 한 바퀴 뒤 같은 배치를 이루며 Android 관성과 드래그를 사용한다.

지원소는 모집, 아지트는 편성, 기록소는 도감/조합, 우편함은 우편/이벤트 소식/공지, 플레이는 탐험/실제 스토리/일반/랭크, 시장은 기존 아이템/패스/재화 보유·교환으로 연결한다. 시장 접점은 신규 현금 결제나 Billing·프리미엄 지갑 구현이 아니다. 홈 상시 재화 수치는 제거했고 소비 화면의 보유량과 비용은 보존했다. 출석과 내 정보·환생 안내·설정, 튜토리얼 실제 메뉴 대상도 보존한다.

대장장이·상인은 시장, 사서는 기록소, 방범대원은 아지트에 항상 존재한다. 서버 AVAILABLE일 때만 !를 표시하고 ACTIVE/READY/COMPLETED를 구분한다. 주민 탭은 대화·제안 확인이고 의뢰 수락은 별도다. 계정·토큰·화면/읽기 세대로 과거 응답을 거부하고 카메라는 안정적인 계정 ID별로 복구한다. 다른 계정이나 갱신 토큰의 복귀도 현재 화면을 다시 구성한다.

서버 최신 단일 실행은 **21파일·206시험, 186통과·20실패, exit 1**이다. Prisma 생성·TypeScript·임시 DB 스키마·seed는 모두 통과했다.

20개 실패와 별도 afterAll 오류는 모집 정책 시험의 `db.player.delete()` cleanup FK 제약이다. 정확한 c37c24e 별도 worktree·새 임시 DB에서도 같은 25개 중 5통과·20실패, 같은 실패명·유형을 재현했다. Story 표가 없는 기준 DB에서도 `DailyProgress.playerId → Player ON DELETE RESTRICT`와 남은 21행이 확인됐다. 관련 시험·모집·일일진행 세 소스 SHA도 기준과 같다. 이를 숨기거나 과거 cleanup/reset·운영 데이터를 수정하지 않았다. 부모의 이전 전체 서버 실패 수는 저자 보고이며 이 직접 통제 실행과 구분한다.

마지막 카탈로그 누락/읽기 예외 보강 뒤 별도 지정 시험 1개가 통과했고 TypeScript·diff 검사도 통과했다. 같은 시험 안에서 null/throw 두 경우의 고정 방 current→tick→정상 action→실제 60/20 XP→중복 정산과 다른 대기자의 취소·대원 해제를 검증했다. 앞선 206개 원본 실행과 별도 1개를 구분하며 207개 단일 실행으로 표현하지 않는다. 증거는 `normal-xp-catalog-safe-final`에 있다.

Android는 새 홈·자산 지연·카메라/배치·XP 표시와 기존 스토리·모집·조합·결과/편성 스크롤·대전을 합쳐 **22모음·147시험 모두 통과**했다(실패/오류/건너뜀 0). 해당 실행의 컴파일된 Controller 바이트코드에서도 마지막 계정 작업 무효화·상태 초기화·서버 재조회 분기를 확인했다. 이전 계정 콜백이 새 로딩을 종료하지 못하는 동작 시험을 추가한 최종 집중 3모음·32개도 모두 통과했다(실패/오류/건너뜀 0). 생산 Controller SHA는 147개 실행에서 보존한 값과 같으며 추가 시험만 재컴파일했다. 이 중복 시험을 더해 179개 고유 시험이라고 계산하지 않는다.

기존 Lobby 전용 시험은 보존된 레거시 컴포넌트를 명시적으로 생성해 검증하도록 의도를 바로잡았다. 실제 기본 홈은 새 Home 전용 시험으로 순환·실제 메뉴·주민·화면 수명을 검증한다. 기존 플레이 메뉴의 탐험·스토리·일반·랭크 네 항목도 실제 진입과 무자동 지출/참가를 확인한다.

세 규격(915×412, 1280×720, 915×412 글꼴130%)의 8U 전체 홈 24장과 정상 지급/상한 보류/이전 방 안내 XP 9장을 직접 픽셀 검토했다. 24프레임·240월드 영역의 geometry와 고정 버튼 48dp, 화면 내 이름·문구의 줄임/높이를 수치 확인했다. 잘림·겹침을 발견하지 못했으며 원화 미술 품질이나 실제 이미지 원본 일치의 검증으로 확대하지 않는다. `android-home-final`에 단계별 JUnit·로그·숫자·PNG를 보존한다.

홈 검증에서 빈 산책로의 DOWN이 FrameLayout 자체에 전달됐을 때 MOVE의 수평 slop 판정이 onIntercept에만 있어 드래그가 시작되지 않는 문제를 재현했다. onTouch의 실제 MOVE에도 같은 판정을 적용해 빈 공간에서 시작하는 드래그를 고쳤다. API fixture의 비동기 starter-loans 읽기 누락과 synthetic clock 문제는 생산 기능 결함과 구분해 기록한다. 또한 다른 계정 복귀 때 이전 me/profile 상태가 남는 경계와 401 후 비활성 홈이 남는 경계를 보완했다. 다른 계정은 이전 화면 작업 세대를 닫고 상태를 비운 뒤 native/state로 다시 읽으며, 같은 계정의 토큰 갱신은 카메라를 보존한다. 늦은 옛 계정 응답은 새 계정의 로딩을 종료하지 못한다.

c37c24e Prisma 스키마로 새 SQLite를 만든 뒤 스토리와 일반전 XP 두 추가 SQL을 순서대로 적용한 리허설은 `integrity_check=ok`, `foreign_key_check=[]`, 최종 Prisma와 `migrate diff` 차이 없음으로 통과했다. 운영 DB에는 적용하지 않았다.

원본 버그 패치·최종 전체 패치·원본 버그 위 후속 패치는 임시 Git index에서 적용 tree와 역적용 tree를 비교한다. 실제 증거의 정확한 해시·파일 수·명령 결과는 ZIP의 manifest 및 patch-verification을 따른다. 과거 story82·Android23, 초기 통합177/111 같은 수치는 이전 단계의 기록이며 최신 수에 더해 고유 합계로 계산하지 않는다.

## 시각 자산과 남은 경계

마을 9장·주민 4장 원본은 부모 환경에 준비됐지만 별도 이미지 브랜치 게시 허가는 아직 사용자 응답 대기다. 이 환경에서 실제 픽셀을 받지 못했으므로 13개 manifest 항목은 모두 `verified:false`이며 준비 중 문구와 자리 표시자로 실행된다. 거절된 파란 지붕·동일 체형 주민 시트는 사용하지 않는다. 로컬 검증 후 앱에 포함하는 복사 구조만 마련했고 런타임 개인 GitHub URL에 의존하지 않는다. 외부 이미지 게시를 대신 실행하지 않았다.

승인 석상 `libfile_359c4947aa748191917e41d690f91d3d`도 다운로드와 한 번의 재시도가 같은 기술 실패였다. 추가 공식 image read는 1536×1024·2,225,654 bytes와 명시 Sediment 포인터를 반환했지만 실제 ImageContent·base64·로컬 바이트는 없었다. 사용 가능한 보기 도구는 로컬 파일만 받고 포인터 해석 도구가 없어 실제 이미지 조회·5단계 영역 렌더를 완료하지 못했다. 다운로드를 더 반복하거나 다른 API에 ID를 대입하지 않았다. 저장된 단계의 텍스트 표시를 실제 이미지 복원 연출 완료로 표현하지 않는다.
