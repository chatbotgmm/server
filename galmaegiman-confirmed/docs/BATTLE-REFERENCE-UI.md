# 전투 화면 시안 반영

기준: `main-oz3tvo`의 `f1935a1` (v0.15.9), 사용자가 첨부한 1번 시안. 출시 버전·APK 버전은 이번 UI 변경에 포함하지 않았다.

## 변경

- 오른쪽 상단에 현재 전투 기록을 표시하고, 그 아래에 공격·아이템·교체·도망 버튼을 배치한다. 기록창 높이에 따라 버튼 영역이 줄어들어 큰 글자에서도 두 영역이 겹치지 않는다.
- 기존 나무·등불 조작판과 산호·조개 상태창 그림을 재사용한다. 해저 배경과 캐릭터 그림도 기존 파일을 사용한다.
- 상태창은 이름/레벨 → 전체 너비 체력바 → 속성/내 체력 수치 → 남은 팀원 → 증강체 순으로 표시한다. 상대 체력은 막대와 접근성 값으로 제공하며, 상세 정보 버튼도 유지한다.
- 버튼 아래에 현재 사용 가능한 기술 수, 아이템 사용량/보유량, 교체 대기 수, 도망 결과를 표시한다. 숫자는 실제 전투 상태에서 계산한다.
- 상태창을 만든 뒤 캐릭터 위치를 계산한다. 큰 글자나 여러 증강체로 내 상태창이 커지면 상대 그림의 아래쪽 위치도 조정한다.

수정 코드: `public/duel/index.html`, `public/duel/duel.js`. 전투 규칙·획득/보상·DB 스키마는 수정하지 않았다. 앱의 기존 `app/build-www.mjs`가 같은 HTML/그림과 묶인 JS를 복사한다.

## 검토에서 찾아 고친 것

- 고정 높이의 기록창 행 때문에 큰 글자에서 기록과 버튼이 겹치던 것을 자동 높이로 변경했다.
- 긴 상태 정보와 큰 글자에서 상대 그림과 내 상태창이 겹치던 것을 실제 상태창 위치를 기준으로 조정했다.
- 설정 버튼이 긴 기록을 가리지 않도록 기록 오른쪽에 여백을 둔다.
- 낮은 화면에서 기술 카드가 잘리지 않도록 필요한 경우 버튼판 내부 스크롤을 허용한다. 780×360·글자 130%에서 모든 기술 버튼을 스크롤하여 접근할 수 있는 것을 확인했다.

## 검증 (2026-10-12)

- 전투 엔진 테스트: `vitest run test/battle.test.ts --maxWorkers=1`, 23개 통과.
- `npm run data:check` 통과: 145종 이미지 존재, 33종 전투 유닛·24종 전투 증강체·4장 스토리 검증.
- `node --check public/duel/duel.js`, `node scripts/build-play.mjs`, `git diff --check` 통과.
- Playwright + 시스템 Chromium에서 실제 UI 소스·전투 엔진·규칙·그림·게임 글꼴을 사용한 로컬 점검. 계정과 아이템 API는 임시 fixture이며 실제 DB를 사용하지 않았다.
- 가로 1536×628, 1006×411, 915×412, 780×360, 1280×720: 기본 메뉴, 기술, 교체, 아이템, 교체 후 그림, 1마리 팀과 항구 배경 캡처. 915×412·1280×720의 로그인 전/후 첫 화면, 로비, 스토리 목록도 직접 검토했다.
- 기본 메뉴의 화면 넘침·버튼 잘림·상태창 겹침 없음. 글자 130%에서도 기록과 버튼판, 상태창과 상대 그림이 겹치지 않음. 780×360에서는 기술/교체 목록에 내부 스크롤이 필요할 수 있다.

## 후속 서버·DB 검증 (2026-10-12)

PR #1의 `codex/battle-reference-ui` 커밋 `83092235038ef03d6d9325cebecea6fd5806d7a4`에서 재검증했다. 이전 Prisma 다운로드 제한과 미생성 Client로 인한 빌드 실패는 아래 결과로 해소됐다. 애플리케이션 코드 수정은 필요하지 않았다.

- 환경의 네트워크 허용 목록에 `binaries.prisma.sh`가 포함되어 있다. 프록시를 통해 실제 Prisma 엔진의 `all_commits/c2990dca591cba766e3b7ef5d9e8a84796e47ab7/debian-openssl-3.0.x/schema-engine.gz.sha256` 경로에 접속해 HTTP 200을 확인했다.
- Node.js `v24.19.0`, npm `11.9.0`에서 `npm ci --cache /tmp/battle-reference-npm-cache --no-audit --no-fund` 통과. 실행 환경의 기본 npm 캐시 경로에 쓸 수 없어 임시 캐시를 사용했다. 잠금 파일은 변경하지 않았다.
- `npm run db:generate` 통과: Prisma Client `v6.19.3` 생성.
- `npm run build` 통과: TypeScript 컴파일 및 `scripts/build-play.mjs`의 웹 번들 생성 완료.
- `npm run test:db` 통과: 임시 SQLite DB에 스키마 적용과 145종 콘텐츠 시드를 수행한 뒤, DB 통합 테스트를 포함한 8개 테스트 파일·121개 테스트 통과. 기존 DB는 수정하지 않았다.

## 적용

웹 화면은 정상 빌드 후 적용된다. 앱에 반영하려면 정상 빌드 후 `app/`에서 `npm run sync`와 APK 빌드가 별도로 필요하다. 현재 변경은 검토용이며 운영 배포하지 않았다.
