# 78판 인게임 C 재질 통일

사용자가 다시 첨부한 C 「선장의 모험일지」를 인게임 전체의 재질·버튼·색감 기준으로 적용한다. 비교 보드의 제목/섹션 팻말이나 임의 게임 수치는 옮기지 않는다. G 시작 화면의 금갈색 시작 버튼, 원본 캐릭터, 게임 규칙과 서버 데이터는 유지한다.

## 적용 내용

- 양피지는 작은 섬유 재질, 바랜 가장자리, 가는 잉크선으로 표현한다. 큰 기록판은 목재 단면과 황동 모서리로 구별한다. 본문은 밝고 고요하게 두며 그림을 늘여 프레임을 만들지 않는다.
- 주요 행동은 깊은 청록 면·밝은 글자·얇은 황동 테두리, 보조 행동은 양피지·잉크 글자로 통일한다. 선택은 옅은 청록 종이와 안쪽 선, 비활성은 읽을 수 있는 밝은 면으로 구분한다.
- 메인은 성장 기록판과 상단 정보·재화, 하단6메뉴를 같은 재질로 연결한다. 큰 출석 가로판을 줄이고 플레이에 돛배 판화와 진행 화살표를 사용한다. 원본 캐릭터, 성장 정보, 패럴랙스와 시간대별 파도는 유지한다.
- 전투의 일반4기술은 양피지와 작은 도구/속성 기호를 사용한다. 합동기는 그 아래의 넓은 청록 카드로 구별한다. 이름·현재 위력/상성·짧은 핵심 효과를 유지한다. 추가 UX 요청에 따라 기본 화면을 고정하고 긴 선택·부가 설명은 모달로 분리한다.
- 조합·매점·탐험의 선택 목록은 공통 종이 선택 상태로 표시한다. 제작·획득 후 성장·스토리 시작·편성 저장·보상 받기 등의 실행 버튼과 공통 머릿말도 같은 규칙을 사용한다.
- 사용자 추가 요청에 따라 조합의 ‘조합식’과 ‘재료로 섞기’에서 상단 재화3개를 제거한다. 조합 재료의 보유·필요 수량과 제작 동작은 그대로 표시한다. 다른 화면의 재화 정보는 유지한다.
- 설정·검색/입력·슬라이더·음소거·모달·상성 탭·증강체·보상창과 결과 연출을 함께 정리한다. 경고/탈퇴·속성·상태이상·상성·등급의 의미색과 실제 숫자는 보존한다.

## 자산과 수명주기

새 자산은 `native/journal/parchment-grain.webp` 하나다. 첨부 C를 참고해 image_gen으로 만든 종이만 있는 그림을512×512 WebP로 변환했다. 파일8,524바이트, SHA-256 `d88cbc28186b1e35e9586770eba5dde27591bf6fd54d2e29175031c26a6ced72`이며 최대 디코딩 크기는1MiB다. 기존412개 APK 자산을 보존한다.

`NativeArt`의 기존 이미지 작업자에서 프로세스당 한 번 준비하며 준비 중 작업은 `idle()`에 포함한다. 완료 후 살아 있는 화면을 한 번 다시 그린다. `JournalMaterial`은 Context를 보관하지 않고, 준비된 Bitmap/반복 Shader·Paint·Matrix를 재사용한다. 시간이나 버튼 크기에 따라 종이 결을 흔들거나 늘이지 않는다. 파일이 없을 때는 기존 종이색을 표시하며 네트워크에서 소재를 받지 않는다.

새 렌더 루프·WebView·웹 프레임워크·권한·서버 API를 추가하지 않는다. Java17·Gradle8.14.3·API24 이상·가로 화면·동봉 글꼴을 유지한다.

## 기본 화면과 모달

기본 페이지는 세로로 스크롤하지 않는다. 로비의 성장 기록, 전투의 명령과 최근 기록, 조합의 재료·보유/필요 수량·제작, 뽑기3종의 수량·총비용·실행, 편성·저장, 출석 수령과 연습 상대·시작을 기본 화면에 둔다. 화면 높이에 따라 부가 설명과 그림의 여백을 조정하며 실제 글꼴·48dp 조작 높이는 줄이지 않는다.

전체 갈매미·조합식·상점 상품·탐험 후보·미션·순위·상성표와 검색·필터·긴 설명은 별도 창으로 연다. 모달 안에서만 세로 스크롤을 허용하고 제목과 닫기·확정 행동은 고정한다. 재료6칸과 획득 결과의 긴 가로 목록은 가로로 넘겨 모두 접근한다.

`JournalViewport`는 자연 높이로 측정한 완전한 행만 기본에 표시한다. 공간이 부족한 부가 목록은 ‘전체 보기’에서 같은 위젯·선택ID·콜백을 이어서 사용한다. 핵심 행동은 긴 목록 밖에 별도로 배치한다. 모달 종료 시 원래 크기 설정을 복원하고, 화면 전환·분리 시 열린 창을 닫으며 오래된 본문을 새 페이지에 붙이지 않는다.

로그인은 기본 카카오/코드 진입을 고정하고, 코드 입력은 키보드 크기에 대응하는 모달에서 이어간다. 긴 이야기 대사는 고정 미리보기의 ‘전문 보기’에서 서버 원문 전체를 읽는다. ‘닫기’는 대사를 유지하고 ‘다음’은 한 줄만 진행한다. 전투의 긴 기술명·큰 글꼴로4기술과 합동기가 들어가지 않을 때도 같은 선택지를 기술 모달에서 제공한다.

## 검토에서 확인한 문제

새 섬유 재질을 실제 합성한 검사에서 기존 보조 글자색의 대비 여유가 부족했다. 읽기 기준4.5를 유지하고 보조 잉크를 `#58635d`로 조금 진하게 조정했다. Canvas와 Android XML 색 토큰을 함께 맞췄다.

출석 카드의 보상 숫자가 왼쪽 목재선에 걸치는 것도 실제 캡처에서 확인했다. 카드 안쪽 여백과 일차·보상·상태의 중앙 정렬을 맞춰 프레임 안에서 읽히도록 보완했다.

작은 화면·큰 글꼴 캡처에서는 일부 큰 묶음이 통째로 ‘전체 보기’로 들어가 주요 행동까지 숨었다. 모드 진입, 편성 후보 선택, 뽑기 비용·실행, 조합 재료·수량, 출석 수령과 현재 상성을 기본에 남기도록 묶음을 나눴다. 스토리 동료3자리와 드래그 손잡이도 기본 화면에 유지했다. 기술 안내·상점·대전·연습의 사진 위 잉크는 밝은 종이 면으로 받치고 기술 카드의 중복 여백 때문에 효과 마지막 줄이 잘리던 점도 보완했다.

로그인 코드와 긴 대사의 모달을 취소·종료할 때 입력·이야기 진행을 보존하고 현재 대화상자 참조를 정리하도록 보완했다. API24에서는 위젯 이동·콜백·수명주기를 검증하며 실제 글꼴 픽셀과 클립 검사는 네이티브 그래픽 캡처로 따로 확인한다.

조합 재료 그림이 빈 상태로 남는 것도 직접 캡처에서 확인했다. 화면의 의미 태그가 이미지 요청 식별자를 덮어써 비동기 완료 반영을 막던 문제였다. `NativeArt` 내부 요청은 별도 리소스 키로 식별해 화면 태그와 분리하고, 같은 뷰에 더 최근 요청이 있으면 이전 이미지를 적용하지 않는 조건은 유지한다. 로딩 완료 후 재료·결과 이미지의 실제 Drawable도 검사한다. 획득 결과 하단 버튼은 행의 고정 높이와 내부 여백이 충돌하지 않도록 자연 높이로 배치하며, 카드도 실제 남은 높이에서 이름·등급·여백을 먼저 확보한 뒤 초상만 맞춘다.

릴리즈 정적 검사에서 새 최근 전투 기록 뷰의 `AppCompatCustomView` 호환성 오류를 확인했다. 표준 `AppCompatTextView`를 상속하도록 수정하고 전투 읽기·재생·안전 영역 관련15개 검사와 실제 캡처를 다시 확인했다. 오류를 억제하거나 lint 기준을 낮추지 않는다.
