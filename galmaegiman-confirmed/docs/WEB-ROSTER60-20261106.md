# 공개 홈페이지를 지금 게임(60종) 규칙으로 (2026-11-06)

사용자 지적: 게임이 60종으로 바뀌었는데 홈페이지는 예전 145종(카톡 챗봇) 내용이었다. 규칙이 바뀐 대로 바꾼다.

## 사용자 결정
- 예전 145종 페이지(도감·조합법·히든 단서·랭킹·수다방·이벤트·검색·프로필)는 **완전히 닫는다**: GET 요청은 첫 화면으로 301 이동, 메뉴·바닥·사이트맵에서 뺀다.
- PC 웹게임(/game)은 60종 이전 규칙이라 홈페이지 버튼을 빼고 **앱 안내(앱 다운로드)**로 바꾼다. 주소는 남겨 둔다. 60종 규칙으로 새로 만드는 일은 별도 작업.
- 세계관은 **스토리모드 기준으로 새로** 쓴다.

## 자료 출처(서버의 실제 파일을 요청 때 읽음, 파일이 바뀌면 다시 읽음)
| 페이지 | 자료 |
|---|---|
| 게임 소개 | `data/test-profiles/<ROSTER60_PROFILE>/catalog.json`(종 수·등급 수), `data/roster60-recruit-policy.json`(모집 종류·지원서 수), `data/story/story-mode-v1.json`(챕터 수). 규칙 문장은 앱 안내 문구(튜토리얼·설정 화면)와 배포된 경험치 정책을 따름 |
| 캐릭터 소개 | catalog.json의 커먼~전설 38종(히든·제한·초월·불멸·영원은 예전 공개 정책과 같이 비공개), 그림은 `art/gpt/registration-v10` 등록증을 360×480 WebP로 줄여 `public/site/units/`에 둠(비공개 등급 그림은 파일 자체를 두지 않음) |
| 모집 확률 | roster60-recruit-policy.json 등급 확률 ÷ 그 등급 종 수(모집 코드가 등급 안에서 균등하게 뽑음), 다시 뽑기 비용 = 비용의 절반, 보장 없음(pity none) |
| 세계관 | story-mode-v1.json의 첫 장면(STORY_01_intro) 대사, 챕터 제목·권장 레벨, 마을 주민 |
| 계정 삭제 안내 | 앱 설정 화면의 실제 순서(마을 메뉴 → 설정 → 계정 삭제 → 「탈퇴」 입력), 지워지는 범위는 앱 확인 창 문구, 백업 보관은 개인정보 처리방침(최근 7개) |

## 구현
- `src/site.ts`: `roster60Reader`, 요청 훅(예전 주소 301, `/odds`·`/world`·`/account/delete`·`/sitemap.xml` 새 페이지). 서버의 `web.js`는 저장소 빌드와 달라 건드리지 않고 `site.js`의 훅으로 가로챈다.
- 머리줄 행동은 「앱 다운로드」 하나(로그인·게임 시작은 예전 웹게임용이라 뺌).

## 남은 문제(이 작업 범위 밖)
- 다운로드 페이지에 실제 앱 링크가 아직 없다(`data/downloads.json` 비어 있음, 운영도 같음).
- 카톡 챗봇의 「공식 홈페이지 창설 기념」 쿠폰 이벤트(끝나는 날 없음)는 조각이 예전 세계관·조합법·히든 페이지에 있어, 페이지를 닫으면 챗봇에서 더 풀 수 없다.
- 서버 계정 삭제(`game.webDeleteAccount`)가 60종 대전 자료 `Roster60PvpParty`·`Roster60PvpQueue`·`Roster60PvpMatch`를 지우지 않는다(플레이어와 연결된 연쇄 삭제도 없음). roster60 쪽 서버 코드에서 따로 고쳐야 한다.
