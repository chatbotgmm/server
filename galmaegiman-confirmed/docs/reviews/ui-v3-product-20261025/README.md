# UI v3 실제 제품 연결 검증

입력: `87324357875f3bfbf35754095a70263cc0dfd401`의 `art/gpt/ui-v3-20261025`.
업로드 manifest의 227개 파일 크기/SHA256 일치. 편성, 전투 B, 조합, 기술 6칸,
누르는 동안 설명, 교체 PNG 6장을 실제로 열어 비교했다. u01 이름 갈매미맨 / 종족 태초 유지.

## 실제 연결
- 기존 org.gmm 제품 MainActivity 경로의 편성/전투/조합을 수정했다. 별도 review 앱이 아니다.
- 편성: 출전 1 + 예비 5 얼굴, 가로 보유 목록, 오른쪽 원본 전신과 실제 소유 레벨/5스탯,
  스토리 호출 확정·전투 시작. 관리 편성 저장 경로는 유지했다.
- 전투: 항구 B, 기존 질감 HP 패널/버튼, 우측 명령·기술·아이템·교체 2열×3행.
  기술 설명은 누르는 동안만 표시하고 손을 떼면 닫히며 시전하지 않는다.
- 교체: 얼굴과 현재/최대 HP·MP, 출전/기절 비활성, 후보 선택 후 확정.
  부활 아이템도 같은 영역에서 대상 선택. 일반 회복 대상 및 서버 효과 정책은 변경하지 않았다.
- 조합: 왼쪽 큰 등록증, 중앙 선택 재료 얼굴/어두운 빈 슬롯, 오른쪽 결과 등록증과
  서버 예상 레벨·누적 XP·잔여 XP. 기존 preview fingerprint/멱등 요청 유지.
- options DTO에 실제 소유 성장곡선의 레벨/상한/5스탯을 추가했다. 랭크 입장 정규화는 유지.
  DB 스키마, 가격, 확률, 성장·피해 정책은 변경하지 않았다.

## 자산과 검증
- 새 생성 자산 ui-v3: 74개 / 9,417,234 bytes (압축 전). 60종 128px 얼굴 포함.
  원본 시안/편집 소스/PDF/256px 중복 얼굴은 APK 자산 목록에서 제외한다.
- Canvas가 .9.png를 읽을 때 metadata의 interior rect로 1px marker를 제거한다.
  실제 HP bitmap 720×247 검증.
- 서버 `npm run build` 성공, 격리 `npm run test:db` 최종 66파일/689시험 성공.
  첫 전체 실행은 기존 realtime-casual-ai.integration.test.ts:86 무작위 AI 분기에서
  1건 실패했다. 해당 코드 변경 없이 단독 24/24 및 전체 재실행 689/689 성공.
- Android org.gmm debug 소스 컴파일 및 관련 Robolectric 18시험 성공.
- 이 폴더의 PNG는 실제 MainActivity/product View를 Robolectric native graphics로
  780×319, 1280×800 크기에 measure/layout/draw한 결과다. 이미지 재조립 시안이 아니다.
  API는 recording mock, 인물명·레벨·기술·예상 XP는 배치 시험용 fixture이다.
  실제 지급/계정/전투 밸런스 또는 라이브 서버 실행 증거가 아니다.

  수정했으며 폰/태블릿 양쪽을 렌더했다. 실기기 DPI/글꼴 확대 검증은 별도다.

## 렌더 QA 후속 수정
- 편성 진입 시 실제 NativeRoster60Battle 헤더를 `전투 편성 · 스토리/모험`으로 갱신한다.
  상단 뒤로가기는 편성을 닫고 전투 선택으로 돌아간다. 전투 snapshot bind 시 전투 헤더를 복원한다.
- 편성 하단 큰 이전/다음 버튼과 우측 돌아가기 버튼을 제거했다. 4명 가로 스와이프 + 작은
  페이지 표시를 사용한다. 드래그 시 자식 버튼에 CANCEL이 전달되어 대원 선택이 일어나지 않는다.
  대전/관리 보유 목록도 같은 가로 스와이프를 사용한다.
- 선택 대원 이름, 등급/레벨, 전신, HP/MP 및 나머지 3스탯을 분리했다.
- 공용 tab 스타일의 `selected=true`는 남색을 뜻하므로 조합에서는 실제 활성 탭이 밝아지도록
  색상을 명시적으로 반전하고 View.selected는 실제 모드를 보존했다. 재료/결과 왕복 시험 추가.
- 예상 결과 확인은 남색 보조 버튼, 조합 확정만 종이색 주행동이다. preview fingerprint와
  선택 변경 시 preview 폐기, 서버 재조회, 멱등 요청은 그대로다.
- 렌더 fixture에 불씨/황금/먹구름/긴 이름/서로 다른 등급을 사용했다. 이 명칭 조합과 수치는
  레이아웃 시험 데이터이며 실제 카탈로그를 대체하지 않는다.
- 후속은 Android만 변경했다. 서버 689개 성공 결과는 앞선 동일 서버 코드에 유효하다.

## P0 시각 수정 (93ae1c7 이후, Android만)
기준: `93ae1c75b79d4bee89d37521cb91b850996a0e70`. 서버 코드·가격·확률·성장/피해 규칙·DB 스키마는 바꾸지 않았다.

- 배율: 휴대폰 가로(전투 760×300dp, 편성 760×260dp, 조합 760×250dp)를 1로 두고 큰 화면에서
  글자·아이콘·여백·버튼 높이를 같은 비율로 키운다(최대 1.7배, `Roster60Scale`). 배율은 px이 아니라
  dp로 계산한다. 명령 칸은 높이를 너비×1.3까지만 쓰고 가운데, 편성/조합 칸은 너비×1.15~1.3까지만 쓴다.
  780×319에서는 이 제한에 닿지 않는다(전투·기술 780 렌더는 직전과 같은 배치).
- 큰 칸 얼굴: 128px 얼굴을 늘리지 않고, APK에 이미 있는 roster60-art 전신(501×512)에서
  faces/focus-manifest.json의 focusRect로 잘라 쓴다. 원본 해시·sourceRect가 같을 때만(60종 대조 일치).
  256px 얼굴·원본은 APK에 넣지 않았다(추가 자산은 focus-manifest.json 80,047 bytes).
- 기술 설명(누르는 동안): 전장 위가 아니라 상단 안내줄 자리에 띄운다. 얼굴·HP/MP·명령 칸과 겹치지 않음을
  시험으로 확인한다. 긴 설명은 칸 안에서 글자를 줄이고 그래도 넘치면 말줄임. 손을 떼면 닫히고 시전하지 않는다.
  다시 그려진 뒤 남은 옛 기술 버튼은 터치를 무시한다(배율 변경 중 누르고 있으면 떼는 순간 시전되던 문제를 시험에서 발견해 수정).
- 교체: 이름 / HP 현재·최대 / MP 현재·최대를 각 한 줄, 상태(출전 중·전투불능·후보·선택됨)는 얼굴 아래 표지.
  사용 불가 칸은 얼굴만 흐리게, 글자는 보조 잉크로 남긴다. 접근성 설명에 사용 불가 이유를 넣었다.
  큰 글꼴에서는 세 줄을 같은 비율로 줄인다. 교체 제한(출전·전투불능 비활성)은 그대로다.
- 교체 확정/취소: 「돌아가기」→「취소」 남색 보조(확정과 같은 글자 크기·같은 터치 높이), 확정만 크림색 주행동.
  취소는 서버 요청 없이 닫기만 한다(시험: 행동 0건).
- 편성: 편성됨은 왼쪽 위 출전/예비 표지, 현재 선택은 크림 테두리 + 오른쪽 위 「선택」. 이름은 한 줄에 맞춰 줄인다.
  스와이프는 선택 대원을 바꾸지 않는다(시험).
- 조합: 재료 칸 두 줄을 한 묶음으로 가운데 정렬, 「재료 n / 6」 표시, 이름 한 줄. 예상 결과 재조회·fingerprint·멱등 요청은 그대로다.
