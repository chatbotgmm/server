# 네이티브 71판 UI/UX 보완

대상은 70판의 로그인 게임 화면이다. `visual70/ux/review.json`의 14개 검토 항목을 읽기·전투 판단·변경 보호·동작 피드백 중심으로 보완했다. 캐릭터 33종 앞뒤 원본, 수비대 등급 프레임 카드, 기존 계정·진행·재화 규칙을 유지한다.

## 게임 흐름을 기준으로 한 UI 원칙

핵심 흐름은 **뽑기 → 상위 갈매미 조합 → 육성 → 속성 상성과 증강체를 활용한 턴제 전투**다. 획득 뒤에도 경험치·학습·승진을 통해 성장하고, 상성에 따른 편성과 증강체 선택이 전투 결과를 다채롭게 만든다. 성장 화면에서는 다음 목표와 필요한 조건, 전투 화면에서는 선택의 근거인 상성·현재 효과·남은 턴을 우선 읽을 수 있게 한다. 이번 보완은 이 판단과 이동을 돕고 기존 전투·확률·재화 규칙을 유지한다.

## 검토에서 추가로 고친 것

- 큰 글자의 유닛 요약에서 경험치 하단 5px가 잘렸다. 폰은 그림·이름을 가로로 배치해 HP/경험치 공간을 확보했다.
- 1.3배 기술 카드의 두 열에서 한글 어절이 끊겼다. 좁은 폰 패널은 한 열로 전환하고 상세 버튼과 효과 본문을 다른 행으로 나눴다.
- 효과 상세의 의미 색이 공통 대화창 스타일에 덮였다. 텍스트 색상 Span을 사용해 의미 색과 이름을 유지했다.
- 폰 캡처 뒤 태블릿 캡처를 만들 때 이전 루트 높이로 작은 화면 배치가 선택되는 검토 방법의 문제를 고쳤다. 새 크기 설정과 실제 루트 측정·배치를 모두 적용한 다음 화면을 생성한다.
- 지연 응답 복구는 전투 행동을 다시 보내지 않고 현재 전투를 조회하도록 했고, 파괴된 Activity의 지연 응답은 무시한다.
- 릴리스 lint에서 API 24·25가 사용할 수 없는 오디오 포커스·파일 저장·애니메이션 API 호출을 발견했다. 구형 API 분기와 파일 스트림 저장을 적용하고 시스템의 애니메이션 끄기를 유지했다.
- 시스템 뒤로 가기를 AndroidX dispatcher에 연결해 제스처에서도 기존 화면 복귀·종료 확인·처리 중 보호를 따른다.

## 검증과 배포

- 버전: `71 / 2.0.8-native`, 개선판 패키지 `org.dpdns.gmm.native.revised`.
- 호환성·시스템 뒤로 가기까지 반영한 최종 전체 실행에서 네이티브 103개 테스트가 모두 통과했다.
- 서버 빌드와 격리 DB 테스트 157개 통과. 실제 운영 DB는 테스트하지 않았다.
- 실제 게임 글꼴로 웹 80장과 Android View/Native Skia 107장을 촬영했다. 가로 915×412·1280×720의 로그인 전후·로비·전투를 직접 검토하고, Z플립 안전 영역·1.3배 글자·수비대·성장·뽑기·탐험·미션도 확인했다.
- 웹 숫자 검사: 실행 오류 0, 스크롤로도 접근할 수 없는 버튼 잘림 0, 상태판/캐릭터 겹침 0. 780×360 큰 글자에서는 추가 버튼을 스크롤로 제공한다.
- 서명·릴리스 검사와 배포 결과는 아래에 기록한다. 로컬 검토 산출물은 `/workspace/review-artifacts/pr-2/ux71/`에 저장한다.

## 측정 범위

Android Java View/Native Skia 캡처와 웹의 실제 글꼴 캡처를 사용한다. 휴대폰 915×412, 태블릿 1280×720과 Z플립 안전 영역 시뮬레이션, 글자 배율 1.3을 확인한다. 실제 물리 Z플립 설치·접힘·터치 검증이나 전체 시각 일치율 95% 달성을 주장하지 않는다.

수비대 목록은 70판에서도 원본 등급 프레임 카드를 정상 사용했다. 이전 시각 보고서의 수비대·편성 모두 스프라이트라는 표현은 바로잡았으며 원래 측정 캡처와 수치는 변경하지 않았다.
