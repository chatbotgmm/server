# Android 제품 인간 PvP 연결

- 제품 새 로스터의 홈 `전투 편성` → 서버 `native/roster60/pvp/options` → 총 1~6개 순서 편성 → `pvp/party` 저장.
- 일반/랭크 선택은 편성을 먼저 서버에 저장하고 `pvp/join`으로 연결. 기존 modesPvp 및 startFight normal/rank도 같은 진입을 사용.
- `pvp/current`로 대기/수락/전투/결과를 복구. 큐 취소가 매칭과 경합해 battle을 돌려주면 전투 수락 화면으로 이동한다.
- 10초 수락은 서버 deadline 표시. 양측 수락 이후에만 전투 명령을 활성화.
- 기존 NativeRoster60Battle의 실제 6명령·최대6기술·길게 누르는 동안 설명·해제 미시전·로컬 앞뒤 아트를 재사용. 실행은 `pvp/action`이며 AI의 `battle/action`은 호출하지 않는다.
- 별도 `|human-pvp` 계정별 요청 저장 영역. 응답 불명확하면 동일 requestId로 재시도. 서버 영수증 후 current polling으로 최신 공유 상태를 복구.
- 상대 행동 선택은 UI에 표시하지 않는다. 자신의 제출 또는 상대의 강제 교체 대기 동안 명령을 잠그고 별도 항복 버튼은 유지한다.
- 기절 후 교체는 기존 수동 선택기를 사용한다. 자동으로 예비를 선택하지 않는다.
- 정상 UI 뒤로가기/백그라운드에서 polling을 중단하고 화면 재진입/복귀 때 current를 다시 조회한다. 앱 재시작은 홈 전투 편성 진입으로 서버 진행중 대전을 복구한다.
- 구 NativeRealtime 자동복구/재개는 새 로스터 계정에서 호출하지 않는다. 신규 편성은 PvP용 저장이며 AI/모험은 기존 새 1+5 선택 경로 유지.
- 상태이상·웹·채팅·감정표현은 추가하지 않았다.

## 검증
관련 Robolectric + debug Java 컴파일 실행. 신규 사례: 제품 편성 max6/저장/일반 매칭/큐 취소, 수락/6번째 기술/롱프레스 취소/같은 요청 재시도/상대 대기, 기절 수동 교체/백그라운드 polling 중지.
640×320 PNG는 Robolectric 네이티브 View 테스트 렌더이며 실제 휴대폰 캡처가 아니다. 테스트 데이터, 승인된 로컬 u01 아트와 실제 패널을 사용한다.
실제 두 휴대폰/EC2 네트워크 E2E 및 운영 배포는 실행하지 않았다. 부모 서버 변경과 실제 HTTP 계약 통합 테스트가 별도로 필요하다.

서버가 상대 거절/수락 시간 만료에 `requeued:true`를 반환하면 이미 수락한 사용자는 종료 결과 수령 대신 매칭 대기 화면으로 복귀한다. 재대기 정책/시점은 서버가 결정한다.

관련 테스트 20개 통과(신규 인간 PvP 4개 포함), `:app:testDebugUnitTest` 및 Java compile 성공. 로그 `/tmp/pvp-android-final.log`. `android-robolectric-640x320.png`에서 캐릭터 앞뒤·5스탯·6기술·상대 대기·항복 버튼을 확인했다. 서버 시험 프로필은 활성 턴 안내에 ‘시험안’으로 표시한다.
