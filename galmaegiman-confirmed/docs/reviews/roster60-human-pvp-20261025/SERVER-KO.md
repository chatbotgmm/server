# 새 로스터 인간 PvP와 편성 — 2026-10-25

## 연결 범위
기존 Android 제품의 전투 편성/대전 진입에서 새 인증 API `native/roster60/pvp/{options,party,join,cancel,current,accept,action,settle}`를 사용한다. 웹/채팅 신규 화면은 만들지 않는다.
서버 `RosterPvp`는 실제 서로 다른 Player의 1~6개 Roster60Owned를 잠그고 영속 공유 매치를 만든다. 1개체 출전+예비 최대5, 동시3대3이 아니다. 보호/타인/중복/일곱번째/경쟁 상태를 거절한다. 편성은 실제 ownedId 기준 저장한다.
기존 구 인간 PvP는 새 로스터 계정에 명시적으로 새 화면 사용을 요구한다. 구 경기 자료와 리플레이는 삭제하지 않는다.

## 재사용한 정책
- 평점차:100에서5초마다25 증가, 최대1200; 랭크 티어차30초마다1 확대; 선대기/가까운 평점 우선.
- 수락10초, 행동30초, 3회 연속 미응답 패배, 최대 방 수/검색량/대기lease/최대방시간은 기존 REALTIME_LIMITS.
- 상대 거절/수락시간초과 시 이미 수락한 쪽은 기존 대기시각으로 복귀.
- 일반전 실제 성장, 랭크 기존 Lv30 기준. 구 등급전용3마리 제약은 제거.
- 기존 Ranked/Casual rating 정산 함수를 재사용. 정상 전투 승리 기존 플레이포인트3 유지. 기존 실제 인간 PvP에는 개체 XP 지급이 없었으므로 0 유지하며 항복도0. 모험100/50 XP 승인을 대전에 적용하지 않음.
- 이번 새 경로는 실제 인간 매칭이다. 기존 일반전30초 AI대체는 구 엔진 경로에 남아 있고 새 인간 큐에는 아직 이식하지 않았다. 랭크 AI없음은 동일. 이 차이를 전체 매칭 기능 완료로 숨기지 않는다.

## 전투와 안전장치
5스탯/8기술속성/적합도10%/무효·반사/MPfull/집중25%와 승인 시험프로필 계산을 사용. 상태이상 효과·지속시간과 시너지 신규 효과는 미도입.
양쪽 선택을 서버에만 저장하고 둘 모두 선택하면 동시 해결. 첫 제출은 턴 revision을 올리지 않아 상대의 같은 턴 제출이 유효하다. 공개 응답은 자기 제출 여부만 포함하며 상대 pending 및 seed를 내보내지 않는다.
교체와 아이템은 공격/기술보다 먼저인 같은 우선그룹이며 그룹 안에서는 기존 최종 속도/서버 seed 동률 규칙. 모든 공격은 실행 시 현재 출전 대상을 확인한다. 기절 뒤 강제교체는 본인 선택이며 행동을 소비하지 않고 자동 예비 선택하지 않는다. 강제교체 미응답은 deadline 정책으로만 처리한다.
아이템은 실제 재고를 예약 차감하고 공용 RealtimeItemEscrow에 HELD 저장하여 상점 보유상한과 정합. 사용시CONSUMED, 실행 전 종료/취소는REFUNDED. 상대 행동/seed/아이템 재고는 공개하지 않는다.
각 요청은 계정별 requestId와 payload 지문 영수증. 재전송 고정 결과, 다른payload 재사용 거절. 세션 소유권검사, DB writer lock, phase revision, 정산 함수의 영수증과 상태 전이가 중복효과/중복정산을 방지한다.
양쪽 결과 확인은 개별 ack로 관리하여 한쪽의 정산 버튼 때문에 다른 쪽 결과가 사라지지 않는다. 서버1초 sweep는 연결이 끊긴 대기/경기와 item hold/owned lock을 정리한다. 서버 close시 sweep 종료대기.

## 심사용 로그인/운영 전 준비
ReviewAuth 로그인·비밀번호 해시·세션수명·기존 전용 Player 검증을 변경하지 않는다. 새 경로는 명시적 allowlist만 추가. 관리자/계정삭제/계정연결/쿠폰 권한은 추가하지 않는다. 기존 심사 로그인은 새 게임과 같은 규칙을 사용한다.
운영 비밀을 읽거나 출력하지 않았다. 운영 DB/서버/계정 생성·변경도 하지 않았다.
향후 DB 초기화는 별도 실행승인 필요. 실행 전 대상 DB와 서비스, `scripts/backup.sh`의 복구 가능한 백업을 확인하고 복원 검증 후 유지대상을 확정한다. REVIEW_LOGIN_PLAYER_ID가 가리키는 비관리자 전용 Player 및 기존 인증설정은 유지해야 한다. 심사계정 게임상태만 초기화할 경우에도 그 범위를 별도로 명시해야 한다. 계정을 삭제한다면 기존 REVIEW_IDENTITY/비관리자/외부연동없음 조건을 만족하는 재생성 절차와 설정갱신 승인이 선행돼야 하며 자동 생성하지 않는다.
이번에는 migration SQL과 Prisma schema만 작성하고 /tmp 격리 DB에만 적용. 운영에는 아무 migration도 실행하지 않았다.

## 검증과 남은 범위
DB 서비스 및 실제 Fastify 인증 HTTP경로의 두 계정 매칭→수락→양측행동→항복→양측결과확인을 테스트한다. Android는 실제 제품 진입 + mock transport + Robolectric이며 실제 두 휴대폰/운영 서버 연동 검증은 아니다.
새 아트 전송403 경로 재시도 없음. 기존 로컬 앞뒤 아트/벡터 fallback 유지. 새 APK 배포·운영서버 적용·외부 업로드 없음.
