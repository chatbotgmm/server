## 실제 제품 연결 지점
- `app/android/app/src/main/java/org/dpdns/gmm/NativeRoster60Library.java`의 `recruit()`가 인증 API `native/roster60/recruit/session` 응답과 저장 요청/결과를 확인해 `NativeRecruitSession.open()`으로 연결한다.
- `NativeRecruitSession.candidateView()`는 현재 남색 임시 프레임 + 제목 + roster60 정면 그림 + 이름/등급/레벨을 구성한다. 실제 v10 카드 로더를 연결할 지점이다. 완성 PNG에 이미 포함된 프레임/제목을 중복 합성하지 않되 미수령/수령 완료와 현재 레벨 등 동적 정보는 별도 UI로 유지한다.
- `RecruitCardTransition`은 기존 View를 8개 clip strip으로 내려보낸 뒤 새 View를 투입한다. Bitmap 캡처 없이 구현되어 새 카드 View에도 재사용 가능하다. 모션 감소/해제 시 기존 즉시 교체 경로를 유지한다.
- 후보 세션이 비활성이고 기존 요청도 없으면 `NativeRoster60Library.recruitLegacy()`로 간다. 현재 이 경로의 `showReceipt()`는 지급 결과를 텍스트로 표시한다. 후보 화면만 교체하면 현재 활성 모집 결과에는 새 카드가 보이지 않을 수 있으므로, 실제 수령 결과에도 같은 카드 로더를 연결해야 한다. 유료 리롤 정책 활성화와는 별개다.
- `RecruitmentArtwork`는 구 모집 트레이이며 `NativeEconomy`에서 실제 참조된다. 이름만 보고 삭제하지 않는다. 전투 `NativeRoster60Art`와 `roster60-art` 앞뒤 이미지는 변경하지 않는다.
- 도감 전체를 등록증으로 교체하는 것은 이번 범위로 추정하지 않는다.
