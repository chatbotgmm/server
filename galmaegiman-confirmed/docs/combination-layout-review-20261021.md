# 조합 화면 카드 크기·재료 칸 수정 검토

기준: `fac667d47edd1a58e8ead2ad14bb7a1c9d91ef0a`, 검토 브랜치 전용. 병합·APK 빌드·배포 없음.

## 원인과 수정
- 카드 위 별도 모드 탭 48dp, 페이지 이동 48dp, 카드 아래 추가 버튼 48dp, 남색 이중 틀 여백이 같은 높이를 나누고 있었다.
- 재료 모드 탭만 기존 머리줄의 빈 폭으로 이동하고 추가 버튼을 기존 하단 행동줄의 왼쪽 빈 자리로 이동했다. 이전/다음 48dp 터치 버튼, 페이지 수, 원본 등록증 비율과 스와이프는 유지한다. 왼쪽 중복 남색 틀·여백을 제거한다.
- 가운데 네 칸은 실제 클리핑이 아니라 `max(4, 선택수+1)` 정책이었다. 처음부터 서버 `maxMaterials` 전부를 그린다(구 서버 기본6 유지, 서버5도5).
- 재료 열 수는 실제 측정 폭에 맞춰 3→2→1로 줄인다. 높이가 부족하거나 서버 한도가 커지면 최소48dp 칸을 유지하고 스크롤바로 나머지 칸에 접근한다.
- 선택/결과 제목은 비상호작용 제목이므로 최소32dp + 내용 높이로 측정한다. 큰 글꼴을 강제32dp 안에 자르지 않는다.
- 결과 패널, 선택/제거/확인/서버 조합 규칙은 유지. 탐색만으로 선택하거나 소모하지 않는다.

## 실시한 검증
- Java compiler AST 파싱: 변경 Java2개 오류0. Android 의미분석/컴파일은 아님.
- `python galmaegiman-confirmed/scripts/check-combination-layout.py`: 126개 산술 조합 + 소스/동작 가드 통과. 915×412,1080×444,1280×720, density1/1.5/2, safe inset, fontScale1/1.3/1.5, 한도0/2/4/5/6/9/12 포함.
- 915×412 mdpi 카드 가용 높이 산술132→246dp,1080×444 mdpi164→278dp. 실제 등록증은 기존 contain 로직으로 최대 내접한다. 수치는 Android 렌더 캡처가 아니다.
- 독립 코드 검토: 좁은 폭 추가 버튼/3열 터치 크기/고정 제목 높이 문제를 찾아 재수정했고 후속 검토 통과. 48dp 페이지 버튼을 되돌리고 추가 버튼의 전체 왼쪽 폭을 확보했다.
- 기존 Robolectric 워크벤치 캡처 테스트에1080×444 mdpi/240dpi 추가. 초기 한도2/5/6/9의 칸수, 기본6칸 viewport 안, 915×412 카드 최소240dp, 컨트롤 이동·무소모 검증 추가.

## 미검증 / 제한
이 실행 환경에 Android SDK/android.jar/Gradle/Robolectric 의존성이 없어 네이티브 테스트·실제 게임 글꼴 캡처·기기 터치는 실행하지 못했다. 위 Robolectric 테스트는 **작성됨, 실행 안 됨**. 산술 검사와 AST 파싱을 네이티브 성공으로 취급하지 않는다. 매우 낮은 유효높이(예:1080×444px density2+inset)는 조작48dp를 유지하므로 카드 가용 높이가 여전히 작다. 실기기 검토가 필요하다. 기존 승인된 빌드 미검증 검토 브랜치에만 올린다.
