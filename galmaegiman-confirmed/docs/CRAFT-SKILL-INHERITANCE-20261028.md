# 조합 기술 계승 09 · 서버 검토본

현재 조합은 재료의 평균 누적 XP만 결과 개체에 보존하고 기술은 종 기본값으로 다시 계산한다. 이 패치는 결과 개체에 기술 한 슬롯의 계승 기록을 저장하고, 전투·편성·모험·PvP·내 갈매미가 같은 계산을 사용하게 한다. 성장 곡선, 환생 보너스, 지급량, 일반공격과 기존 전투 스냅샷은 변경하지 않는다.

## 확정 규칙

- 결과 종은 기존 `resultId` 조합식으로 고정한다. 실제로 보유·사용 가능한 모든 재료의 **현재 해금된 장착 기술**을 모으며 일반공격과 아직 해금되지 않은 기술은 후보에서 제외한다.
- 기술 ID로 후보를 하나씩 합친다. 같은 기술을 여러 재료가 보유하면 서버가 실제 원본 중 가장 낮은 필요 레벨을 선택한다. 동률은 owned ID, 재료 기술 슬롯 순으로 고정한다. 선택한 출처·필요 레벨·MP·속성은 확인 전에 표시한다.
- 총 한 기술만 직접 선택하고 결과의 기존 기술 한 슬롯과 교체한다. 기존 기술 수를 유지하며 최대 6개, 일반공격은 별도다. 없는 여섯 번째 기술을 임의로 만들지 않는다.
- 후보 ID가 결과 기본 기술에 이미 있으면 **그 동일 ID 슬롯만** 교체할 수 있다. 기술 종류가 그대로인 것과 필요 레벨이 달라지는 것을 응답에서 명시한다. 실제 u37 조합처럼 모든 후보가 기본 기술과 겹쳐도 하나를 선택할 수 있고 중복 슬롯은 생기지 않는다.
- 원본 필요 레벨은 낮은 교체 슬롯의 해금 레벨로 낮아지지 않는다. 획득 시 기록한 원본 레벨을 하한으로 유지하고, 현재 서버 원본이 더 높은 레벨을 요구하면 그 높은 조건을 적용한다. MP·속성·위력은 현재 서버 원본에서 읽는다.
- 환생은 같은 owned ID와 계승 기록을 유지한다. 레벨 초기화 후 같은 해금 조건으로 다시 잠긴다. 재조합은 선택한 한 기술의 원본만 이어받으며 다른 재료의 계승 기록을 누적하지 않는다.

## 저장과 배포 경계

`Roster60Owned.skillInheritanceJson`에 nullable TEXT 열 한 개를 추가한다. 기존 행은 null이고 기존 종 기본 기술을 그대로 사용한다. 저장값은 서버가 만든 버전·교체 슬롯·기술 ID·원본 종/슬롯·원본 필요 레벨·카탈로그 버전뿐이다. 클라이언트가 보낸 MP·위력·필요 레벨을 저장하지 않는다.

추가 migration과 동일한 수동 ALTER 스크립트를 제공한다. **둘 중 한 경로만** 기존 배포 절차에 맞게 검토·적용해야 한다. 기존 테이블 삭제·데이터 초기화·재작성은 없다. 운영 DB에는 적용하지 않았다. 새 서버 코드 전에 스키마를 반영하고 새 Prisma client를 생성해야 한다. 이번 검증용 client는 별도 복사한 node_modules에만 생성했다.

앱과 서버의 전환이 필요하다. 구앱의 새 조합 확정에는 계승 선택이 없으므로 `409 INHERITANCE_SELECTION_REQUIRED`로 소비 없이 거절한다. 과거에 이미 완료된 영수증의 같은 요청은 기존 해시 형식을 그대로 재생한다. 새 앱에서만 선택 UI를 노출하고, 운영 반영은 별도 승인·배포 작업이다.

## API 계약

기존 `craft/options`에는 `inheritancePolicy`를 추가한다. `craft/preview`와 `craft/confirm` 요청의 선택 필드는 `inheritance: {skillId, replaceSlot}`이다. 슬롯은 0 기반 정수 0~5이며 실제 결과 슬롯에 존재해야 한다. 숫자 수치·출처·기술 여러 개는 요청 필드로 허용하지 않는다.

미선택 preview도 원래 결과 레벨·XP·fingerprint와 다음 정보를 반환한다.

- `inheritance.status`: `selection-required` 또는 `selected`.
- `candidates`: 기술 ID·이름·속성·MP·위력·필요 레벨, 실제 재료/원본 출처, 서버가 허용한 `allowedReplaceSlots`.
- `resultSkillSlots`: 실제 결과 슬롯의 기술과 필요 레벨·결과 레벨에서의 해금 여부.
- `selected`: 선택 기술·교체 슬롯·기존 기술·출처·해금 여부, `kindUnchanged`, `requiredLevelChanged`. 미선택이면 null.

선택 후 preview를 다시 받아 그 fingerprint로 확정한다. 재료 ID·XP·기존 계승 기록·후보 기술 수치·해금 레벨·대상 슬롯 변경은 기존 proof를 무효화한다. UI에서도 재료를 다시 고르면 이전 선택을 지워야 한다.

`owned/read`는 기존 attack/current/nextLearn을 보존하며, 본인 전용 `skills.slots`에 잠긴 기술과 계승 표시를 추가한다. 슬롯의 기술 ID 필드명은 기존 기술 DTO와 같은 `id`다. 후보의 필드명 `skillId`와 구분한다. 종 도감이나 상대 공개 DTO에 이 개체 기록을 추가하지 않는다.

## 트랜잭션·공개 범위

모든 재료는 요청 계정 소유·AVAILABLE·잠금 해제·기존 조합 레벨 조건을 다시 확인한다. 기존 환생 재료 조합 제한은 유지한다. 같은 트랜잭션 안에서 각 재료의 XP·환생 수·계승 기록까지 확인해 소비하고, 결과 한 개·기술 한 개 기록·기존 일일 진행도·영수증을 함께 확정한다. 결과나 영수증 기록 실패는 전부 롤백한다.

완료 영수증은 요청 계정과 request ID로 찾는다. 같은 요청은 같은 결과를 재생하며, 다른 기술·슬롯으로 request ID를 재사용하면 거절한다. SQLite writer와 기존 공유 write queue를 사용해 동시 요청도 한 번만 소비·지급한다.

원본 기술이 삭제되거나 슬롯의 ID가 달라지면 임의 대체하지 않고 명시적 서버 오류로 차단한다. 카탈로그 변경에 따른 별도 데이터 이관이 필요한 경우다. 같은 ID에 서로 다른 전투 수치가 섞인 후보도 숨은 변형을 임의 선택하지 않는다.

기존 `publicDefenseSafe`와 상대 관측 경계를 유지한다. battle/PvP에는 장착·해금된 기술만 넣으며 원재료 ID·계승 JSON·잠긴 슬롯·개체 전용 내성은 새로 공개하지 않는다. 이미 시작한 전투·모험은 저장된 기술 스냅샷을 다시 계산하지 않는다. 08의 신규 편성 최대 3 및 기존 진행 중 6마리 복귀 규칙은 보존한다. 랭크의 기존 정규화 레벨에서 해금된 기술만 사용하는 규칙도 바꾸지 않는다.

## 검증 범위

분리된 임시 SQLite에서 계승 계산·출처·해금·동일 ID 슬롯·소유권·미리보기 변경·원자성·동시 요청·과거 영수증·환생·재조합·실제 전투/모험/PvP·인증 API 및 additive migration을 검사한다. 최종 시험 수와 원본 XML·로그·소스 해시는 동봉한 결과 파일을 따른다.

APK·실기기 FPS·운영 DB migration·서버 배포는 수행하지 않았다. 테스트 카탈로그·플레이어·재화는 시험 데이터이며 실제 사용자 상태가 아니다.
