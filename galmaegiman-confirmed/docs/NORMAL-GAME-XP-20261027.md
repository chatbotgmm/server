# 일반게임 정상 완주 개체 XP

사용자 확정: 일반게임의 정상 승리와 정상 패배는 개체 XP를 지급한다. AI 상대와 사람 상대는 같은 결과별 지급 기준을 사용한다. 항복·도주는 지급하지 않는다. 랭크 XP·점수·재화, 모험 XP, 스토리 XP와 어둠의 새우Gang 지급 규칙은 이 변경 범위가 아니다.

## 시험 정책과 미정 정책

`data/test-profiles/five-stat-device-test-v1/normal-xp-policy.json`은 운영 밸런스 승인이 아닌 명시적 시험 정책이다. 실제 전투에 들어간 개체 각각만 지급하는 분배도 초기 시험안이다. 초기 출전 개체와 실행된 교체·강제 교체 대상이 해당하며 미출전 예비 개체는 받지 않는다. 모험의 100%/50% 분배를 복사하지 않는다.

지급량은 기존 전투 정책의 `mode=duel` 조우에서 출전 개체의 시작 레벨에 가장 가까운 행의 `winXp/lossXp`를 재사용한다. 거리 동점은 낮은 레벨, 그다음 조우 ID 순서다. 기존 `lossXp`가 0이면 시험 설정의 분자·분모·최소값으로 양수를 마련한다. 현재 시험 제안은 승리 XP의 절반을 버림한 값과 최소 1 중 큰 값이며, 이 비율은 사용자 승인이 아니다. 양수 승리 XP 원본이나 정상 정책이 없으면 일반게임의 새 입장을 소유 개체 잠금 전에 거절한다.

무승부·타임아웃·연결 종료·서버 중단 보상은 결정되지 않았다. 서버의 최종 사유가 `BATTLE`이고 승자가 정해진 정상 종료만 새 지급 대상이다. 첫 번째·두 번째 미입력 제한 시간에 서버가 자동 공격을 넣어 KO가 난 경우도 정상 XP 대상이 아니다. 기존 방 종료 사유·랭크·점수 계약을 바꾸지 않고 서버 전용 시간 초과 경로 표시로 `TIMEOUT_RESOLUTION_POLICY_PENDING`을 기록한다. 이전에 시간 초과가 있었더라도 이후 사용자가 직접 조작해 정상 종료한 별도 턴은 정상 판정을 유지한다. 미정 사유는 `*_POLICY_PENDING`으로 표시하고 지급을 확장하지 않는다. 항복은 명시적으로 0이다.

기존 최대 60/환생 후 99 성장 경계는 그대로 사용한다. `growthAt`가 `CAP_XP_POLICY_REQUIRED`를 반환하면 개체를 잠그지 않고 전투 종료·대원 해제를 완료한다. 원자 지급 기록에 요청량·적용량 0·보류량·`CAP_POLICY_PENDING`을 남긴다. 이 보류량은 미적용 요청의 감사 기록이며 소비 가능한 지갑이나 자동 향후 지급 약속이 아니다. 잘라 버리기·초과 XP 은행·자동 환생·다른 재화 전환은 구현하지 않는다.

## 저장과 복구 경계

일반게임 입장 전에 계정의 실제 보유 개체, 시작 XP, 환생 횟수, 성장 곡선, 정책 버전과 결과별 지급량을 검증하고 큐에 고정한다. 매칭 후 방 snapshot으로 옮기므로 이후 정책 파일이 바뀌거나 없어져도 이미 시작한 정상 전투의 지급 기준은 바뀌지 않는다. 큐 중 카탈로그 버전이 달라지면 그 큐의 새 방 생성을 차단하고 `normalXpCondition=NORMAL_XP_CATALOG_CHANGED`와 취소 가능 상태를 알린다. 다른 대기자와 진행 중인 방의 시간 처리는 계속된다. 해당 사용자는 대기를 취소한 뒤 새 설정으로 다시 입장할 수 있다.

`Roster60NormalXpLedger`의 `(playerId, roomId, ownedId)` 복합키가 한 번만 적용되는 결정을 보장한다. 실제 XP 증가, 대원 해제, 방 종료, 기존 점수 정산과 요청 영수증은 같은 서버 트랜잭션이다. 실패하면 함께 되돌아가고 동일 요청을 다시 실행할 수 있다. `current`, `action`, `settle`, 재시작, 결과 재조회는 다시 지급하지 않는다. AI의 가상 계정이나 가상 개체에는 지급 기록을 만들지 않는다.

정책이 고정되기 전에 존재한 방에는 새 보상을 소급 판단하지 않는다. `LEGACY_POLICY_UNCONFIGURED`로 명확히 표시하고 대원 해제·기존 정산을 허용해 고착을 막는다. 정책이나 버전이 없는 이전 큐로는 새 방을 만들지 않고 정책 확인 안내와 대기 취소를 제공한다. 취소 후 새 정책으로 재입장할 수 있다. 새 일반게임 입장의 누락 정책을 이 경로로 숨기지는 않는다.

## 서버/API

기존 인증된 `native/roster60/pvp/*` 경로를 사용한다. 클라이언트는 XP·승자·종료 사유를 제출하지 못한다. 공개 결과의 `xpAwarded`, `xpRequested`, `xpDeferred`, `xpByOwnedId`, `normalXp.units`는 해당 계정 것만 반환한다. 상대의 보유 개체 ID와 지급 계획은 공개하지 않는다.

시험 로스터 프로필은 위 시험 정책 파일을 사용한다. 프로필을 사용하지 않는 환경의 정책 위치는 `data/roster60-normal-xp-policy.json`이며 승인된 운영 정책은 제공하지 않았다. 파일이 없으면 새 일반게임 입장은 `NORMAL_XP_POLICY_PENDING`으로 거절된다. 랭크 입장은 이 정책으로 차단하지 않는다.

추가 스키마는 `20261027_roster60_normal_xp/migration.sql`에 있다. 로컬 시험용으로만 준비했으며 운영 DB에 적용하거나 서비스를 재시작하지 않았다. 적용 전에는 별도 배포 승인과 카탈로그/기존 큐 운영 검토가 필요하다.
