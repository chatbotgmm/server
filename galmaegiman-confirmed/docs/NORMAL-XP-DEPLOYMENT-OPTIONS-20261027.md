# 일반전 XP 정책 미설정 503: 배포 전 선택지

기준은 `manual/home-assembly-20261019@c37c24ecb9399abf0cb438b25412924ffbe921db` 위의 현재 스토리·버그·일반전 XP·마을 통합 소스다. 이 문서는 소스 읽기 검토에 따른 선택지이며 운영 설정·경제·서버·DB·배포를 변경하지 않는다. 실제 이미지 연결과 로컬 APK 검증은 이 정책 결정과 독립적으로 진행할 수 있다.

## 현재 503이 발생하는 이유

`registerRoster60()`는 서버 시작 시 읽은 `ROSTER60_PROFILE`에 따라 아래 파일을 선택한다. 정책 내용은 getter에서 읽지만, 프로필 선택 자체를 바꾸는 것은 XP만 바꾸는 설정이 아니다. 같은 프로필이 로스터와 전투 정책 경로도 함께 선택한다.

| 서버 설정 | 일반전 XP 파일 | 현재 승인 상태 |
| --- | --- | --- |
| `ROSTER60_PROFILE=five-stat-device-test-v1` | `data/test-profiles/five-stat-device-test-v1/normal-xp-policy.json` | 명시적 시험안. `approved:true`, `productionBalanceApproved:false`, `testValues:true` |
| 프로필 미설정 | `data/roster60-normal-xp-policy.json` | 현재 통합 소스에 파일 없음. 승인된 운영 정책을 제공하지 않음 |

따라서 유효한 로스터·전투 정책은 있지만 XP 파일이 없는 환경에서 **새 일반전** `POST /my/api/native/roster60/pvp/join`을 요청하면 `NORMAL_XP_POLICY_PENDING`과 HTTP 503을 반환한다. 검증은 대원 잠금·큐 생성 전에 수행하므로 임의 XP0 전투를 시작하거나 대원을 묶지 않는다. 잘못된 JSON/정책 구조·카탈로그 불일치는 `NORMAL_XP_POLICY_INVALID` 등으로 구분된다. 인증·로스터·전투 정책 오류는 이보다 먼저 발생할 수 있으므로 모든 503을 XP 파일 누락으로 단정하지 않는다.

클라이언트에는 일반게임 성장 보상 준비 중 안내가 있다. 그러나 현재 API에 새 입장 가능 여부를 사전에 알리는 전용 capability와 정상적인 서비스 미개방 상태가 구현돼 있는 것은 아니다. 메뉴에서 일반전을 열 수 있어도 실제 새 입장은 거절될 수 있다. APK에 마을 PNG를 포함하거나 APK를 새로 만드는 것만으로 서버의 XP 정책이 생기지는 않는다.

근거: `src/roster60-routes.ts`의 `normalXpFile/normalXpPolicy`, `src/progression/normal-xp.ts`의 `validateNormalXpPolicy/prepareNormalXpPlayer`, `src/roster60-pvp.ts`의 `join`, `test/normal-xp.integration.test.ts`의 미설정 HTTP 검증.

## 확정과 미확정

사용자가 확정한 것은 정상 승리·정상 패배의 개체 XP 지급, AI와 사람 상대의 같은 결과별 기준, 항복·도주 0이다. 승리와 패배의 수량이 같다는 뜻은 아니다. 랭크 XP·평점·입장 레벨 판정 대상, 기존 모험·스토리 XP와 어둠의 새우Gang은 이 결정으로 바꾸지 않는다.

현재 시험안은 시작 레벨에 가장 가까운 기존 비튜토리얼 duel 조우의 승패 XP를 재사용한다. 패배 XP0 행의 절반·최소 1 보완과 실제 출전 개체별 분배는 초기 제안이다. 운영 수량·분배 승인이 아니다. 무승부·미입력 자동 행동 KO·타임아웃·연결 종료 등은 지급 대상을 확대하지 않고 미정 상태로 기록한다.

상한 초과는 요청량 전체를 적용하지 않은 `CAP_POLICY_PENDING` 감사 기록이며 자동 은행이나 향후 지급 약속이 아니다. 59레벨에서도 지급량이 상한을 넘으면 보류될 수 있다. 따라서 양수 XP 연결 시험과 약 60레벨까지의 전체 성장 완성은 구분한다. 다른 상한 처리나 다른 분배를 선택한다면 정책 문자열만 바꿀 문제가 아니라 별도 구현·회귀 검증이 필요하다.

## 큐·전투를 보존해야 하는 경계

| 대상 | 현재 동작과 배포 시 의미 |
| --- | --- |
| 실제 새 normal 입장 | 정책 누락/미승인 시 잠금 전 503. 같은 요청이 기존 큐·방을 복구하는 경우는 아래 경로를 먼저 사용 |
| XP 계획이 고정된 기존 큐 | 현재 XP 파일을 제거해도 저장한 계획을 사용. 로스터 버전과 전투 정책이 유효하면 사람/30초 AI 매칭을 계속할 수 있음 |
| XP 계획/버전이 없는 이전 큐 | 새 매칭 제외, `NORMAL_XP_POLICY_PENDING`, 취소 가능. 취소 후 유효 정책으로 재입장 |
| 카탈로그 버전이 다른 큐 | 조회 한도 전에 매칭 제외, `NORMAL_XP_CATALOG_CHANGED`, 취소 가능. 다른 유효 큐의 매칭을 막지 않음 |
| 카탈로그 누락/읽기 예외 | 새 normal 매칭 후보를 비움. 고정된 방의 진행·정산과 큐 취소는 별도 복구 경계를 유지 |
| XP 계획이 고정된 기존 방 | 당시 결과별 수량·성장 곡선으로 정확히 한 번 정산. 현재 XP 파일 삭제나 수량 변경으로 소급 바꾸지 않음 |
| XP 계획이 없는 이전 방 | `LEGACY_POLICY_UNCONFIGURED`, 새 XP 소급 지급 없이 기존 종료·대원 해제 허용 |
| 수락 시간 초과/거절 뒤 실제 사람 재대기 | 기존 고정 계획과 원래 대기 시각을 보존. 계획 없는 이전 방에서 온 큐는 미설정 안내·취소가 필요 |
| rank | normal XP 준비·정산을 사용하지 않음. 기존 로스터/전투 정책 등 자체 조건은 여전히 필요 |

`current()`는 큐 lease를 갱신한다. 문제가 있는 큐도 계속 조회하면 자동 만료를 기대할 수 없으므로 취소 경로를 유지해야 한다. XP 정책 파일을 지우는 것은 전체 일반전 중지 스위치가 아니다. 이미 고정된 큐·방의 정상 진행을 막거나 이력을 삭제하는 운영 reset은 이 선택지에 포함하지 않는다.

## 안전한 선택지와 권장안

| 선택지 | 필요한 조건 | 효과·제한 |
| --- | --- | --- |
| **권장: 로컬 아트·APK 검증을 계속하고, 일반전 운영 개방은 정책 합의까지 보류** | 격리된 시험 계정/DB와 명시 시험 프로필로 기존 수치를 시험값으로 표시 | 그림·입력·메뉴 검증을 끝낼 수 있음. 실제 운영 일반전 XP·약 60레벨 완성을 승인한 것으로 보지 않음 |
| 승인된 운영 정책으로 일반전 개방 | 수량·분배·상한/미정 종료의 현재 취급을 명시적으로 결정하고, 실제 운영 카탈로그·전투 정책에 맞춘 정책 및 스키마를 검토·검증 | 정상 승패와 AI 동일 기준을 운영에서 제공. 승인된 설정과 별도 운영 반영 절차가 필요하며 이번 문서는 이를 실행하지 않음 |
| 마을 등 다른 기능을 먼저 배포하고 일반전은 명시적 미개방 | 일반전만을 대상으로 하는 서버 상태와 앱 사전 안내를 별도 설계·구현·검증. 기존 큐 취소·진행 방 복구 경로는 유지 | 경제를 임의 활성화하지 않음. 현재 소스에는 완성된 일반전 전용 개방 스위치가 없으므로 별도 구현·검증이 필요 |
| 승인 전까지 이번 서버 묶음의 운영 배포 자체 보류 | 현재 운영을 그대로 유지하고 로컬 검토 산출물만 전달 | 가장 단순하게 미확정 정책의 운영 적용을 피함. 새 마을 앱이 어느 서버와 호환되는지는 별도 검증 필요 |

사용자가 아직 운영 XP 수치를 결정하지 않은 현재에는 첫 번째 선택지를 권장한다. 실제 운영 반영이 먼저 필요하다면 일반전을 조용히 XP0으로 열거나 503을 정상 개방으로 보고하지 말고, 세 번째 또는 네 번째 선택지를 명시적으로 정해야 한다. 일반전 사전 미개방 기능의 새 구현이나 운영 배포를 이 문서만으로 승인하지 않는다.

기존 `MenuAccess`를 일반전 전용 스위치로 쓰는 선택지는 현재 성립하지 않는다. 해당 서비스는 `enforcementEnabled:false`이고 관리 쓰기는 `MENU_ACCESS_RETIRED` 410이며 normal/rank 전용 기능 ID도 없다.

다음 우회는 권장하지 않는다.

- 시험 파일을 운영 경로로 복사하거나 `productionBalanceApproved` 표시만 바꿔 운영 승인처럼 사용하기. 현재 검증기는 파일 경로와 `profileKind`를 강제로 묶지 않으므로 기술적으로 읽힐 수 있다는 사실이 경제 승인을 뜻하지 않는다.
- `ROSTER60_PROFILE`을 켜서 XP503만 없애기. 로스터·전투 정책도 시험 프로필로 바뀌며 운영 데이터와의 호환을 보장하지 않는다.
- 정책 누락 시 XP0이나 하드코딩한 기본 수량을 지급하도록 완화하기. 정상 패배 XP와 AI 동일 기준의 확정 요구를 충족하지 못하거나 미확정 경제를 활성화한다.
- 진행 중인 방·대원 잠금·원장을 삭제하거나 기존 큐에 새 지급량을 덮어씌우기. 저장된 지급 기준과 중복 방지 경계를 훼손한다.
