# 경험치 정산 연출 준비 — 2026-10-28

현재 상태는 **별도 단계 구현 및 집중 시험 완료**다. 먼저 검증한 편성·마을 패치와 분리한다. 전투·스토리 의뢰·탐험 귀환 결과에 실제 정산 표시를 연결했으며 기존 전투·서버 지급 규칙·버전 코드는 변경하지 않았다.

`NativeXpReceipt`는 실제 정산 응답에서 지급된 값만 읽는다. 스토리 즉시 지급의 `unitXp.units[].startingXp/endingXp/appliedXp`는 누적값과 이번 획득량을 제공한다. 탐험의 `delivery:pending-return`은 아직 지급된 경험치가 아니므로 정상 귀환 시 획득할 보관분으로만 표시한다.

읽기 전용 표시 필드 확장 승인을 받아 optional `xpProgress.before/after`를 지원한다. 각 점은 실제 `level`, `maxLevel`, `totalXp`, `levelStartTotalXp`, `nextLevelTotalXp`를 포함한다. 서버는 기존 성장 계산과 정산에서 이 데이터를 투영한다. 이 필드가 있으면 실제 레벨 구간의 경험치바와 레벨업을 표시하며, 여러 레벨을 넘을 때도 서버가 확인한 전후 레벨만 사용한다. 필드가 없는 이전 정산은 기존 지급 숫자를 그대로 표시한다. 임계치가 없는 유닛의 바는 '이번에 획득한 경험치' 연출로 명시하며 레벨 내 진행률로 표시하지 않는다.

`NativeXpRewards`는 650ms 안에 획득 숫자와 바를 증가시키고 터치 또는 연출 끝내기 버튼으로 즉시 완료한다. 방범대장 레벨업도 실제 `xpProgress`를 우선 사용한다. 옛 방범대장 응답에서는 기존 권위 스냅샷과 정산 스냅샷의 정책이 같고 revision이 정확히 한 단계 증가했으며 누적 경험치 차이가 실제 지급량과 일치할 때만 표시한다. 레벨·성장 임계치·새 기술을 추측하지 않는다.

서버·계정·전투/탐험 ID로 만든 표시 마커를 연출 전에 기기에 저장한다. 같은 기록을 다시 열면 '추가 지급 없음'과 최종 기록 숫자를 표시하며 레벨업 연출은 다시 하지 않는다. 마커가 없는 최초 실행이라도 이미 끝난 과거 정산으로 재접속하면 자동 연출하지 않는다. 현재 화면에서 진행 중인 전투를 관찰했거나 현재 세션에서 새로 만든 정산·의뢰 요청의 성공 응답일 때만 1회 연출한다. 이 모듈은 경험치 지급·초기화 API를 호출하지 않는다. 결과창을 닫을 때에는 기존 공통 대화창의 `visibleDialog` 정리도 보존한다.

검증한 범위:

- 새 프로덕션 소스 2개와 `NativeXpRewardsTest`를 실제 SDK 36, 기존 앱·시험 클래스, 현재 의존성으로 독립 javac 컴파일: 통과.
- 처음 작성한 회귀 시험 6개는 부모의 Robolectric 실행에서 통과했다.
- 이후 실제 전후 레벨 구간·여러 레벨 상승·cap·잘못된 표시 데이터·탐험/의뢰의 안정적인 식별자를 검사하는 시험을 추가해 총 9개가 됐다. 확장 소스와 시험의 독립 javac 컴파일은 통과했다.
- 실제 전투 결과 응답·최초 cold 재접속·의뢰 완료 응답을 연결하는 `NativeXpResultIntegrationTest` 3개도 추가했다. 지급 요청 횟수 유지, Back·확인 버튼의 창 정리, 과거 기록의 레벨업 재연출 차단을 검사한다.
- 최종 집중 실행: `NativeXpRewardsTest` 9개, `NativeXpResultIntegrationTest` 3개 **모두 통과**. 실패·오류·생략 0, Gradle `BUILD SUCCESSFUL` 43초. 실제 화면 캡처와 기기 검증은 하지 않았다.

검토·시험에서 보완한 점:

- 최초 종료된 정산으로 접속한 경우에는 기존 경험치를 새 획득처럼 연출하지 않는다. 새로 만든 정산 요청 또는 현재 진행을 관찰한 전투에서만 1회 연출한다.
- 자동 창은 메인 Handler와 세대 보호를 사용하며 화면을 떠나면 예약을 취소한다. 같은 정산을 재읽어도 새 지급 요청이나 연출을 만들지 않는다.
- 확인·Back·일시정지에서 애니메이션과 창 참조를 해제하고 공통 대화창의 `visibleDialog` 정리를 자기 창의 identity에 한정한다.
- 실제 결과 시험은 정산·자산 콜백이 생성한 다음 메인 작업까지 기존 bounded async await로 기다린다. 대기 전에 팝업을 검사하던 시험 타이밍을 고쳤으며 지급 횟수·중복 방지 검사는 유지했다.

전투 결과에서 정산 모듈의 버튼 생성·`bind`·일시정지 처리와 스토리 의뢰 완료·탐험 귀환 연결을 적용했다. 일반 대전도 공통 전투 렌더러를 상속해 같은 흐름을 사용한다. 새 표시 데이터가 없는 예전 정산의 유닛 레벨업은 복원하지 않는다. 정확한 레벨 경험치바에는 함께 준비한 서버 표시 DTO가 필요하며, 아직 운영 배포하지 않았다. APK·실기기·FPS·운영 배포는 검증하지 않았다.
