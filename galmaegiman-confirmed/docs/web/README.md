# 갈매미맨 공개 홈페이지 · 웹 게임 — 구현 인계

작성 2026-10-19. 브랜치 `claude/web-site-fma5lb`(웹 전용).
- 기준 설계: 「웹게임 설계도 v1」, 「공개 홈페이지 보충 설계 v1」.
- **배포하지 않았다.** 운영 서버·DB는 건드리지 않았다.
- 모든 확인은 격리 시험 서버(127.0.0.1:3999, 임시 SQLite)와 실제 Chromium으로 했다.
- 실제 휴대폰·태블릿 기기에서는 확인하지 않았다(브라우저 창 크기만 바꿔서 찍음).

## 1. 경로

| `/about` | 게임 소개. 대원 수·등급별 수·조합법 수는 저장소 자료(`data/units.json` 등)에서 계산 | 필요 없음 |
| `/world` | 기존 세계관 페이지 그대로. 쿠폰 조각 기능을 보존하려고 새 디자인으로 바꾸지 않음 | 필요 없음 |
| `/characters` | 공개 대원만(히든·최상위 제외, 기존 공개 도감과 같은 정책). 페이지 그리드 + 같은 화면 상세 | 필요 없음 |

| `/login?next=&from=` | 기존 인증(카카오, 카톡 6자리 코드)만 씀 | — |
| `/game` | 웹 게임(해시 화면: `#home` `#dex` `#team` `#play` `#match` `#battle` `#draw` `#craft` `#explore` `#shop` `#account`) | 필요 |

- 예전 메인(`/`) 소개 화면(오늘의 갈매미·랭킹·히든·로그인 칸)은 `/web/landing`에 그대로 남아 있다. 로그인하지 않은 상태로 `/my`에 들어가면 이 화면을 쓴다.

## 2. 파일

- `src/site.ts`: 공개 페이지와 `/login`, `/game` 화면 파일, `/site/*`·`/game/*` 정적 파일.
  - 정적 파일은 정해진 확장자만 내보내고, `..` 경로는 거절한다.
  - `src/app.ts`에서 등록한다.
  - `src/web.ts`에서는 예전 `/` 처리만 지웠다.
- `public/site/site.css`, `site.js`: 공개 페이지 스타일, 작은 화면 메뉴, 로그인 진입·복귀, 캐릭터 페이지 넘김.
- `public/game/index.html`, `game.css`, `game.js`, `screens.js`, `battle.js`, `more.js`: 웹 게임.
  - `game.js`: 틀, 머리줄, 항구 홈, 시트.
  - `screens.js`: 도감·편성·플레이.
  - `battle.js`: 매칭·실시간 방·증강체·전투·상성표.
  - `more.js`: 뽑기(모집)·조합·탐험·상점·계정·출석·미션.
- `public/web/dash.js` 맨 앞: 카카오 로그인에서 돌아왔을 때 원래 목적지로 보내는 짧은 코드(아래 3절).
- `public/site/a/*`: 웹용 그림·글꼴. `scripts/web/build-site-assets.py`가 앱 자산에서 만든다.
  - 원본: `app/android/app/src/main/assets/harbor-v1`, `battle-v1`, `native/*.ttf`.
  - 글꼴은 Jua·고운돋움의 부분 woff2이고, OFL 라이선스 파일을 같이 둔다.
- `data/notices.json`, `data/downloads.json`: 공지·다운로드. 확인된 내용만 넣는다.
- `scripts/web/site-review.mjs`: 검수 캡처와 숫자 검사.
- `scripts/web/realtime-review.mjs`, `net-review.mjs`, `actions-review.mjs`: 실시간 대전, 느린 응답·끊김, 모집·조합·상점·탐험 실행 검수(시험 서버만).
- `test/site.test.ts`: 공개 페이지 단위 테스트.

## 3. 로그인 흐름

1. 「게임 시작」을 누르면 누른 페이지와 스크롤 위치를 sessionStorage에 기억하고 `/game`으로 간다.
2. `/game`이 `/my/api/who`로 로그인을 확인한다.
   - 401이면 `/login?next=/game&from=<원래 페이지>`로 간다.
3. `/login`의 `next`·`from`은 **서버가 허용 경로로 거른다.**
   - 바깥 주소, `//`, `\` 같은 값은 기본값으로 바뀐다(`safeNext`, `safeFrom`, 테스트 있음).
4. 코드로 로그인하면 `next`로 간다. 「돌아가기」를 누르면 원래 페이지와 스크롤로 돌아간다.
5. 카카오는 서버가 항상 `/my`로 돌려보낸다. 그래서 `/login`에서 목적지를 기억해 두고, `/my` 화면(dash.js)이 10분 안에 이어 보낸다.
   - 취소하면 원래 공개 페이지로 돌아간다.
   - 실패하거나 계정 연결이 필요하면 `/login`으로 돌아간다.
6. 로그인 상태만으로는 게임으로 보내지 않는다. 공개 머리줄의 「로그인」이 「내 계정」으로 바뀔 뿐이다.

## 4. 웹 게임이 쓰는 서버 API(모두 기존, 새 규칙 없음)

- 항구 홈·편성
  - `GET /my/api/who`
  - `GET /my/api/native/state`
  - `GET /my/api/duel-key`: 대원 그림 열쇠
  - `POST /my/api/native/team`: 스토리 편성
  - `POST /my/api/battle-team`: 대전 편성. 앱과 같이 두 가지 편성을 나눈다.
  - `GET /my/api/daily`
  - `POST /my/api/logout`
- 도감: `GET /my/api/native/catalog`
- 뽑기(모집): `GET /my/api/draw`, `POST /my/api/draw`, `POST /my/api/claim`(지원서 받기)
- 조합: `GET /my/api/craft`, `POST /my/api/craft`, `POST /my/api/mix`(직접 섞기)
- 탐험: `POST /my/api/party`, `POST /my/api/expedition/start`, `POST /my/api/expedition/claim`, 바로 귀환은 `POST /my/api/shop {item:'skip'}`
- 상점: `POST /my/api/shop`(지원서 묶음), `POST /my/api/items/buy`(전투 아이템), 가격·종류는 `GET /my/api/me`의 `prices`·`itemDefs`
- 계정: `POST /my/api/kakao/unlink`, `POST /my/api/coupon`, `POST /my/api/account/delete`(서버가 「탈퇴」 입력을 요구), 카카오 연결은 기존 `/my/kakao`
- 출석·미션: `GET /my/api/daily`, `POST /my/api/attend`
- 스토리·연습 전투
  - `POST /my/api/native/battle/start`
  - `GET /my/api/native/battle/current`
  - `POST /my/api/native/battle/turn`: 행동·증강체·다시 뽑기·도망
- 일반전·랭크전
  - `POST /my/api/pvp/queue/attempt`, `/my/api/pvp/queue/join`, `/my/api/pvp/queue/cancel`
  - `GET /my/api/pvp/queue/current`
  - `GET /my/api/pvp/room/current`
  - `POST /my/api/pvp/room/command`: 수락·준비·행동·증강체·다시 뽑기
  - `POST /my/api/pvp/room/surrender`
- 그림
  - `/duel/sprites/*?k=`: 대원
  - `/duel/icons/*.png`: 증강체·아이템
  - `/thumbs/*.jpg`: 카드

- 30초 표시
  - 서버가 내 입력을 받고 있고 내 제출이 아직 접수되지 않았을 때만 보인다.
    - 스토리: 증강체 단계의 `chooseDeadline`
    - 실시간: `room.deadline`
  - 남은 시간 = 마감 − (응답의 `serverNow` + 받은 뒤 흐른 시간).
  - 화면 이동·다시 그리기·창 크기 변경으로 다시 세지 않는다.
  - 0초가 되면 입력을 잠그고 서버 결과를 다시 받는다. 화면이 자동으로 행동하지 않는다.
- 실시간 상태 새로 받기는 1.5~3초 간격이다.
  - 서버 상태(단계·revision)가 그대로면 화면을 다시 그리지 않는다. 고르던 슬롯·패널이 지워지지 않게 하려는 것이다.
- 제출 중 연결이 끊긴 경우
  - 같은 행동을 자동으로 다시 보내지 않는다. 상태를 다시 받아 접수 여부를 확인한다.
  - 사용자가 다시 누르면 같은 요청 번호로 보낸다. 서버가 중복 접수를 막는다.

웹에 전혀 없는 것:
- 스토리 단계 고르기, 스토리 대사(before/after)
- 전투 연출: 기술 애니메이션, 피해 숫자

새 디자인을 적용하지 않은 것:
- 세계관 페이지: 기존 디자인 그대로(쿠폰 조각 보존).
- 「대원 모집」 메뉴 이름: 제안 상태라 쓰지 않았다. 하단 메뉴는 설계대로 「뽑기」다.

### 검토에서 찾아 고친 것
- 시트·뒤로 버튼이 처음부터 보이던 문제.
  - 원인: CSS `display`가 `hidden` 속성을 덮었다.
  - 고침: 전체에 `[hidden]{display:none!important}`를 넣었다.
- 안쪽 화면 머리줄이 얇은 흰 띠로 보이던 문제.
  - 원인: HP 막대 클래스 `.bar`가 머리줄 `.bar`와 이름이 같았다.
  - 고침: HP 막대 이름을 `.hpbar`로 바꿨다.
- 빈 기술 칸이 두 칸 너비로 늘어나던 문제.
  - 원인: 그리드 빈 목록용 `.empty`와 이름이 같았다.
  - 고침: 빈 기술 칸 이름을 `.none`으로 바꿨다.
- 전투·증강체 화면에 머리줄·하단 메뉴가 같이 보이던 문제.
  - 원인: 제목 함수가 화면 모드를 다시 덮었다.
  - 고침: 호출 순서를 바꿨다.
- 작은 세로 화면(360×640)의 증강체 문제.
  - 설명 글이 세로로 한 글자씩 꺾였다. 후보 카드도 겹쳤다.
- 작은 세로 화면에서 이름이 글자 중간에서 끊기던 문제(「검토대/장」).
  - 고침: 한국어 단어 단위 줄바꿈(keep-all)을 넣었다.
- 장면 테두리가 검토용 틀처럼 보이던 것을 지웠다.
- 가로·세로 폰에서 성장 카드가 대원 방패를 가리던 위치를 옮겼다.
- 로그인 칸이 360px 폭에서 화면 밖으로 넘치던 문제.
  - 원인: 그리드 최소 폭.
- 가로 폰에서 터치 영역이 48px보다 작던 것.
  - 재화 알약과 상성표 속성 버튼이 44px였다. 48px로 키웠다.
- 가로 폰 도감이 한 페이지에 1줄만 보이던 것(37페이지). 2줄로 고쳤다.
- 실시간 준비 화면 문제.
  - 일반전 후보 ID가 개체 키(o…)라서 그림이 404였다.
  - 상태를 새로 받을 때마다 화면을 다시 그려서 고르던 슬롯이 지워질 수 있었다. 서버 상태가 바뀔 때만 다시 그리게 했다.
- 대전 편성(battle-team)을 따로 정하지 않으면 랭크 탐색이 서버 오류로 멈췄다.
  - 앱처럼 「스토리·연습 / 대전」 두 편성을 나누고, 오류 화면에 「대전 편성」 링크를 넣었다.
- 연결이 끊긴 뒤 「확인하는 중」 안내가 계속 남던 문제.
  - 이제 다시 받은 상태와 비교해 접수 여부를 알려 준다.
- 전투 화면에 다시 들어오면 이미 끝난 전투의 예전 상태가 보이던 문제.
  - 이제 들어올 때마다 서버 상태로 다시 맞춘다.
- 360×640에서 교체 목록이 화면 밖으로 넘치던 문제. 세로 화면에서는 대원 3명을 한 줄에 놓는다.
- 360×640에서 결과 화면 버튼이 밀려나던 문제. 결과 내용만 패널 안에서 스크롤되게 했다.
- 편성 후보 카드가 낮은 칸에서 이름이 잘리던 문제(가로 폰). 그림이 칸에 맞게 줄어들게 했다.
- 검사 도구도 고쳤다: 카드·버튼 자체의 잘림도 검사하게 했다.

## 10. 배포 전에 확인할 것

- `/`가 공개 홈페이지로 바뀐다.
  - 예전에는 로그인하면 `/`에서 대시보드가 보였다. 이제 대시보드는 `/my`에서만 보인다.
  - 공개 머리줄 「내 계정」과 웹 게임 계정 시트에서 기존 화면으로 갈 수 있다.
- 공지·다운로드·공식 문의·이용약관은 실제 내용과 링크를 확인한 뒤 `data/*.json`과 바닥 링크에 넣는다.
  - 지금 바닥에 있는 링크는 이미 있던 카카오톡 채널·개인정보처리방침·계정 삭제 안내·확률 페이지뿐이다.
  - 이용약관 링크는 없다(확인된 문서가 없어서).
- 운영 배포는 별도 승인을 받은 뒤에만 한다.
