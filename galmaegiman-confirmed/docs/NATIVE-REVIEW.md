# Android 전체 화면 네이티브 전환 검토 (2026-10-13)

로그인, 로비, 챕터·스테이지 선택, 이야기 대화, 수비대·성장, 도감, 뽑기,
조합, 상점, 아이템, 탐험, 출석·미션, 대전, 자유 연습, 속성 상성, 설정,
안내와 전투를 Android Views/Canvas로 전환했다. 웹 게임을 APK에 넣지 않는다.
원래 캐릭터 33종 앞·뒤 이미지는 수정하지 않았다. 전체 디자인 통일은 후속 범위다.

## 확인 및 수정

- 가로 폰 880×360, 태블릿 1280×720에서 네이티브 화면 24개씩 캡처하고 검토했다.
- 폰 로그인 입력 영역을 좌우로 배치하고 키보드 표시 및 완료 입력을 처리했다.
- 전투 오른쪽 메뉴 뒤 큰 패널을 제거하고 재질 버튼에 큰 행동 이름만 남겼다.
- 이미지 알파 상태 공유로 캐릭터가 흐려지던 문제와 View 측정 지연을 수정했다.
- 버튼 원본 비율을 기준으로 배치하며 태블릿의 남은 높이는 전투기록이 사용한다.
- 기술 카드는 공격·유틸 색을 구분하고 효과·사용 불가 이유를 표시한다.
- 기존 웹 기술 카드의 이전 `!important` 스타일이 새 배경을 지우는 충돌을 수정하고 재검토했다.
- 이미지 요청 중복을 합치고 API와 이미지 작업 스레드를 분리했다.
- 원본 이미지의 투명 여백 좌표만 미리 계산해 저장했다. 원본 이미지를 편집하지 않았다.
- 연습은 보유 목록과 별도로 33종, 양측 수비대, 레벨, 승진을 선택할 수 있다.
- 이야기 대화는 인물 이름·초상화와 고정된 다음 버튼을 사용한다.

## 검증 범위

Android 35 소프트웨어 에뮬레이터에서 로그인과 화면 이동, 증강체 선택,
전투 메뉴·기술·교체·아이템·연습 종료 테스트를 폰/태블릿 각각 통과했다.
전투 행동 버튼 4개의 높이가 최소 48dp이며 큰 이름만 표시되는 것을 검증한다.
캡처는 실제 앱 루트 View를 그린 것으로, 느린 소프트웨어 에뮬레이터의
시스템 대화상자는 포함하지 않는다. 실기기 성능 및 장시간 플레이 측정은 포함하지 않는다.

서버 테스트 129개 통과: 연속 공격, 중복 유틸 방지, 계정·수비대 검증,
동시 요청 및 전투 revision, 잘못된 행동의 상태 보존, 아이템·보상 원자성,
레벨업 체력 회복, 네이티브 OAuth, 33종 연습 선택을 확인했다.
스토리는 기존 스테이지 ID를 보존하며 6개 챕터·70개 전투로 확장했다.
시뮬레이션 100회에서 2·3장 진입을 위해 이전 보스를 반복해 경험치를
얻을 필요는 없었다. 보스 자체의 재도전 가능성은 유지한다.

기존 웹 화면은 실제 폰트를 사용해 915×412, 1280×720을 포함한
6개 크기에서 로그인·로비·전투의 가로 넘침과 주요 영역 겹침을 검사했다.
보유 목록 등 긴 메뉴는 의도적으로 세로 스크롤한다.

## 배포

운영 API는 https://gmm.dpdns.org 이며 빌드 시 nativeServer를 지정하지 않는다.
첫 전환 APK는 org.dpdns.gmm.native, 버전 2.0.0-native (63)이다.
기존 웹 APK와 서명이 달라 별도 설치하는 시험판으로 공개한다.
기존 APK 및 apk 브랜치 이력은 보존한다. 빌드·게시 방법은 app/README.md 참고.

## 프레임·탐험 편성 보완 (2.0.1-native)

대화창의 모서리 장식까지 포함하는 90px 영역을 같은 비율로 표시한다.
네이티브 대화·전투 상태·전투기록은 공통 9분할 렌더러를 사용하고,
모서리는 균일한 배율로 유지한다. 전체 그림을 가로·세로로 따로 늘리지 않는다.
기존 배경은 CENTER_CROP, 캐릭터는 FIT_CENTER/비율 유지 표시를 그대로 사용한다.

탐험 출발 시 실제 출발 편성을 중복 수량까지 저장하고 보상 수령 뒤에도 유지한다.
이전 버전에서 지워진 진행 중 탐험의 편성은 귀환 보상 수령 시 복원한다.
이미 보상을 받은 탐험은 웹·네이티브의 '최근 탐험대 불러오기'로 복원할 수 있다.
보유 수량이 부족하면 서버의 기존 검증을 적용하며 임의로 다른 편성으로 바꾸지 않는다.

태블릿 재검토에서 원본 종이 질감의 색 차이로 나타나는 분할 경계도 발견했다.
상태창·전투기록은 새로 생성한 투명 테두리 coral-frame.png와 코드로 그리는
단일 종이 배경을 분리했다. 테두리의 가운데는 투명하며 배경 질감을 분할하지 않는다.
새 프레임을 적용한 뒤 폰·태블릿의 대화·전투 화면을 별도로 다시 실행·캡처했다.

## 기능 오류·기존 화면 복원 (2.0.2-native)

- 진행 중 전투가 있을 때 로비의 회복·성장·편성 변경을 거부해 치료약 손실을 막는다.
  같은 계정의 웹 진행 저장과 웹 회복도 네이티브 스토리 전투 중에는 거부한다.
- 탐험 보호는 조합·판매 보호와 구분한다. 보호된 대기 갈매미도 선택할 수 있다.
  편성 저장 버튼을 제공하며 뒤로 이동할 때 변경한 편성을 서버에 저장한다.
- 화면 요청 세대(epoch)를 검사하고 이미지 열쇠를 재사용해 늦은 응답의 화면 덮어쓰기를 막는다.
- 승진 표창은 저장된 개체 번호·단계·이전 표창을 씨앗으로 무작위 후보를 재현한다.
  서로 다른 개체는 다른 후보를 받을 수 있고, 재접속으로 후보를 다시 뽑을 수 없다.
- 첫 화면은 웹과 같은 t2 원본 이미지와 1961×802 배치 규칙을 사용한다.
  로그인은 같은 화면 위의 작은 입력창, 성공 뒤에는 '게임 시작' 버튼으로 로비에 진입한다.
- 스토리는 장면 배경과 좌우 인물을 유지하며 해설 중에도 인물을 숨기지 않는다.
  다음 버튼·페이지 번호를 대화창 안에 배치하고 본문에 Gowun Dodum 원본 글꼴을 사용한다.
  캐릭터 그림은 편집하지 않고, 비발화 인물의 밝기만 낮춘다(불투명도는 유지).

서버 테스트 131개가 통과했다. 회복·성장·편성의 전투 중 변경 거부,
아이템 보존, 웹 저장 충돌 방지, 승진 후보의 안정성과 개체별 변화를 확인한다.
Android 검토에는 첫 화면 로그인 전·후, 입력창, 화면 요청 취소,
보호된 갈매미 탐험 선택·뒤로 이동 후 저장과 이야기 대화 진행을 포함한다.

## 이미지 포함 · 기존 로비·팝업 복원

2026-10-13 사용자 요청에 따라 요청사항을 모은 뒤 승인받고 빌드·배포한다.
사용자가 같은 날 빌드 및 배포를 승인했다. 검토용 APK로 화면을 확인한 뒤
운영 서버 주소를 사용하는 최종 APK를 만든다.

- 로비의 12버튼 격자를 제거하고 기존 웹 로비의 방 3개 레이어,
  하단 탐험·뽑기·수비대·조합·상점, 출석 이미지, 큰 플레이 이미지를 사용한다.
  플레이에서 스토리·대전·연습을 고르고 프로필에서 추가 메뉴를 연다.
  검토에서 첫 진입 시 검은 배경이 나타나던 점을 찾아 첫 화면에서 로비 이미지를
  미리 읽고, 준비 전에도 기본 배경을 표시하도록 보완했다.
- 확인·종료·선택·입력 창에 공통 GameDialog를 적용한다.
  Android 선택 동작을 유지하며 기존 종이 프레임·게임 글꼴·따뜻한 버튼을 적용한다.
- 고정 이미지 358개(약 35.86MiB)를 Gradle Sync 작업으로 APK에 포함한다.
  public/battle의 원본 캐릭터·배경·아이콘과 public/thumbs의 기존 미리보기를 읽으며
  원본 수정이나 저장소에 같은 이미지 중복 복사는 하지 않는다.
- 이미지 순서는 메모리 → APK 원본 → 기기 파일 → 서버이다.
  도감·조합 목록의 /images/*.png는 같은 기존 그림의 480px 미리보기를 사용한다.
  APK에 없는 추가 이미지만 다운로드하고 완전히 디코딩된 파일을 원자적으로 저장한다.
  서버 추가 이미지의 기기 캐시는 7일 뒤 갱신하며 연결 실패 시 기존 파일을 사용한다.
  캐시는 최대 40MiB, 다운로드는 파일당 최대 12MiB로 제한한다.
  같은 이미지의 중복 요청을 합치고 전투·이야기·로비 이미지 작업을 우선 처리한다.
- 검토 APK에 원본 358개가 포함되고 HTML이 포함되지 않는 것을 확인했다.
  APK 크기는 약 49.64MiB다. NativeArtTest의 열쇠 없는 로컬 이미지 읽기와
  앱 재생성 후 파일 재사용이 통과했다.
  폰 전체 화면·전투·탐험 편성 저장·화면 요청 취소, 로비·팝업 검증이 통과했다.
  로비의 터치 영역은 최소 48dp이며 화면 밖으로 나가거나 서로 겹치지 않는다.
  확인·플레이 팝업은 실제 Dialog Window를 따로 캡처해 검토했다.

최종 검토에서 폰 880×360과 태블릿 1280×720의 첫 화면·로그인·로비·대화·전투,
선택 메뉴와 확인 창을 직접 확인했다. 태블릿 전체 화면·전투·대화·로비·팝업
테스트 3개도 통과했다. 원본 도감 이미지 모두에 APK 미리보기가 있는 것을 확인했다.
기존 웹 UI 변경은 없으며, 실제 글꼴을 사용한 915×412·1280×720을 포함한
6개 크기의 화면 넘침·상태 칸 겹침 검사 결과는 0이었다.
검증은 Android 35 소프트웨어 에뮬레이터 기준이며 실기기 성능 측정은 포함하지 않는다.

APK에 포함한 고정 그림 교체는 앱 업데이트로 반영한다. APK 용량이 늘어나는 대신
해당 이미지의 최초 다운로드와 재실행 다운로드를 없앤다. 계정·전투·보상 데이터는
계속 서버에서 확인하며 이미지 캐시에 저장하지 않는다.
