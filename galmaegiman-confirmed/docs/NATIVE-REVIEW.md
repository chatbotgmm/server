# Android 전체 화면 네이티브 전환 검토 (2026-10-13)

로그인, 로비, 챕터·스테이지 선택, 이야기 대화, 수비대·성장, 도감, 뽑기,
조합, 상점, 아이템, 탐험, 출석·미션, 대전, 자유 연습, 속성 상성, 설정,
안내와 전투를 Android Views/Canvas로 전환했다. 웹 게임을 APK에 넣지 않는다.
원래 캐릭터 33종 앞·뒤 이미지는 수정하지 않았다. 전체 디자인 통일은 후속 범위다.

## 확인 및 수정

- 가로 폰 880×360, 태블릿 1280×720에서 네이티브 화면 24개씩 캡처하고 검토했다.
- 폰 로그인 입력 영역을 좌우로 배치하고 키보드 표시 및 완료 입력을 처리했다.
- 전투 오른쪽 메뉴 뒤 큰 패널을 제거하고 재질 버튼에 큰 행동 이름만 남겼다.
- 이미지 알파 상태 공유로 캐릭터가 흐려지던 문제와 View 측정 지연을 수정했다.
- 버튼 원본 비율을 기준으로 배치하며 태블릿의 남은 높이는 전투기록이 사용한다.
- 기술 카드는 공격·유틸 색을 구분하고 효과·사용 불가 이유를 표시한다.
- 기존 웹 기술 카드의 이전 `!important` 스타일이 새 배경을 지우는 충돌을 수정하고 재검토했다.
- 이미지 요청 중복을 합치고 API와 이미지 작업 스레드를 분리했다.
- 원본 이미지의 투명 여백 좌표만 미리 계산해 저장했다. 원본 이미지를 편집하지 않았다.
- 연습은 보유 목록과 별도로 33종, 양측 수비대, 레벨, 승진을 선택할 수 있다.
- 이야기 대화는 인물 이름·초상화와 고정된 다음 버튼을 사용한다.

## 검증 범위

Android 35 소프트웨어 에뮬레이터에서 로그인과 화면 이동, 증강체 선택,
전투 메뉴·기술·교체·아이템·연습 종료 테스트를 폰/태블릿 각각 통과했다.
전투 행동 버튼 4개의 높이가 최소 48dp이며 큰 이름만 표시되는 것을 검증한다.
캡처는 실제 앱 루트 View를 그린 것으로, 느린 소프트웨어 에뮬레이터의
시스템 대화상자는 포함하지 않는다. 실기기 성능 및 장시간 플레이 측정은 포함하지 않는다.

서버 테스트 129개 통과: 연속 공격, 중복 유틸 방지, 계정·수비대 검증,
동시 요청 및 전투 revision, 잘못된 행동의 상태 보존, 아이템·보상 원자성,
레벨업 체력 회복, 네이티브 OAuth, 33종 연습 선택을 확인했다.
스토리는 기존 스테이지 ID를 보존하며 6개 챕터·70개 전투로 확장했다.
시뮬레이션 100회에서 2·3장 진입을 위해 이전 보스를 반복해 경험치를
얻을 필요는 없었다. 보스 자체의 재도전 가능성은 유지한다.

기존 웹 화면은 실제 폰트를 사용해 915×412, 1280×720을 포함한
6개 크기에서 로그인·로비·전투의 가로 넘침과 주요 영역 겹침을 검사했다.
보유 목록 등 긴 메뉴는 의도적으로 세로 스크롤한다.

## 배포

운영 API는 https://gmm.dpdns.org 이며 빌드 시 nativeServer를 지정하지 않는다.
첫 전환 APK는 org.dpdns.gmm.native, 버전 2.0.0-native (63)이다.
기존 웹 APK와 서명이 달라 별도 설치하는 시험판으로 공개한다.
기존 APK 및 apk 브랜치 이력은 보존한다. 빌드·게시 방법은 app/README.md 참고.

## 프레임·탐험 편성 보완 (2.0.1-native)

대화창의 모서리 장식까지 포함하는 90px 영역을 같은 비율로 표시한다.
네이티브 대화·전투 상태·전투기록은 공통 9분할 렌더러를 사용하고,
모서리는 균일한 배율로 유지한다. 전체 그림을 가로·세로로 따로 늘리지 않는다.
기존 배경은 CENTER_CROP, 캐릭터는 FIT_CENTER/비율 유지 표시를 그대로 사용한다.

탐험 출발 시 실제 출발 편성을 중복 수량까지 저장하고 보상 수령 뒤에도 유지한다.
이전 버전에서 지워진 진행 중 탐험의 편성은 귀환 보상 수령 시 복원한다.
이미 보상을 받은 탐험은 웹·네이티브의 '최근 탐험대 불러오기'로 복원할 수 있다.
보유 수량이 부족하면 서버의 기존 검증을 적용하며 임의로 다른 편성으로 바꾸지 않는다.

태블릿 재검토에서 원본 종이 질감의 색 차이로 나타나는 분할 경계도 발견했다.
상태창·전투기록은 새로 생성한 투명 테두리 coral-frame.png와 코드로 그리는
단일 종이 배경을 분리했다. 테두리의 가운데는 투명하며 배경 질감을 분할하지 않는다.
새 프레임을 적용한 뒤 폰·태블릿의 대화·전투 화면을 별도로 다시 실행·캡처했다.
