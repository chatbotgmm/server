# 모집 후보 캐러셀 · 불합격 환급 UI

기준: `085f204b13429889c631994961433a0a1f0ffb25`. 긴급 01/02 변경 파일과 별개인 후속 07 UI 패치다. 서버 후속 `07-recruit-server-085f204b.patch`를 함께 검토해야 환급 기능이 활성화된다. 운영 배포·APK 생성·실기기 성능 검증은 수행하지 않았다.

## 동작

- 조합 화면의 `CraftResultCarousel`을 재사용한다. 기본 조합 동작은 유지하고 모집에서만 카드 크기와 양끝 중앙 여백을 설정한다. 관성 이동이 멈추면 가장 가까운 카드로 정렬하며 가운데는 크게, 옆은 작게 표시한다.
- 옆 카드의 터치는 가운데로 선택하는 동작이다. 옆 카드의 새로고침과 불합격 버튼은 비활성이다. 새로고침과 불합격은 현재 선택 카드에서 실행되며 진행 중인 드래그/빠른 관성 이동에서는 제출되지 않는다. 빠른 이동 중 첫 터치는 멈추기만 하고 다음 터치부터 선택된다.
- 새로고침은 48dp 영역 안의 `↻` 아이콘이다. 비용은 카드 아래 `↻ N장`, 상단의 지원서 잔액/새로고침 비용, 접근성 설명으로 유지한다. `미수령` 상태 문구는 표시하지 않는다.
- 하단 가운데 `전부 합격`은 남은 후보 ID와 revision만 한 번의 `claim-all` 요청으로 보낸다. 한 후보만 남아도 개별 합격 API를 사용하지 않는다.
- 서버가 현재 보유 종족·미처리·환급 가능으로 명시한 후보에만 `불합격 · 지원서 1장 환급`을 표시한다. 기존 보유 유닛을 처분하는 요청은 없다. 무료 생성/과거 차감 증명 없는 후보는 이유를 표시하며 합격은 가능하다.
- 응답의 `pendingSessions`를 완전한 현재 목록으로 적용하고 `credits`를 카드 요약 및 기존 헤더에 함께 갱신한다. 성공 뒤 별도 GET을 추가하지 않는다. 이전 영수증 재전달도 서버가 현재 목록/잔액을 함께 반환해야 한다.

## 확정과 연출

계정·서버별 키에 요청 전체를 먼저 저장하고 동일 requestId로 재확인한다. UI는 서버 결과를 받은 후만 후보 제거와 잔액을 반영한다. reject는 request/session/status와 환급 1장, 지급 개체 0개, 해당 sessionIds 및 receipt의 replayed 값을 검사한다. 불완전한 영수증은 결과 불확실로 남겨 같은 요청을 재확인한다.

지금 화면에서 처음 보낸 reject의 첫 확정 성공이고 `replayed=false`일 때만 연출한다. 연결 실패 후 재시도, 재접속, 계정/화면 전환, 저장 결과 재열기, 영수증 재전달에는 파쇄 연출을 재생하지 않는다. 계정별 sessionId 표시 기록도 저장한다.

파쇄는 이미 표시하던 카드 View를 짧게 8조각으로 그리는 기존 `RecruitCardTransition`을 사용한다. bitmap 캡처나 프레임별 bitmap 생성/디코드가 없다. 서버 성공 뒤 400ms 파쇄와 200ms `지원서 +1` 표시를 하고, 650ms에 정리한다. 터치로 즉시 끝낼 수 있다. 종료/화면 이탈 때 원래 이미지 바인딩도 지워 늦은 콜백이 남지 않게 한다. 동작 줄이기 설정이면 파쇄 없이 확정 결과만 표시한다.

## 검증 범위

최종 JUnit XML과 Gradle 로그는 함께 전달한다. 신규 계약 시험은 실제 MotionEvent/native scroller, 중앙 스냅, 옆 카드 비활성/48dp 중앙 터치, 중복 제출, 잘못된 영수증, 불확실 재시도, 계정·epoch 변경, 무료/과거 후보, authoritative 빈 목록, 파쇄 시 기존 View 재사용과 이미지 바인딩 정리를 검사한다. 기존 모집/관성/새로고침/조합 워크벤치 회귀를 함께 실행한다.

640×320, 915×412, 1280×720 및 글자 1.0/1.3배의 실제 Android View 캡처를 생성한다. 사용자의 원래 첨부 스크린샷 픽셀은 이 환경에서 열지 못했으므로 정밀 재현을 주장하지 않는다. 캡처에는 저장소의 기존 roster 정면 원화를 사용했고 임시 도형으로 아트를 대신하지 않았다. 전체 `bundleGameArt`/APK 패키징, 설치 APK106의 실제 소스/자산, 실기기 프레임·터치·메모리 검증은 별도로 필요하다.

## 07r 작은 화면 새로고침 보완

640×320·글자1.3배에서 48dp 불투명 배경이 중앙 그림을 가렸다. 캐릭터 크기는 유지하고, 기존 버튼 상태 배경을 10dp씩 inset해 시각 배경을 28dp로 줄였다. 투명한 전체 터치 영역은48dp이고 아이콘은 글자 배율에 따라 과도하게 커지지 않는24dp다. 비용·중앙 전용 액션·거래 규칙은 동일하다. 시험은 실제 Button 렌더의 alpha 경계를 측정해 시각 영역24~28dp·가운데 정렬·투명 모서리를 검사하며, 터치 영역48dp와 기존 관성/거래 시험도 유지한다. 최종 시험 결과/캡처는 별도07r 산출물을 참조한다.
