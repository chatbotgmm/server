### 개발 환경에서 실행

기존 서버의 인증 설정과 60종 시험 로스터에 더해 `ROSTER60_STORY_PROFILE=story-device-test-v1`를 명시해야 새 API가 열린다. 기존 로스터 시험 프로필은 `ROSTER60_PROFILE=five-stat-device-test-v1`다. 새 플래그가 없으면 스토리 API는 `STORY_PROFILE_PENDING`을 반환하며 초안 화면으로 대신 진행시키지 않는다. 이 문서는 운영 플래그 변경이나 배포 승인이 아니다.

새 API는 `/my/api/native/roster60/story/` 아래 `state`, `open`, `advance`, `accept`, `close`, `battle/create`, `adventure/create`, `materials`다. 계정 인증과 기존 guard, no-store 응답, 엄격한 요청 스키마를 재사용한다. 기존 `battle/action`, `battle/settle`, `adventure/read`, `adventure/return`이 실제 전투 및 모험 귀환을 처리한다. 클라이언트는 승리·조각·잔액·완료 목록을 제출할 수 없다.

의존 설치와 Prisma client 생성 후 저장소 앱 루트에서 `node scripts/test-story-mode.mjs`를 실행하면 매번 새 임시 DB를 만들고 스토리 및 관련 기존 경로 시험을 실행한다. 이 스크립트는 호출자의 `DATABASE_URL`을 사용하지 않는다. 스키마 파일과 마이그레이션 SQL은 검토 산출물이며 운영 적용은 수행하지 않았다.

직접 실행한 기존 경로 회귀 시험은 별도 임시 DB(`/tmp/galmaegiman-tests-igifH8/test.db`)에서 6개 파일·46개가 통과했다. 대상은 `roster60-battle`, `roster60-adventure`, `roster60-party-actions`, `roster60-observed-defense`, `roster60-rebirth-transaction`, `roster60-play-modes`의 통합 시험이다. 실제 플레이어 DB를 사용하지 않았다.

마이그레이션은 기준 커밋의 Prisma 스키마로 새 임시 SQLite를 만든 뒤 새 SQL 파일만 적용해 리허설했다. `PRAGMA integrity_check=ok`, `foreign_key_check=[]`, 새 Story 표 세 개 확인, 최종 Prisma 스키마와 `migrate diff` 차이 없음으로 통과했다. 운영 DB에는 적용하지 않았다.
