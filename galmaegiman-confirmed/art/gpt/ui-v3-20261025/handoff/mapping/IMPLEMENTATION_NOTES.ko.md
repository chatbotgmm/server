# 갈매미맨 방범대 v3 화면 구현 연결 안내

최종 시안집의 **36개 화면 ID와 50개 표시 상태**를 실제 앱의 컴포넌트·데이터·이벤트에 연결하기 위한 개발 인계 자료입니다. 네이티브 구현이나 서버 적용을 완료했다는 문서가 아닙니다. 전체 화면 PNG는 비교·검수 자료로만 사용하고, 앱 화면 자체를 통이미지로 붙이지 않습니다.

## 기준 파일과 사용 순서

1. `screen-state-bindings.json`의 `screens`에서 화면 ID를 찾습니다. `visible_state_variants`의 PDF 페이지와 PNG SHA256이 최종 v3 시안집과 연결됩니다.
2. `layout_source`가 가리키는 렌더러에서 배치·간격을 확인합니다. `component_bindings`의 의미 단위로 이미지, 텍스트, 목록, 버튼, 제스처를 별도 구현합니다.
3. `data_inputs`는 필요한 UI 어댑터 입력입니다. **실제 API나 DB 필드가 이미 존재한다는 뜻이 아닙니다.** 서버 응답·로컬 상태 모델에 맞춰 연결하고, 표시용 샘플 숫자를 운영 기본값으로 복사하지 않습니다.
4. `actions`의 의도·가드·목적지와 `routes`의 경로 ID를 연결합니다. `CALLER`는 원래 호출 화면과 모드·선택·진행 상태를 복원하는 문맥이며, 메인으로 무조건 이동한다는 뜻이 아닙니다.
5. `asset_references`는 안정적인 **인계용 논리 키**입니다. Android 리소스 ID는 별도 자산 인벤토리에 맞춰 연결합니다. 원본 경로는 `outputs/ui-mockups-20261025` 기준이며, `../../`는 워크스페이스 루트입니다. 이 폴더는 자산을 복제하지 않습니다.

## 원래 게임 느낌 유지

- 남색 `#193047`, 크림 `#F5E2B5`, 실제 Noto Sans KR을 사용합니다. 기존 질감 버튼을 9-slice로 배치하고 글자는 네이티브로 올립니다. 탭, 상태 표시, 실행 버튼을 같은 모양으로 취급하지 않습니다.
- 작은 슬롯은 원본 캐릭터/얼굴을 크게 보여 줍니다. 전체 등록증은 도감·상세·모집 결과와 조합의 큰 탐색 카드에 남깁니다. 미니의 얼굴 확대는 UI 표시용 크롭일 뿐, 전투에서의 원래 몸 크기를 바꾸는 규칙이 아닙니다.
- 메인은 캐릭터 왼쪽, 플레이 오른쪽 아래, 메뉴·작은 우편·설정 중심입니다. 새 대시보드나 큰 공지 패널을 덧붙이지 않습니다.
- 전투는 **사용자가 선택한 B 항구 배경**입니다. A는 비교 이력입니다. 기존 전장, 캐릭터 크기·위치, 캐릭터별 HP/MP, 오른쪽 2×3 명령 패널을 유지합니다.

## 핵심 화면의 동작 계약

### S05 전투 편성

출전 1명과 후보 5명의 원본 캐릭터를 식별 가능하게 표시합니다. 편성 역할인 `출전/후보`와 현재 선택 상태는 별개입니다. 보유 목록은 페이지 또는 좌우 탐색으로 전체 대원에 접근할 수 있어야 합니다.

주행동은 호출 목적에 따라 바뀝니다. 메인 관리에서는 **편성 저장**, 스토리에서는 **편성 확정 · 전투 시작**, 대전에서는 **매칭 시작**입니다. 모드 선택 기능은 S28에 남습니다. 관리 저장 뒤 S28로 자동 이동하는 R073은 미확정 제안이므로 실행하지 않습니다. S05에서 대전 매칭으로 이어지는 구현 경로는 기존 S28의 일반·랭크 문맥을 보존하도록 연결 검토가 필요합니다. `비우기`는 확인 후 초안을 변경하고 저장과 구분합니다. 빈 후보가 있을 때 입장 가능한지 등 세부 편성 유효성은 실제 규칙을 확인합니다.

### S12 조합

왼쪽은 **전체 등록증 유지안**이 정본입니다. 선택한 재료 슬롯만 원본 캐릭터를 크게 표시하고, 빈 슬롯은 약하게 표시합니다. 재료를 다시 누르면 해제하며 별도 추가·해제 버튼을 만들지 않습니다.

XP 계승 규칙은 확정입니다.

`평균 성장 XP = floor(재료 누적 성장 XP 합 / 재료 개체 수)`

이 값을 **결과 유닛의 XP 곡선**에 적용해 레벨과 잔여 XP를 구합니다. 최신 개별 레시피와 XP 곡선은 아직 검증·연결되지 않았으므로 시안의 예상 레벨은 미정입니다. 규칙 자체가 없다는 뜻이 아닙니다. 유효한 레시피·곡선·비용을 확인하기 전 확정 버튼은 비활성으로 두며, 시안의 재료와 결과 조합을 실제 레시피로 등록하지 않습니다.

### S14와 S15 모집

회당 비용은 저급 2, 중급 6, 고급 10입니다. 수량은 최대 50이며 동시에 보유 지원서로 감당 가능한 수량 이하여야 합니다. `MAX = min(50, floor(보유 지원서 / 회당 비용))`입니다. 1회도 감당할 수 없으면 모집을 비활성화합니다.

재추첨은 **카드별 1회, 동일 등급, 원가 절반인 1/3/5**이며 천장은 없습니다. 각 카드의 재추첨 사용 여부와 결과 수령 여부를 거래 상태에 저장합니다. 지원서 부족, 재추첨 사용, 수령 완료 상태를 별도로 표시합니다. 뒤로 가기·재시작은 미수령 거래를 복원해야 하며 무료 재추첨이나 중복 수령을 만들면 안 됩니다.

### S16 지원서 받기

서버 `credits`와 화면의 **지원서**는 하나의 재화입니다. `모집크레딧`이나 `지원권`을 별도 잔액으로 추가하지 않습니다. **커먼 선택지급권**은 유닛 선택 권리를 가진 별도 아이템입니다. 지원서 획득 경로·수령 간격·수량은 실제 데이터 연결 전 미정입니다.

### S06과 M02와 M03 전투

명령은 공격·기술·집중·아이템·교체·도망, 기술은 6개입니다. 공격 MP는 0, 전투 시작 MP는 가득, 집중은 최대 MP의 25% 회복입니다. 실제 기술명·비용·효과·대상 규칙과 아이템 목록·효과는 확정 데이터 연결이 필요합니다. 시안의 이름·수치·효과 설명을 실제 스킬 정의로 옮기지 않습니다.

기술 설명은 **누르는 동안만** 표시하고 손을 떼거나 포인터가 취소되면 닫습니다. 이 동작은 기술 사용, MP 소모, 턴 확정으로 이어지지 않아야 합니다. 짧은 탭 뒤 대상·확정 처리는 실제 기술별 타깃 계약을 확인해 연결합니다. 아이템은 아이템 선택→적법한 대상→효과·수량 확인→사용 순서이며 취소는 소비나 턴 소모를 일으키지 않습니다. 교체에는 후보의 HP와 MP를 함께 표시하고 전투불능 또는 이미 출전 중인 대원은 선택할 수 없습니다.

스토리·대전의 도망은 항복이며 XP는 0입니다. 모험 도망은 성공률 70%, 실패 시 적 1행동입니다. 성공해도 현재 전투만 끝나고 누적 보상을 유지한 채 S19로 돌아갑니다. 모험 귀환은 전투 밖에서만 가능하며 전멸 시 누적 보상을 잃습니다. 전투·귀환 결과는 **결과 확인→정산 완료→메인/정해진 복귀처** 순서를 지키고, Android 뒤로·연결 끊김·재시작으로 이 순서를 우회하지 않습니다.

## 로그인과 잠금과 보상

- 카카오 로그인과 별도 심사용 로그인을 유지합니다. 코드 수신·6자리 입력 흐름을 되살리지 않습니다. 로그인 문제는 재시도 안내 범위이며 별도 계정 복구 기능은 확정하지 않습니다.
- 모집·방범대·조합·탐험·상점·전투편성·출석·미션·환생의 **요청된 8개 메뉴**를 계정별 서버 상태로 통제합니다. 여기서 `출석·미션`은 메뉴 하나입니다. 시안의 잠금 사유는 점검 중입니다. 대표 레벨은 현재 보유한 새 유닛 중 최고 레벨이며 과거 최고 기록이 아닙니다. 해제 레벨은 미정이고 플레이·우편·설정의 잠금 범위도 미정입니다.
- 시작 대원은 u01입니다. 튜토리얼 완료 우편은 u01을 제외한 커먼 1명을 고르는 선택지급권 1장이고 영구 보유입니다. 기간제 대여나 추가 태초 보상을 만들지 않습니다.
- S20은 대원 변경 진입과 진행·수령 가능·수령 완료 상태를 구분합니다. 파견 시간·보상·진행 중 교체/취소 정책은 시안으로 확정하지 않습니다.
- 상점의 품목·가격·결제, 출석 보상의 즉시/우편 지급, 실제 랭킹 정책은 미정입니다. R056의 `TBD` 목적지를 임의로 채우지 않습니다.

## 소스에서 그대로 가져오면 안 되는 부분

- `v3/canvas-core.cjs`의 오래된 S05 함수는 최종 출력에서 사용되지 않습니다. 최종 S05는 `party-v3/render-party-v3.cjs`입니다.
- `v3/canvas-modals.cjs`의 오래된 M02/M03 함수도 사용하지 않습니다. 최종 M02/M03은 `battle-v3` 소스입니다. 오래된 기술명·MP 예시와 A 배경 미정 문구를 되살리지 않습니다.
- `review-decisions.json`의 S05 검토 대기·PDF 보류는 과거 이력입니다. 최종 산출물은 50페이지의 `reference/page-manifest.json`과 그 해시를 기준으로 봅니다. 시안집 완성이 모든 화면의 개별 사용자 승인이나 런타임 검증 완료를 뜻하지는 않습니다.
- R032의 도감→상세 중복 진입은 최신 도감의 탭 통합안에서 표시하지 않습니다. 경로 원본을 삭제한 것이 아니라 비실행 상태로 구분한 것입니다.

## 구현 후 확인할 항목

시안 좌표는 게임 영역 **1920×800 px**, 검토 캔버스는 하단 설명을 포함한 **1920×900 px**입니다. 하단 100px는 게임 UI에 넣지 않습니다. 이 좌표를 Android dp로 간주하지 않습니다.

실기기에서 안전 영역, 화면 비율, 글자 배율, 대비, 터치 영역, 접근성 이름, 버튼 연타, 뒤로 가기, 포인터 취소, 네트워크 재시도, 매칭 취소 경합, 거래 복원, 중복 수령 차단을 확인해야 합니다. 현재 검증은 정적 Canvas 시안, 축소 시각 검토 및 파일·경로·해시 대조이며 실제 Android dp/터치 검증은 수행하지 않았습니다.

## 인계 패키지 연결

- `assets/asset-references.json`: 원본 자산 **64개 고유 SHA256** 인벤토리. 매핑의 `canonical_asset_identity`와 SHA로 연결하며 같은 파일의 여러 의미 키는 하나의 원본을 가리킬 수 있습니다. 현재 패키지 하위집합에 없는 로컬 추가 자산은 `asset_pack_status`로 구분합니다.
- `layout/native-component-layouts.json`: 일반 화면 **40개 상태**의 실제 컴포넌트 배치 좌표.
- `layout/battle-recruit-layouts.json`: 전투·모집 **10개 상태**의 배치 좌표. 두 파일을 합쳐 최종 50개 표시 상태를 참조합니다.
- `reference/authoritative-delivery.json`: 최신 시안집 Library ID·version 1·SHA와 검토 기준. 개발 ZIP에는 PDF를 중복 포함하지 않고 이 참조와 핵심 PNG 3장을 사용합니다.

`태초`는 **현재 종족명**이므로 유지합니다. 제외 대상은 구형 D1/태초갈매미맨 캐릭터 자산과 이전 추가 보상이지, 현재 종족 라벨 전체가 아닙니다.

패키지 내부 경로: 최종 페이지 목록은 `reference/page-manifest.json`, 흐름 검증은 `qa/flow-validation.json`, 전투 계약은 `reference/battle-state-contracts.json`입니다. 렌더러는 `editable/workspace/outputs/ui-mockups-20261025/` 아래에 있습니다. `review-decisions.json`은 패키지에 없는 외부 과거 이력이며 정본이 아닙니다. 50개 전체 PNG 경로는 외부 원본 워크스페이스 참조입니다. ZIP에는 핵심 PNG 3장만 포함되므로 전체 검토는 `reference/authoritative-delivery.json`의 최신 PDF를 사용합니다.
