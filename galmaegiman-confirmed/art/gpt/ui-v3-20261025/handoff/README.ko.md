# 갈매미맨 방범대 - UI v3 개발 전달

## 먼저 확인할 것

**이 패키지는 앱에 붙일 통이미지 UI가 아닙니다.** 기존 앱의 화면·컴포넌트·상태·데이터 바인딩을 아래 구조에 맞추는 개발 참고 자료입니다. 화면을 PNG 배경으로 만들고 투명 버튼을 겹치는 방식은 사용하지 않습니다.

- 정본: **36개 화면 ID / 50개 상태 페이지 / 원본 흐름 95개 경로**.
- 최신 전체 PDF: Library `libfile_3100600207c881919eb4d74ca7c52445`, **version 1**. v2는 이전 version 0입니다.
- PDF 파일·SHA-256·크기와 포함된 PNG 3장의 해시는 `reference/authoritative-delivery.json`에 있습니다. PDF는 다운로드 중복을 줄이기 위해 ZIP에 넣지 않았습니다.
- 포함된 검토 이미지: **S05 전투 편성 / S06 B 항구 전투 / S12 조합**. 모두 최종 v3 파일과 바이트가 같습니다.
- 전투 배경은 **사용자가 선택한 B 항구**입니다. A는 비교 이력이며 현재 구현 기준이 아닙니다.
- S12는 **왼쪽 전체 등록증**을 유지한 안입니다. 단독 캐릭터 대안은 정본에 포함하지 않습니다.

## 개발 시작 순서

1. `reference/`의 핵심 PNG 3장과 전체 PDF version 1을 직접 봅니다. 파일을 읽지 못했다면 UI 픽셀을 검토했다고 보고하지 않습니다.
2. `mapping/screen-state-bindings.json`에서 기존 화면 ID, 호출 문맥, 네이티브 컴포넌트, 데이터, 행동 가드와 경로를 연결합니다.
3. `theme/theme-tokens.json`과 `layout/` 두 파일의 **1920×800 기준 좌표**를 실제 앱 레이아웃 제약으로 변환합니다. 1920×900 이미지의 아래 100px 검토 표시는 앱 UI가 아닙니다.
4. `assets/asset-references.json`의 SHA-256으로 기존 프로젝트/별도 리소스 팩의 원본 그림을 찾습니다. 같은 이름만으로 구형 아트를 대체하지 않습니다.
5. `mapping/IMPLEMENTATION_NOTES.ko.md`의 확정 규칙·보류 정책과 호출별 상태를 적용합니다. `editable/`의 수치·잔액·레시피·이름 예시는 서버 운영 데이터가 아닙니다.
6. 실제 기기에서 글자·캐릭터 식별성, 안전영역, 터치 영역, 상태 전환, 뒤로가기, 중복 지급 방지와 네트워크 재시도를 검증합니다. 이 ZIP만으로 앱 동작이나 서버 반영이 검증된 것은 아닙니다.

## 반드시 유지할 구분

- 기존 남색/Noto/질감 버튼을 유지합니다. 새로운 청록 테마, 큰 대시보드 패널을 추가하지 않습니다.
- 작은 편성/목록 칸에는 캐릭터를 크게 보여주고, 상세·결과·조합의 큰 영역에는 전체 등록증을 사용합니다.
- **‘태초’ 종족명은 현재 도감 데이터에 존재하며 삭제 대상이 아닙니다.** 제외 대상은 구형 D1/태초갈매미맨 캐릭터 아트와 폐기된 별도 시작 보상입니다. 새 u01 갈매미맨을 사용합니다.
- 서버 `credits`는 화면 용어 **지원서**와 같은 재화입니다. 지원서/모집크레딧을 두 재화로 만들지 않습니다. 새우깡, 땅콩과 구분합니다.
- 모집은 카드당 동일 등급 재추첨 1회입니다. 화면 예시 잔액을 실제 잔액으로 고정하지 않습니다.
- S05 주행동은 호출 목적에 따라 달라집니다: 관리 저장 / 스토리·모험 편성 확정 및 시작 / 대전 매칭 시작. S28의 모드 선택은 유지합니다.
- 조합 XP 산식은 확정되어 있습니다. 미정 표기는 개별 레시피·XP 곡선 미연결에 대한 것이며, 성장 규칙 자체가 없는 것이 아닙니다.
- 카카오 인증과 심사용 로그인을 유지합니다. Google 로그인·6자리 코드·임의 계정 복구 기능을 추가하지 않습니다.
- 미정 상점/레벨 잠금 조건 등은 비활성·검토 상태로 두고 구현자가 숫자나 정책을 발명하지 않습니다.

## 좌표와 실제 기기 검증

`layout`의 단위는 **reference px**이며 Android `dp`가 아닙니다. 화면을 단순 축소하면 버튼도 작아지므로 컨텐츠 크기와 터치 영역을 분리해 검증해야 합니다. Android 공식 가이드는 상호작용 요소의 터치 영역을 최소 48×48dp로 권장합니다. 이 시안의 버튼 높이가 해당 기준을 충족한다고 주장하지 않습니다. [Android 접근성 가이드](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)

- 가로 화면의 시스템 인셋·디스플레이 컷아웃을 적용하고 핵심 버튼을 안전영역 안에 유지합니다.
- 화면 전체 세로 스크롤은 사용하지 않습니다. 목록·도감은 해당 영역 안에서 페이지/가로 이동합니다.
- 길게 누르는 기술 설명은 release/cancel 때 닫히며 시전·MP·턴을 소비하지 않습니다.
- 실제 원본 그림을 재가공하지 않고 sourceRect/contain 등 표시 방식만 사용합니다. 미니의 목록 얼굴 확대를 전투 본체 크기 변경으로 전용하지 않습니다.

## 편집 시안 재렌더 (선택)

아래는 디자인 reference를 재현하는 도구이며 앱 빌드가 아닙니다. 원본 래스터·글꼴은 중복 포함하지 않았습니다. 별도 원본 리소스 팩 또는 기존 프로젝트의 승인된 원본 자산이 필요합니다. **없는 자산을 가짜 그림으로 채우지 않습니다.**

```bash
npm install
node scripts/hydrate-original-assets.cjs /path/to/extracted-original-assets
node scripts/render-reference.cjs
```

64개 자산 인벤토리는 이 50개 시안의 재현에 필요한 하위집합이며 전체 60종의 모든 전후면·모션을 대체하는 게임 자산 목록이 아닙니다.

자산 준비 스크립트는 지정한 자산 폴더만 읽고, 확인된 SHA의 파일만 `editable/workspace/`에 복사합니다. 프로젝트 원본·서버·Git에는 쓰지 않습니다. 렌더 결과는 같은 편집용 작업 폴더에 저장됩니다. 패키지에서 잠긴 버전은 실제 검증 환경의 `@napi-rs/canvas 0.1.100`, `sharp 0.35.5`입니다. 설치 명령은 이 패키지를 사용하는 환경에서 수행하며 현재 프로젝트 의존성을 변경하라는 뜻이 아닙니다.

`canvas-core.cjs`의 과거 S05, `canvas-modals.cjs`의 과거 M02/M03 함수는 전달 사본에서 제거했습니다. 최종 S05는 `party-v3`, M02/M03은 `battle-v3`만 기준으로 사용합니다. Jua 호출 alias는 전달 사본에서 NotoBold 명칭으로 정리했습니다. 원본 v0/v2/v3 작업 기록은 보존되어 있습니다.

## 이번 패키지 검증 결과

별도 임시 폴더에서 전달 소스와 동일 SHA의 원본 자산으로 재렌더하여, **50개 상태 PNG 모두 최종 v3 PNG와 바이트 단위 SHA-256 일치(50/50)**를 확인했습니다. 이는 디자인 소스 재현 검증이며 앱 실행·실기기 터치 검증은 아닙니다. 세부 결과는 `qa/source-replay-check.json`에 있습니다.

별도 전투 런타임 최소팩은 `libfile_285f318822f88191baef46422579f018` (version 0)입니다. `assets/resource-pack-links.json`에서 원본 SHA와 최소팩 파일을 연결합니다. 이 팩은 전투 중심이며 모든 일반 화면 자산을 포함한다고 가정하지 않습니다.
