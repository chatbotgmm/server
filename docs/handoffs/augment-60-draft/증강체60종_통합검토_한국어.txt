증강체 60종 통합 검토 보고서
검토일: 2026년 10월 20일(UTC)

결론과 현재 상태

기존 기준 버전을 바탕으로 만든 증강체 후보본을 현재 브랜치에 통째로 덮어쓰면 안 됩니다. 최신 코드에 이미 들어간 기능을 되돌릴 위험이 있습니다. 실제 통합을 승인받은 뒤, 통합 대상 브랜치와 최신 버전을 다시 확인하고 그 버전에 증강체 관련 변경만 옮기는 방식이 적절합니다.

검토한 후보본과 원격 최신 코드는 서로 다른 방향으로 변경되어 있습니다. 단순히 커밋 두 개를 추가하는 업데이트가 아닙니다. 후보본의 수정 대상 파일 12개를 대조한 결과, 6개 파일에서 기능 변경이 직접 겹쳤습니다. 추가로 줄바꿈 차이 때문에 적용 검사가 실패한 파일 1개와, 적용 검사는 통과하지만 기능을 별도로 맞춰야 하는 파일도 확인했습니다.

특히 보상으로 받은 추가 재선택, 보유 캐릭터 식별, 환생, 스토리 입장 조건, 전투 화면과 자산 검증 관련 최신 변경을 함께 살펴야 합니다. 스토리 입장에서 승급 조건을 제거한 것은 원격 코드에서 확인된 변경 사항입니다. 이를 실수로 되돌리지 않도록 구분하되, 이 검토가 해당 정책에 대한 사용자 승인을 확인하거나 새로 승인한 것은 아닙니다. 최종 적용 정책은 별도 확인이 필요합니다.

이번에는 소스 코드만 읽고 비교했습니다. 후보본 수정, 원격 저장소 반영(push), 병합(merge), 빌드, 배포, APK 실행, 외부 연락은 하지 않았습니다. 통합도 아직 적용하지 않았으며, 전체 빌드와 전체 테스트도 실행하지 않았습니다.

개발자용 상세 부록

1. 통합 기준과 버전 관계

통합 대상 브랜치를 다시 확인한 뒤, 합의된 통합 기준 커밋을 정확히 체크아웃하고 증강체 관련 변경만 이식해야 합니다. 이번에 검토한 통합 기준 커밋은 다음과 같습니다.

b7f9092a7da592f7b0b402333ef7f8277acc464e

후보본의 원래 기준 커밋:
34e9b4b08ee0e6ed181bf9e87f73ce34bee7872d

두 버전의 공통 조상(merge base):
9787b7cfa190985c0e699bbb6403af7e6710f881

GitHub 비교 결과는 65 ahead / 18 behind입니다. 즉 양쪽에 서로 포함되지 않은 변경이 있어, 단순한 두 커밋 fast-forward 방식으로 합칠 수 없습니다. 실제 통합 작업 전에 해당 브랜치가 의도한 대상인지 다시 확인해야 합니다.

2. 직접 확인한 충돌

후보본이 수정한 경로 12개의 정확한 원격 파일 사본을 확인했습니다. 원격 스냅샷을 기준으로 git apply --check를 실행했을 때 다음 6개 파일에서 실질적인 변경 충돌이 발생했습니다.

- src/battle/engine.ts
  원격 코드는 rerollAugment에 bonus=false 인자를 추가하고, 보상으로 얻은 추가 재선택에는 슬롯당 1회 제한을 적용하지 않도록 변경했습니다. 후보본도 같은 제한 조건과 선택지 제공 로직을 수정합니다. 후보본의 V2 rerollOffer에는 별도의 슬롯당 1회 제한이 하나 더 있습니다. 따라서 두 제한 조건과 서비스 계층의 재선택 권리 확인·소비 트랜잭션을 함께 조정해야 합니다. 엔진 함수의 인자만 바꾸는 것으로는 충분하지 않습니다.

- src/native.ts
  후보본의 스냅샷·생성·서비스 관련 수정이 원격 코드의 추가 재선택 응답 및 사용 처리, 환생·보유 캐릭터 식별, 현재 스토리 접근 로직과 겹칩니다. 원격 코드에는 이전 스테이지 완료와 비어 있지 않은 팀이라는 입장 조건을 유지하면서 승급에 따른 입장 조건을 제거하고, 적의 승급 단계와 새로운 오류 문구를 반영한 변경이 있습니다. 통합 과정에서 이를 무심코 되돌리지 않도록 검토해야 합니다. 다만 승급 입장 조건 제거에 대한 사용자 승인은 이번 소스 검토만으로 확인되지 않았으므로, 최종 입장 정책은 별도 확인이 필요합니다.

- src/pvp/service.ts
  import와 전투·서비스 경로에서 원격 코드의 진행 보상, 추가 재선택 사용 처리, 보유 캐릭터 인스턴스 기준의 로스터·라인업 선택, 환생 처리와 겹칩니다. 이러한 기능을 유지하면서 버전을 고정한 전투 규칙과 V1/V2 복원 동작을 도입해야 합니다.

- src/pvp/realtime-native-view.ts
  후보본의 보호막·증강체 DTO(데이터 전달 구조) 변경이 원격 코드의 표시용 ownedCharacterId, combatDefinitionId, 이미지 대체 처리와 겹칩니다. 개인정보 및 비공개 정보 필터링을 유지하면서 두 식별 필드와 현재 이미지 처리 방식을 모두 보존해야 합니다.

- NativeAugmentView.java
  후보본의 등급·설명 추가가 원격 코드의 화면 배치와 보상 재선택 버튼·상태 로직에 겹칩니다. 원격 코드의 재선택 권리 관련 카운트다운, 입력 허용 조건, 버튼 문구와 스타일을 보존해야 합니다.

- BattleView.java
  후보본의 보호막·효과 표시가 원격 코드의 statusNames(f) 사용 전환 및 현재 전투 패널 배치와 겹칩니다. 기존의 화면 배치와 상태 표시 개선을 되돌리지 않고 보호막 표시를 합쳐야 합니다.

추가 확인 사항:

- src/battle/rules.ts에서도 적용 검사가 실패했지만, 이는 파일 끝의 빈 줄 문맥 차이일 뿐 기능상의 충돌은 아닙니다.
- realtime-adapter.ts는 패치 적용 문맥 검사를 통과합니다. 하지만 원격 코드의 bonus 인자 전달을 반드시 유지해야 하는 기능상 통합 요건이 있습니다. 패치 적용 가능 여부만으로 호환성을 판단하면 안 됩니다.

4. 통합 후 인수 검증 조건

통합 작업에 대해 별도 승인을 받은 뒤 다음을 확인해야 합니다.

- 실제 통합 시점의 최신 커밋을 다시 확인합니다.
- 위에서 확인한 원격 기능을 보존하고, 스토리 입장 정책 등 별도 확인이 필요한 사항을 확정합니다.
- 전체 저장소에서 새로 추가할 파일의 경로가 기존 파일과 충돌하는지 확인합니다.
- 예전 기준 버전에서의 테스트 결과를 그대로 인용하지 않고, 새로운 데이터와 규칙을 기준으로 증강체 테스트를 다시 실행합니다.
- 보상 재선택에 대한 V1/V2 테스트를 추가합니다. 권리 확인, 실패하거나 허용 횟수가 소진된 재선택에서 권리를 소비하지 않는지, 재시도 및 중복 요청에도 결과가 일관적인지(멱등성), 타이머가 연장되지 않는지를 검증합니다.
- 보유 캐릭터 식별과 개인정보·비공개 정보 보호 테스트를 추가합니다.
- 스토리 입장 조건과 적 승급 단계 테스트를 추가합니다.
- 기준 자산과 해시 검증을 수행합니다.
- 승인을 받은 범위에서 전체 TypeScript/Fastify/DB 통합 검증과 Android 화면·실행 검증을 수행합니다.

소스 수준의 테스트만으로 APK가 실제 실행된다고 판단하거나, 강화된 적 능력치에서 전투 밸런스가 맞는다고 결론 내릴 수 없습니다.

현재 후보본은 서버 옵션에서 V2를 명시적으로 선택하지 않으면 여전히 V1을 기본값으로 사용합니다. 자동으로 V2가 배포·활성화되는 것으로 설명해서는 안 됩니다.

6. 검토의 한계

통합을 적용하지 않았고 전체 빌드·테스트를 실행하지 않았습니다.

GitHub 비교 화면의 파일 목록은 표시 개수가 제한될 수 있고, 공통 조상 커밋을 기준으로 산출됩니다. 위 충돌 판단은 그 목록이 완전하다는 가정에 의존하지 않습니다. 검토 대상 커밋의 정확한 파일을 읽고, 수정되지 않은 후보 원본 파일과 직접 비교한 결과에 근거합니다.
